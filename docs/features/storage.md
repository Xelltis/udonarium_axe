# 画像・ストレージ・ルームの取り込み

## 画像 / ストレージ

- **ルームの自動保存** — テーブル変更の20秒デバウンス（最長3分）で手動保存と同じzipをIndexedDBへ保存。編集権限を持つピアのみが保存し、直近5世代 / 合計256MBを上限に古い世代を自動削除。未接続起動時の復元バナーと世代一覧パネルから復元できる（`core/storage/room-snapshot-store`、`application/file/room-snapshot.service`、`features/room-archive`）
- **画像ドロップからのコマ生成** — テーブル上に落とした画像をキャラクターコマ化。ファイル名を名前に、複数枚はずらして配置し、生成位置はテーブル範囲にクランプ（`features/tabletop/image-drop`）
- アップロード / 読み込み画像の**WebP変換**
- canvasベースの画像ダウンスケーラ（`downscaleImageBlob`）
- **画像の編集** — 取り込む画像と取り込み済みの画像を、ブラウザの中で手直しする（`ui/components/image-editor`）。回転（90度ずつ）と反転、背景の透過、切り抜き、出力サイズの変更をこの順に重ねて書き出す。回転や反転をすると、透過で押した点と切り抜きの枠も一緒に回る（`domain/media/image-edit`）。背景の透過は、押した点とつながった近い色を「色の幅」の範囲で透明にする（`domain/media/erase-connected-color`）。上下左右の4近傍で広げるので、図柄の内側にある同じ色は残る。幅の2倍までの色は半透明にして、縁に元の背景が残らないようにする。押した点は覚えておき、スライダーを動かすと元画像から全点をやり直し、「ひとつ戻す」で最後の点を取り消せる。切り抜きの比率は自由・元の比率・1:1・4:3・3:4・16:9から選ぶ。枠は画像の外から引き始めてもよく、その点は画像の縁に寄せる。手を加えていない画像はそのまま保存し、手を加えた画像はPNGとWebP（品質0.9）のうち小さい方で書き出す。2MBを超える画像は、手を加えなくても書き出し直してから保存する。それでも2MBを超えるときは書き出した大きさを示し、編集画面を開いたまま切り抜きや縮小を続けられる
- **画像の取り込みと置き換え** — 「ファイル一覧」とコマなどの画像を選ぶ画面からアップロードすると、2MB以下の画像はすぐに追加し、2MBを超える画像だけをあとから1枚ずつ編集画面で開く（`ImageEditQueue.upload`）。「編集してから追加」にチェックを入れると、選んだ画像をすべて編集画面で開く。このチェックは端末ごとに保存する（`application/file/image-upload-preference.service`）。ドロップした画像が2MBを超えたときも編集画面を開く。テーブルに落とした画像は、編集画面が閉じたあとで落とした位置にコマとして置く（`features/file/files-too-large`）。ZIPの中の画像と音声は、大きすぎることだけを知らせる。「貼り付け」ボタンか、一覧にフォーカスがあるときのCtrl+Vでは、クリップボードの画像を編集画面で開く。チャットなどほかの場所への貼り付けには関わらず、ブラウザが読み取りを拒めばCtrl+Vを案内する。一覧でチェックした画像1枚を「編集」で開くと、編集後の画像で元の画像を置き換える。同期オブジェクトの値にある元の画像IDを新しいIDに書き換え、タグと非公開の指定を引き継いだうえで、元の画像は「システム予約」のタグで一覧から隠す（`application/file/image-relink.service`）。チャットの発言とリアクションは書き換えない。置き換えたあとはチェックが新しい画像に移るので、続けて編集できる。ほかのピアには新しい画像として届くので、古い版でも表示できる
- **外部ツールのZIPの画像** — 名前だけの画像はWebPに変えて、保存先のハッシュで呼ぶ。一方、ほかのツールが作ったZIPは、部屋データの中で画像を元のバイト列のハッシュで参照している。読み込むときは先に画像を保存し、保存したIDが元のハッシュと違うものを控えてから、部屋データの中のその参照を置き換えて読む（`file-archiver`の`withImagesRenamed`）。WebPへの変換はそのまま行う。画像がハッシュの名前で入っているZIP（Axeが保存したZIP）は、参照を置き換えずに読む
- **同梱画像へのリンクの保存** — 見本のコマの絵のような同梱の画像は、部屋やコマを保存して、見本を置いていないブラウザで読み込んでも絵が消えない。保存に`imagelink.xml`を入れ、読み込むときに部屋が呼ぶ識別子のまま取り込む（`ImageLinkList`、`domain/media/image-link-list`。仕組みは[保存と素材](../architecture/save-and-assets.md)）

## 画像・音声・3Dモデルの削除と自分専用のタグ

- **削除できる人** — 部屋から画像・音声・3Dモデルを削除できるのは、GMならどれでも、PLなら自分が追加したものだけ。見学の席は削除できない（`application/file/asset-removal.service`）。削除できるのは人が追加したSHA-256の名前の物だけで、同梱のもの・URLで指すもの・「システム予約」のタグの画像は削除できない。画像は「ファイル一覧」の「削除」から、音声は「ジュークボックス」から、3Dモデルは「3Dモデル」のパネル（[モデル一覧](models.md#モデル一覧)）から削除する
- **削除の前の確認** — 部屋の中で使っている所の数と、選んだうちほかの人が追加したので残る件数を出してから削除する。使っている所には、タグ・追加した人や削除の記録・チャットの発言とリアクション・止まっている環境音を数えない。音声は、BGM・環境音・表示中のカットインで鳴っていれば先に止める
- **削除の記録** — 削除は`AssetRemoval`（`@SyncObject('asset-removal')`、`domain/media/asset-removal`）の`removed`を`'1'`にして部屋に書く。各席はこれを受けて手元の物を手放し、ほかの席からも取り寄せない（`features/file/asset-removal-event-handler.service`）。部屋のサーバーの部屋では、サーバーの置き場からも消すよう頼み、2分後にもう一度頼む。使っていたコマなどは書き換えない。識別子は中身のハッシュなので、GMが同じファイルを足し直すと、使っていた所にそのまま戻る。GM以外が足し直そうとすると「部屋から削除された画像です。足し直せるのはGMだけです」（音声・3Dモデルも同じ形）と知らせる
- **追加した人** — 画像・音声・3Dモデルを最初に追加した席を`AssetOwner`（`@SyncObject('asset-owner')`、`domain/media/asset-owner`）の`owner`に書く。同じファイルをあとから足しても変わらない。書くのは、見学でない席が追加したSHA-256の名前の物だけ（`application/file/asset-ownership.service`）
- **席の見分け方** — 部屋のサーバーの部屋では、ログインしているアカウントのユーザーIDで席を見分け、サーバーがすべての記録をこれで確かめる。ピアの間ではブラウザごとの鍵（`owner_`で始まり、localStorageの`udonarium-axe.owner-key`に保存）で見分けるので、タブを閉じて別の日に入り直しても同じ人として扱う。ピアの間では誰も確かめないので、決まりを守る人にだけ効く
- **タグを自分専用にする** — 「ファイル一覧」で選んだタグを「自分専用にする」と、そのタグの画像は、鍵をかけた人とGM以外の一覧と選択画面に出なくなる（`application/file/image-tag-lock.service`）。卓に置いた画像は全員に見え、どの席も画像のバイトを持ったままなので、隠れるのは一覧と選択画面からだけ。見学でない席なら、誰も鍵をかけていないタグに鍵をかけられる（「システム予約」のタグは除く）。鍵はかけた人とGMが外せる。GM以外は、ほかの人が鍵をかけたタグに画像を入れられない。記録は`ImageTagLock`（`@SyncObject('image-tag-lock')`、`domain/media/image-tag-lock`）の`tag`・`owner`・`locked`
- **記録を消さない** — `AssetRemoval`・`AssetOwner`・`ImageTagLock`はどれもdestroyしない。一度破棄した識別子は作り直せないので、削除を戻すときは`removed`を、鍵を外すときは`locked`を空にする。画像や音声のタグに印を付けずに別の種類にしたのは、旧版がタグを丸ごと書き換えて送り、知らない種類は読み飛ばすから
- **保存** — 追加した人と自分専用のタグは部屋の保存に入り、読み込むと戻る。コマなど1つの物の保存には入れない（`AssetOwnerList`・`ImageTagLockList`。仕組みは[保存と素材](../architecture/save-and-assets.md)）

## ルームの取り込み（実験的）

- **ココフォリア ルームデータzip** — `__data.json`を持つzipをテーブルに落とすと、通常のzip展開を止めて取り込みへ回す（`core/storage/room-archive`、`core/storage/file-archiver`、`features/ccfolia-room-import`）
- **場面 = テーブル** — `scenes` 1件を`GameTable` 1枚へ（名前はシーン名、`order`順）。ココフォリアは場面を切り替えてもパネルとコマが残るため、パネルは全テーブルへ複製し、コマは1体ずつ生成する（Axeのコマはテーブル横断）。盤面サイズはコマ座標の基準を揃えるためルームの値で統一する
- **画像レイヤー** — ココフォリアの前景が盤面サイズちょうどの絵なので`imageIdentifier`（テーブル面）へ、背景は盤面外の壁紙なので`backgroundImageIdentifier`へ写す
- **写像** — `items`を床のみの`Terrain`（視界・光を遮らない）へ、`characters`を`ImportedCharacterFactory`経由の`GameCharacter`へ。`faces`はコマ画像ギャラリーに追加し、`secret` / `invisible`は`DisclosureMode.GameMaster`にする
- **座標** — 原点は盤面中央。パネルはマス単位、コマだけは1マス = 25のピクセル単位（`domain/tabletop/import/ccfolia-room-layout`）。盤外配置は意図的な用法なのでクランプしない
- **重なりパネル** — gravityが常時走るため、`z` 1段ぶんの厚み（`PANEL_THICKNESS`）を与えて物理的に積む。0厚だと支持面に落ちてzファイティングする
- **取りこぼしの明示** — BGM（仕様上zipに非同梱）・`decks` / `effects` / 非表示パネルは写さず、件数をチャットのシステムメッセージで報告
