# 画像・ストレージ・ルームの取り込み

## 画像 / ストレージ

- **ルームの自動保存** — テーブル変更の20秒デバウンス（最長3分）で手動保存と同じzipをIndexedDBへ保存。編集権限を持つピアのみが保存し、直近5世代 / 合計256MBを上限に古い世代を自動削除。未接続起動時の復元バナーと世代一覧パネルから復元できる（`core/storage/room-snapshot-store`、`application/file/room-snapshot.service`、`features/room-archive`）
- **画像ドロップからのコマ生成** — テーブル上に落とした画像をキャラクターコマ化。ファイル名を名前に、複数枚はずらして配置し、生成位置はテーブル範囲にクランプ（`features/tabletop/image-drop`）
- アップロード / 読み込み画像の**WebP変換**
- canvasベースの画像ダウンスケーラ（`downscaleImageBlob`）
- **画像の編集** — 取り込む画像と取り込み済みの画像を、ブラウザの中で手直しする（`ui/components/image-editor`）。回転（90度ずつ）と反転、背景の透過、切り抜き、出力サイズの変更をこの順に重ねて書き出す。回転や反転をすると、透過で押した点と切り抜きの枠も一緒に回る（`domain/media/image-edit`）。背景の透過は、押した点とつながった近い色を「色の幅」の範囲で透明にする（`domain/media/erase-connected-color`）。上下左右の4近傍で広げるので、図柄の内側にある同じ色は残る。幅の2倍までの色は半透明にして、縁に元の背景が残らないようにする。押した点は覚えておき、スライダーを動かすと元画像から全点をやり直し、「ひとつ戻す」で最後の点を取り消せる。切り抜きの比率は自由・元の比率・1:1・4:3・3:4・16:9から選ぶ。枠は画像の外から引き始めてもよく、その点は画像の縁に寄せる。手を加えていない画像はそのまま保存し、手を加えた画像はPNGとWebP（品質0.9）のうち小さい方で書き出す。2MBを超える画像は、手を加えなくても書き出し直してから保存する。それでも2MBを超えるときは書き出した大きさを示し、編集画面を開いたまま切り抜きや縮小を続けられる
- **画像の取り込みと置き換え** — 「ファイル一覧」とコマなどの画像を選ぶ画面からアップロードすると、2MB以下の画像はすぐに追加し、2MBを超える画像だけをあとから1枚ずつ編集画面で開く（`ImageEditQueue.upload`）。「編集してから追加」にチェックを入れると、選んだ画像をすべて編集画面で開く。このチェックは端末ごとに保存する（`application/file/image-upload-preference`）。ドロップした画像が2MBを超えたときも編集画面を開く。テーブルに落とした画像は、編集画面が閉じたあとで落とした位置にコマとして置く（`features/file/files-too-large`）。ZIPの中の画像と音声には、これまでどおり大きすぎることだけを知らせる。「貼り付け」ボタンか、一覧にフォーカスがあるときのCtrl+Vでは、クリップボードの画像を編集画面で開く。チャットなどほかの場所への貼り付けには関わらず、ブラウザが読み取りを拒めばCtrl+Vを案内する。一覧でチェックした画像1枚を「編集」で開くと、編集後の画像で元の画像を置き換える。同期オブジェクトの値にある元の画像IDを新しいIDに書き換え、タグと非公開の指定を引き継いだうえで、元の画像は「システム予約」のタグで一覧から隠す（`application/file/image-relink`）。チャットの発言とリアクションは書き換えない。置き換えたあとはチェックが新しい画像に移るので、続けて編集できる。ほかのピアには新しい画像として届くので、古い版でも表示できる
- **外部ツールのZIPの画像** — 名前だけの画像はWebPに変えて、保存先のハッシュで呼ぶ。一方、ほかのツールが作ったZIPは、部屋データの中で画像を元のバイト列のハッシュで参照している。読み込むときは先に画像を保存し、保存したIDが元のハッシュと違うものを控えてから、部屋データの中のその参照を置き換えて読む（`file-archiver`の`withImagesRenamed`）。WebPへの変換はそのまま行い、この版が保存したZIPは従来どおり読む

## ルームの取り込み（実験的）

- **ココフォリア ルームデータzip** — `__data.json`を持つzipをテーブルに落とすと、通常のzip展開を止めて取り込みへ回す（`core/storage/room-archive`、`core/storage/file-archiver`、`features/ccfolia-room-import`）
- **場面 = テーブル** — `scenes` 1件を`GameTable` 1枚へ（名前はシーン名、`order`順）。ココフォリアは場面を切り替えてもパネルとコマが残るため、パネルは全テーブルへ複製し、コマは1体ずつ生成する（Axeのコマはテーブル横断）。盤面サイズはコマ座標の基準を揃えるためルームの値で統一する
- **画像レイヤー** — ココフォリアの前景が盤面サイズちょうどの絵なので`imageIdentifier`（テーブル面）へ、背景は盤面外の壁紙なので`backgroundImageIdentifier`へ写す
- **写像** — `items`を床のみの`Terrain`（視界・光を遮らない）へ、`characters`を`ImportedCharacterFactory`経由の`GameCharacter`へ。`faces`はコマ画像ギャラリーに追加し、`secret` / `invisible`は`DisclosureMode.GameMaster`にする
- **座標** — 原点は盤面中央。パネルはマス単位、コマだけは1マス = 25のピクセル単位（`domain/tabletop/import/ccfolia-room-layout`）。盤外配置は意図的な用法なのでクランプしない
- **重なりパネル** — gravityが常時走るため、`z` 1段ぶんの厚み（`PANEL_THICKNESS`）を与えて物理的に積む。0厚だと支持面に落ちてzファイティングする
- **取りこぼしの明示** — BGM（仕様上zipに非同梱）・`decks` / `effects` / 非表示パネルは写さず、件数をチャットのシステムメッセージで報告
