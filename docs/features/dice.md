# ダイス

## ダイス

- **振った中身を残す** — bcdiceが返す個々の出目と成否（`rands` / `detailedRands` / `success` / `failure` / `critical` / `fumble`）を`domain/dice/dice-roll-detail`の形に写し、ダイスボットの返答の`ChatMessage.dicebot`にJSONで載せて持ち回る。この欄は前からあるSyncVarで、ほかに書き込む所が無い。新しいSyncVarを足さないので部屋データの後方互換に触らない。読み出しは`message.rollDetail`（欄が空の発言と、その欄に別のものが入っている古い部屋ではnull）。**文章からは読み直さない**。言い回しはシステムごとに違い、`＞`の置換や改行の挿入まで通ったあとの文字列が相手になる
- **卓上で振った目もチャットへ** — ダイスシンボルを振ると、いま開いているタブへ結果が流れる（`application/dice/dice-roll.service`）。コインと同じ扱いで、行き先は`ActiveChatTabService`。複数選択して右クリックすればまとめて振れ、同時に回って1行にまとまる（面がすべて数字なら合計つき）。ほかの人が伏せたダイスは回さず、回さなかった個数を自分にだけ知らせる。自分が伏せたダイスは回し、名前と出目をシークレットの行で流す
- **コマに持たせて連動** — ダイスシンボルの`ownerCharacterIdentifier`でコマの持ち物にできる（「自分だけ見る」の`owner`とは別）。チャットに`dice:コマ名`を書き添えると、そのロールの出目が卓上のダイスに乗る（`domain/dice/dice-chat-token` + `dice-link`、`features/dice/dice-chat-event-handler.service`）。名前を省いた`dice:`は話し手のダイスを指す。面の数が合うダイスから順に埋め、その目を出せないダイスは動かさない。適用するのは送信者の端末だけ（面はSyncVarなので二重に当てない）
- **キャラが持つダイス** — ダイスをキャラクターシートへ預けられる（`domain/character/character-dice`）。保存先はシートの「所持ダイス」節で、個数と面ごとの絵柄を持つ普通のDataElementなので、部屋データにもキャラの持ち出しにも一緒に乗り、詳細画面から手で直せる。盤の右クリック**コマにしまう**で預け（複数選択なら選択メニューから預け先を選んでまとめて）、キャラの右クリック**ダイスを展開する**でコマの隣へ並べ直す（`application/dice/character-dice.service`）。**しまったときの出目も1個ずつ残る**ので、展開するとその目のまま並ぶ（伏せたダイスの出目は残さない）。展開はシートから取り出す操作（`takeHeldDice`）で、1個のダイスは盤の上かシートの中のどちらかにしか無い。取り出さないと押すたびに増える。詳細画面ではviewMode=tableの1行として出る（個数・出目・面の絵柄）。面の絵柄は`type="image"`なので保存zipの画像収集にそのまま乗る。展開したダイスは最初からそのコマの持ち物なので`dice:コマ名`の連動がそのまま効く
- **転がる演出** — 振ると卓のキャンバスがダイスの絵を転がして止め（`domain/tabletop/world/piece-motions`の`dice-tumble-a` / `dice-tumble-b` / `dice-tumble-c`を`PieceMotionsService`で再生）、止まったあとに出目が浮かび上がって消える（`styles/animations.css`の`dicePop`）。転がり方は3通りを順に使うので、まとめて振っても同じ動きにならない。振った本人の画面では、送信が手元へ戻るのを待たずに`ObjectChangeService.notifyDiceRolled`で回し始める（コインと同じ作り）。伏せたダイスの出目は、読める人（伏せた本人と`canSeeHidden`の席）の画面にだけ出す
- **チャットのロールを3Dで転がす** — 部屋設定の「ダイスの演出」（`Config._diceStage`。`''`＝出さない / `frame` / `table` / `both`、未知の値も出さない。`both`は枠と卓で別々に物理を解き、同じ目で止める）。振った端末が`DICE_THROW`（回答の識別子と、元の行の話し手のコマ）を送り、シークレットは`localDispatch`で自分にだけ流す。受けた端末は発言が届くのを待ち、見てよい行か・30秒以内か・リプレイ中でないかを確かめてから、発言の識別子を種に自分で物理を解く（`application/dice/dice-throw.service`）。three.jsとcannon-esは`infrastructure/dice-3d`に閉じ込めて遅延読み込みし、物理はWorkerで回す。出目は、物理が着地させた面を形の対称回転で目標の面に回して合わせる。数字は読む人に向けて正立させ、選べる回転が1通りしかないd10は転がる間の鉛直軸ひねりと投げ直しで合わせる。描画はWebGLRenderer 1つで描いて各キャンバスへ写し（`application/dice/dice-render.service`）、再生は最初に描いたフレームから数える。卓の上のダイスは卓の場面の中で描くので、壁やコマとの前後、光と影がほかの物と同じになる。トレイは読む人の画面に揃え、話したコマの手前（見えなければ画面中央）に置く（`application/dice/dice-tray-placement.service`）。部屋に`diceStage`が入ると、手の空いたときにエンジンを先に用意する
- **まとめて作成** — 卓の右クリック「ダイスを作成」の末尾の**個数を指定して作成…** で種類・個数（既定2個、30個まで）・所有者・「自分だけ見る（伏せて置く）」を選び、一度に置く（`features/dice/dice-symbol-create-dialog`＋`TabletopActionService.createDiceSymbols`）。配置は純関数`getDicePlacements`（1マスの1.1倍の刻み・5個で折り返し）に切り出してあり、1個だけ作るときも同じ関数を通る。ダイアログはめったに開かないので、`features/tabletop/create-menu/create-object-menu.service`の`DICE_CREATE_DIALOG_LOADER`（InjectionToken）が初めて開くときに遅延importで読む
- **ダイスシンボルシート** — 面ごとの画像設定、保存 / 複製（`features/dice/dice-symbol-sheet`）
- **BCDiceの読み込み** — ゲームシステムは`BCDiceLoader`（`domain/dice/bcdice/bcdice-loader`）がbcdiceの`Loader`を継承し、あらかじめ書き出した一覧`bcdice-importers.generated`から動的importで読む。bcdice同梱の`DynamicLoader`は実行時に組んだパスを`require`に渡すので、バンドラが追えない。ローダーそのものも`DiceBot`が初めて要るときに遅延importで読み、起動後は手の空いたときに先に読んでおく（`DiceBot.ensureLoaded`、`composition/app-initialization.service`の`prefetchWhenIdle`）。チャンクのまとめ方と、bcdiceを上げたときの作り直しは[依存の更新](../contribution.md#依存の更新)
- **名前・所有者のラベル** — 画面のHTMLで描き、卓のキャンバスがダイスの絵を描いた位置の上に置く（`ui/tabletop/hud-place.directive`）。視点やダイスが動いたフレームで`HudFrameService`が置き直す
- **1ロール200個まで、枠を分けて転がす** — 1つの枠に転がすのは50個まで（`MAX_DICE_PER_TRAY`）。超えるロールは最大4枠（`MAX_TRAYS`）へ均等に分け、200個（`MAX_THROWN_DICE`）を超えた分は最後の枠の隅に`+N`と数だけ出す（`domain/dice/dice-3d/dice-throw-plan`の`throwPlanOf` / `traysOf`）。120個を50・50・20でなく40ずつにするのは、枠の大きさがダイスの数で決まり、小さい枠だけダイスが大きく見えるため。枠ごとに別の投擲として順に解き、解けた枠から転がすので、最初の枠は残りを待たない。同時に転がるのは6ロールまでで、動いているダイスの合計も400個（「描画: 軽くする」の端末では200個）以内に限る（`DiceThrowService.hasRoomToTumble`）。ほかに動くロールが無ければ数に関係なく転がり、超えたロールは止まった姿で出す
- **マイダイス** — 自分が振るダイスの材質（樹脂 / マーブル / 金属 / 半透明）・ダイスの色（既定は「発言の色に合わせる」）・数字の色（既定は「ダイスの色から自動で決める」）を選ぶパネル（`features/dice/my-dice-setting`、`application/dice/my-dice.service`）。半透明は「描画: 軽くする」の端末でだけ樹脂で描く。部屋やキャラクターではなくこのブラウザの設定で、localStorage（`my-dice`）に置き、誰として話しても同じになる。話した行は既定との差分だけを`encodeDiceLook()`でSyncVar`ChatMessage.diceLook`に載せる。ダイスボットの返答と別タブへの複写もこれを引き継ぐので、全員が振った人の見た目で転がし、再読み込み後も変わらない。値の無い古い行は無地で、知らない材質は樹脂として読む。チャット入力欄の「マイダイス」ボタンは「ダイスの演出」が入った部屋でだけ出て、見学には出さない。開くと各形を1個ずつ試し振りし（ロールとしては数えない）、変更のたびに振り直す
- **ダイスに画像を貼る** — マイダイスの「画像」で選んだ絵を「巻き付ける」か「各面に貼る」で着せる。巻き付けは3方向から投影して面の向きで混ぜるので辺をまたいで続き、ダイスごとに別の部分が出る。各面に貼るは面ごとに数字の下に敷く。貼っている間は樹脂で描くが、選んだ材質は残して行にも書く（外したときや、画像を載せない見学の行で戻すため。`wornDiceLook`）。8MBを超えるもの・画像として読めないものは断り、長辺512pxに縮めて、まずこのブラウザのIndexedDB（`core/storage/dice-image-store`）へ保存する。保存できたときだけ`ImageStorage`へ足して共有する（手元に残せない画像をほかの人へだけ配らないため）。行には識別子を`diceLook`とは別の`ChatMessage.diceImageIdentifier`で載せる。名前が`ImageIdentifier`で終わるので、部屋の保存にも画像が入る。部屋の画像は訪問ごとに空から始まるので、話したときかパネルを開いたときに、同じバイト列から同じ識別子で足し直す（`MyDiceService.ensureShared`）
- **ダイスのマット** — チャットの枠でダイスが転がる面を、「スキン」パネルの「ダイスのマット」で選ぶ（`domain/ui/skin-mat`の`DiceMat`、`ui/components/dice-roll-stage/dice-mat.component`）。中身はフェルトの色（既定の灰`#3e424a`、よくある卓布の7色、または任意の色）と、その上に敷く画像（透過率・合わせ方・位置）。ライト / ダーク別にこの画面のlocalStorageへ置くので、ほかの人の枠は変わらない。スキンファイルはversion 2でマットを画像ごと運び、version 1のファイルは無地の灰になる
