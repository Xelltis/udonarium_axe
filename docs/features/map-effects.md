# マップ演出

## マップ演出（エフェクト）

盤面のコマにエフェクトを再生する。31種の内蔵アニメ × 90プリセットを15系統（物理・打撃・射撃・炎・雷・氷・土・風・闇・時空・回復・状態異常・防御・強化・撃破）× 初級〜上級で揃え、ブレス／放電／生命吸収／極太レーザーのように発射元との位置関係を使う演出も持つ。`grade`で粒子量を、`scale` / `durationMs`で規模と長さを段階付ける。

### 段で組み立てる（バレットエディット式）

1プリセットが**段の列**を持てる（`domain/effect/effect-stage`）。役割は**運び / 着弾 / 残留 / 派生**の4つで、運び・着弾・派生は数珠つなぎ、残留だけは後段を待たせず並走する。段が指すのは**既存の31種類の見た目**であってプリセットではないので、循環が原理的に起きず深さも描画前に確定する（派生の中で再度の派生は禁止、段は最大6・分裂は2〜8）。

- **合成** — 段ごとの時間窓は`domain/effect/effect-stage`の`stageLayoutOf`が、段の発射元と着弾点は`domain/effect/effect-stage-timeline`の`placesFor`が出す。卓の場面では`domain/effect/scene/effect-frame`が、段ごとに既存の見た目を描く。運びの段の飛翔体・弾道ミサイル・光の剣は着弾を自分では描かない（`TRAVELLING`。次の段が着弾なので二重になる）。コマの絵を切る見た目（崩壊・両断）の段は`stagedCutPictures`が絵を切る。切り方は`CutPicturePainter`として引数で受け取る（`effect-timeline`との相互importを避けるため）
- **段ごとの見え方** — 色・等級・大きさ・尺は段で上書きできる。`@SyncVar`はプロトタイプのアクセサなので、**代入すると卓の全員のプリセットが書き換わる**。`Object.create`＋自前プロパティで読み取りだけ差し替える
- **場面と音** — 段は自分の時間窓と、見た目ごとに決めた消えきるまでの時間（`SCENE_LINGER_S`）の間だけ場面に描く。派生した枝は、段が着いた点から広がりの角度（`spreadDeg`）に振り分け、1マスに`scale`を掛けた長さの1.6倍（`BRANCH_REACH`）離れた点で描く。発射音は運びの段の開始ごと、着弾音は着弾と派生の段の開始ごとに鳴らす（`domain/effect/effect-sound-times`の`stageSoundTimes`。近いものは間引く。派生の枝は同時に始まるので1回に畳む）
- **保存と互換** — 段リストはプリセットの1フィールド（`stages`、JSON文字列）。見本の3つを除く既定の90プリセットは空で、1種類の見た目を描く。旧版のクライアントはこのフィールドを無視し、`kind`の1種類を描く
- **編集** — エフェクト編集画面の「演出の組み立て」で追加・並べ替え・削除・パラメータ編集。役割に合わない見た目は自動で既定へ戻す。書き込みは**リスト全体を1回で**（1段ずつ書くと編集途中が同卓者へ流れる）
- **見本** — 「散弾の魔弾」「氷結の追撃」「着弾の絨毯」を既定プリセットに同梱（系統「組み立て」）

### 発動の入口

入口は次のとおり。

- エフェクト集パネル（`features/effect/effect-library-panel`）。タイルを選ぶと構えに入り、確定の操作で発動する（[構えと対象の選び方](#構えと対象の選び方)）
- チャット記法`《…》`（`domain/effect/effect-chat-token`で解析し、`features/effect/effect-chat-event-handler`が`resourceEditMessage$`で受けて発火。送信者だけが撃つのは、全員が撃つと人数ぶん重なるため。対象は`t:`と同じ、撃ち手はその行の発言者）
- キャラクターシートの`DataElementFieldType.EFFECT`欄（値は演出名。コマ右クリックの「演出を発動」にも並ぶ）。シートの行（`features/data-element/game-data-element`）もコマのメニュー（`features/character/game-character/game-character-menu.service`）も、名前でプリセットを引いて`EffectTargetingService.castFrom`を呼ぶ
- ホットバーのエフェクト枠（`features/hotbar/hotbar-runner.service`。[ホットバー](pl-tools.md#ホットバー)）。動作が「発動」の枠は`castFrom`を呼ぶ。「ターゲットを無視して自分に」を入れた枠は`EffectCastService.fire`で押したコマ自身に撃ち、「設置」と「自分だけ」の枠は`castFrom`を通らない
- スイッチの動作「エフェクト」と、踏んだら起きることの`TableTrigger.effect`（[スイッチ](map-editor.md#スイッチ)、[機能塗り](map-editor.md#機能塗りマップエディター)）。どちらもエフェクトを名前で引き（`application/media/named-cue.service`）、スイッチは押した人の発言者のコマに、罠は踏んだコマに撃つ
- リソースの増減（`EffectAutoPlayService`）。オプトインで、2つの設定がどちらも入のときだけ出る。1つはエフェクト集の「HP の増減に演出を出す（自分の画面だけ）」で、`localStorage`（`axe.effect.autoPlay`）に持つ個人設定。既定は切。もう1つはリソース欄ごとの「増減でエフェクト」（`cs-change-effect`属性、`domain/character/resource-feedback`の`playsEffectOnChange`）で、属性の無い欄では出ない。見本のキャラクターのHPとMPにだけ、`CharacterTemplateFactory`が`'true'`を書く。属性を持たない欄を入に移す処理はない。出すのは同梱の打撃（殴打・強打・崩拳）か回復（治癒・回復光・大治癒）で、最大値に対して動いた割合が15%未満なら1つ目、40%未満なら2つ目、それ以上なら3つ目を使う（`resourceChangeSeverity`、`domain/effect/resource-effect-map`）。増減は同期済みなので、`EFFECT_CAST`を送らず各画面が自分で再生する

発動すると`EFFECT_CAST`イベントで全員の画面が同時に再生しSEも鳴る（リソースの増減と試し撃ちは送らない）。演出の状態は同期せず、各クライアントが受信時刻を起点に純関数でフレームを算出する。

シートの行・コマのメニュー・ホットバーの枠が通る`castFrom(preset, piece)`は、押した時点のターゲット指定で動きを分ける。

| 条件                                                                 | 動き                                                                       |
| -------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| そのコマ以外に`targeted`のコマがある                                 | `EffectCastService.fireFromCharacter`でその場で発動する                    |
| 対象規則が`self`のプリセット                                         | 同じく、その場で発動する                                                   |
| 卓を編集できない席、または卓に出ていないコマ                         | 同じく、その場で発動する                                                   |
| 上のどれでもない（相手が要るプリセットで、ほかのコマを狙っていない） | `begin`のあと`setCaster`でそのコマを撃ち手にして構えに入り、`'held'`を返す |

チャット記法・スイッチ・罠・リソースの増減は構えを通らず、その場で再生する。

### 構えと対象の選び方

エフェクト集のタイルを選んでも発動しない。選んだプリセットは発動を待つ状態（構え）になり、確定の操作があるまでそのまま残る。構えは`application/effect/effect-targeting.service`の`EffectTargetingService`が持つ。中身は、構えたプリセット（`preset`）、選んだ順の対象（`picks`）、撃ち手（`casterIdentifier`）の3つ。

| 操作           | メソッド                         | すること                                                                                                                                                           |
| -------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 構える         | `begin(preset)`                  | `targeted`のコマのうち自分から見えるものを上限まで対象に引き継ぎ、開始前の`targeted`を覚える。対象規則が`self`で引き継ぐコマが無ければ、選択コマを対象に入れておく |
| 対象を選ぶ     | `pick(identifier)`               | 選んでいないコマを足し、選んであるコマを外す。上限に届いても発動しない                                                                                             |
| 撃ち手を変える | `changeCaster()` / `setCaster()` | `changeCaster()`のあと最初に押されたコマを、対象に足さず`setCaster`に渡す。`setCaster`はそのコマを対象から外す。空文字を渡すと撃ち手なしになる                     |
| 確定する       | `confirm()`                      | `picks`のうち卓にいるコマへ`EffectCastService.fire`で撃ち、構えを解く。対象が0体なら何もせず、構えも残す                                                           |
| 中止する       | `cancel()`                       | `targeted`を開始前の状態に戻して構えを解く                                                                                                                         |

発動するのは`confirm()`だけで、呼ぶのはエフェクト集の「対象に発動する」、ターゲット帯の「発動」、一人称のビューのボタン、Enterキー（`game-table`の`onEnterKey`。入力欄にフォーカスがある間は取らない）の4か所。`cancel()`は、それぞれの「中止」、Escキー（`onEscapeKey`）、構えたプリセットのタイルの再選択が呼ぶ。`PieceTargetService.clear()`（ターゲット帯の「すべて外す」とShift+T）は先に`cancel()`を呼んでから`targeted`を全部外す。卓を編集できない席に変わったときも中止する。

対象は選択コマ（`SelectionSignalService.selectedObject`）の変化で拾う。構えた時点で選択されていたコマは、押し直されていないので対象にしない。順番の扱いは`domain/effect/effect-target-picks`の`toggleEffectPick`が決め、上限に達した状態で別のコマを選ぶと最古の対象と入れ替える。

`areaRadius`を持つプリセットは、1回の`pick`で中心からの半径内を近い順に上限までまとめて選び直す（`domain/effect/effect-area`の`effectAreaTargets`）。交戦ゾーンにいるコマはゾーンの中心にいるものとして測り、戦線を離れたコマ（`offField`）は入れない。半径は`areaRadiusCells × gridSize`で、ヘクスの卓でも円で測る。

選んだ順の配列が元データで、コマの`targeted`はその写し（`mirror()`）。発動後も`targeted`を残すので、チャットの`t:`がそのまま同じ対象へ効く。対象規則が`self`のプリセットだけは、発動後に`targeted`を開始前の状態へ戻す。自分から見えないコマは、撃つが`targeted`にはせず、番号も付けない（`pickOrder`は見えるコマだけで数える）。

撃ち手は`begin`の時点の選択コマを固定して持つ（選び進めると選択が対象側へ移るため）。`EffectCastService.fire`は、撃ち手が対象の中にいるときは撃ち手なしで撃つ。確定した発動は`lastConfirmed`に置くので、Enterやターゲット帯で確定したときも、エフェクト集は知らせの行に相手の名前を出せる。

### 構えている間の卓の表示

`features/effect/effect-target-overlay`が、次の印を、卓のcanvasがその場所を描く画面上の位置に重ねる。床に寝かせるのは番号以外の全部で、番号だけは画面へ向けて立てる（盤を傾けると寝かせた数字は読めない）。

| 印             | 元にする値                  | 見た目                                                               |
| -------------- | --------------------------- | -------------------------------------------------------------------- |
| 対象           | `marks`                     | プリセットの主色の円と、選んだ順の番号                               |
| 撃ち手からの線 | `links`                     | 撃ち手から各対象への帯                                               |
| 撃ち手         | `casterMark`                | 白い二重線のひし形。対象が0体でも出す                                |
| 範囲           | `areaCenter` / `areaRadius` | 中心を押したあとの破線の円                                           |
| 押す前の範囲   | `areaProspect`              | ポインタの下のコマを中心にした点線の円と、巻き込むコマごとの破線の輪 |

対象は円、撃ち手はひし形にして、色だけでなく形でも見分けられるようにしている。押す前の範囲は線だけで描き、卓の上に面を敷かない。

`areaProspect`は`pick`と同じ`areaPicks`で求めるので、見せた相手と、押して選ばれる相手が一致する。ポインタがコマに入ったことと出たことは、コマ（`features/character/game-character`）が`hoverPiece`で知らせる。ホバーできない端末（`ViewportService.canHover`が偽）、撃ち手の変更を待っている間、すでに中心として押したコマの上では出さない。

本体と一緒に選ばれた部位は印を持たない（本体の印に重なるため）。一人称のビューは、番号と撃ち手の印を出さない（`badges`と`casterRing`を偽にする。番号は卓のカメラへ向けて立てるもので、撃ち手はそのビューが覗いているコマだから）。

ターゲット帯（`features/tabletop/target-band`）は、構えた瞬間から構えが解けるまで、対象が0体でも出し続ける。選んだ数と上限を幅の決まった箱に入れ、「発動」「中止」「すべて外す」のボタンを持つので、対象の数が変わっても帯の大きさは変わらず、エフェクト集のパネルに手が届かなくても確定と中止ができる。ボタンの高さは44px。構えていない間は、`targeted`のコマが1体以上ある間だけ出る。

### エフェクト集パネルの配置

`features/effect/effect-library-panel`は、上から4つの領域を決まった高さで並べる。状態が変わっても領域の中身を差し替えるだけで、行を足さない。構えても、対象が増えても、発動しても、一覧の位置は動かない。

| 領域           | `data-testid`            | 中身                                                                                      |
| -------------- | ------------------------ | ----------------------------------------------------------------------------------------- |
| 検索と絞り込み | `effect-library-filters` | 検索欄、追加・増減の演出・書き出し・既定を反映のボタン、等級・対象数・系統の絞り込み      |
| 構えの領域     | `effect-library-stance`  | プレビューの枠、プリセット名と「選んだ数/上限」、撃ち手の行、対象の行、発動と中止のボタン |
| 一覧           | `effect-library-list`    | 最近使ったもの、系統ごとのタイル、置いてある演出。ここだけがスクロールする                |
| 知らせの行     | `effect-library-notice`  | 1行。知らせ（`notice`）があればそれを、無ければ直前の発動の相手（`lastFired`）を出す      |

構えの領域の各行は、構えの前後で次のように変わる。

| 行     | 構える前                                                       | 構えている間                                                     |
| ------ | -------------------------------------------------------------- | ---------------------------------------------------------------- |
| 名前   | 「エフェクトを選んでください」                                 | プリセット名と、`pickOrder`の数/`limit`                          |
| 撃ち手 | 「撃ち手（予定）」として`upcomingCasterIdentifier`（選択コマ） | `casterIdentifier`のコマ。変えるボタンと、なしにするボタンが付く |
| 対象   | `targeted`で自分から見えるコマ                                 | `pickOrder`のコマ                                                |

撃ち手の名前を選択コマから出さないのは、対象を押すたびに選択が対象へ移るため。対象の行は名前のチップを1行に並べ、収まらないぶんは横スクロールで読ませる。折り返すと行の高さが変わる。発動と中止のボタンは常に置き、使えない間は`disabled`にする。タッチの端末（`pointer-coarse`）では高さを44pxにする。

タイルの選択（`choose`）は`begin`を呼ぶだけで、対象規則が`self`のプリセットも発動しない。構えたプリセットのタイルをもう一度選ぶと`cancel`を呼ぶ。

タイルはキーボードで移れる。Tabキーが止まるタイルは1つだけにし（`tabStopKey`。最後にフォーカスしたタイル、無ければ先頭）、矢印・Home・Endでどのタイルへ移るかは`effect-tile-keys`の`tileAfterKey`が、タイルの画面上の位置から決める。左右は読む順の前後へ、上下はいちばん近い行の、横の位置がいちばん近いタイルへ移る。SpaceとEnterはタイルを選ぶ。タイルの上のEnterは`enterOnTile`が受けて卓へ渡さない（卓の`onEnterKey`が同じ押下で発動しないように）。構えたプリセットのタイルの上のEnterだけは卓へ通し、発動になる。

### プレビュー

`features/effect/effect-preview`は、10×7マスの盤に代役のコマを2体置いた小さな舞台（`infrastructure/table-3d/effect-stage`の`createEffectStage`）で、プリセットを繰り返し再生する。描くのは卓と同じ`EffectLayer`。周と周の間は600ms（`EFFECT_PREVIEW_REST_MS`）あけ、プリセットの大きさに合わせてカメラを引く。音は鳴らさない。演出を止めている間は、尺の半分の時点の1枚を出す。

入力は3つ。`preset`が替わると頭から再生し直す。`version`は同じプリセットの値が変わった回数で、増えるたびに描き直して頭から再生する（編集中のプリセットは同じインスタンスのままなので、`preset`だけでは変化が伝わらない）。`fill`を付けると、置かれた箱の高さいっぱいに広がる。

置いてあるのは次の4か所。

| 場所                   | 映すもの                                                                                                                      |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| エフェクト集           | 構えているプリセット。構えが無ければ、ポインタかフォーカスが200ms（`EFFECT_TILE_PREVIEW_DELAY_MS`）留まったタイルのプリセット |
| エフェクトの編集画面   | 編集中のプリセット。上部に固定し、項目の欄だけをその下でスクロールさせる                                                      |
| ホットバーの枠の編集   | 枠に選んだプリセット（`chosenEffect`）                                                                                        |
| 戦闘カットインのパネル | 一覧で選んでいるプリセット（`focusedPreset`。[戦闘カットイン](battle-cut-in.md#戦闘カットイン)）                              |

エフェクト集のプレビューは1つだけで、`preset`を差し替えて使う。プレビューは1つにつきcanvasとレンダラーを1つずつ持つので、タイルごとには置けない。作るのは最初に映すものができたとき（`previewMade`）で、パネルと一緒に破棄する。タイルのプレビューはホバーできる端末でだけ出し、ホバーできない端末では構えたプリセットだけを映す。

### 飛翔体（射撃系）

撃ち手が卓にいれば、いま描かれている位置の0.6マス上（`AIMED_FROM_CELLS`）から、いなければ撃った時点の位置（`EffectCast.origin`）から対象へ飛ばす。どちらも無いときは対象の斜め上から飛ぶ。着弾後は`impactKind`が指す種類の見た目を、着弾の瞬間からの自分の時計で描く（氷の矢なら霜、岩弾なら岩石破砕。空、または飛翔体・光の剣・弾道ミサイルを指していれば爆発。`strikesInSceneWith`）。連射（`shots` / `shotInterval`）に対応し、弾ごとに撃つ・飛ぶ・当たるが独立する。連射の弾は互いに少し離れた所に当たり、1発ぶんの着弾は小さめに、粒の量を弾数の平方根で割って描く（`volleyLandingPreset`）。

`projectileStyle`で見た目を切り替える。ミサイルと誘導弾のほかは、まっすぐ飛ぶ。

| 見た目             | 飛び方                                                                                  |
| ------------------ | --------------------------------------------------------------------------------------- |
| `bolt`魔法弾       | 光る芯に光の帯の尾を引き、道中に星形の光を落とす                                        |
| `arrow`矢          | 鏃・矢柄・矢羽根を色の層で描き（光らせない）、後ろに淡い光の筋を引く                    |
| `bullet`銃弾       | 進む向きへ引き伸ばした火花で飛び、銃口炎を出す                                          |
| `crescent`飛ぶ斬撃 | 三日月の刃を進む向きに横たえ、後ろへ反らせて飛ばす                                      |
| `blaster`光線      | 白い芯を色の鞘でくるんだ短い光条。銃口炎を出す                                          |
| `tracer`曳光       | 撃った瞬間に銃口から的まで線を引き、0.3秒で薄れる。線の上を細い火花が飛ぶ。銃口炎を出す |
| `missile`ミサイル  | 撃ち手の横へ蹴り出されて上がり、上から的へ曲がり込む                                    |
| `cruise`誘導弾     | ミサイルより高く上がって大きく振れ、迫りながら左右に揺れる                              |

速さは`PROJECTILE_TRAVEL_MS`（`domain/effect/timeline/flight-timing`）に見た目ごとの実時間で持ち、再生の5〜60%に収める（再生の割合で持つと、尺の長い連射ほど弾が遅く飛ぶ）。

ミサイルと誘導弾は、撃ち手の横の上と、的の手前の上を制御点にした3次ベジエ曲線で飛ばす（`courseOf`）。連射の弾は`SWERVE_SIDE`の順に左右へ振り分け、上がる高さも弾ごとに変えるので、束に見えない。後ろには色の筋と、通った所に残って膨らみながら薄れる煙を引く。本体は淡い色の胴（下側に影）、色の付いた弾頭、尾の4枚の翼（横から見て2枚）、尾から出る推進炎で描く（`domain/effect/scene/shot/bodies`の`missileBody`）。

**SEは発射音と着弾音の2段階**で鳴らす（`impactSoundIdentifier`を着弾時刻に予約。撃った瞬間から音が要る極太ビームと電流は、`impactSoundAt`で着弾音を前に寄せる）。発射音は弾ごとに鳴らす（`launchSoundTimes`。連射で1回しか鳴らないと弾数が耳に伝わらない）。

### アローレイン（`arrowrain`）

**撃ち上げ → 落下 → 突き刺さり**の三段。撃ち手の位置から36本（`ARROW_RAIN_COUNT`）が順に空へ上がって消え、対象とその周り（`areaRadius`の範囲。無ければ的のまわり）へ急な角度で頭から落ち、刺さった所で火花と土埃を上げ、傾いたまま地面に残る。最初の矢が落ちる0.2秒前から最後の矢が刺さるまで、落ちる範囲の地面を淡く光らせる。撃ち上げを省くと矢がどこから湧いたのか分からない。落ちる位置はキャストの種から1回だけ決めて覚えるので、毎フレーム同じ場所へ落ちる。矢1本ごとの撃つ・落ちる・刺さるは`arrowRainShots()`が返す1枚の表で、絵と音の両方がこれを見る。**発射音も着弾音も矢ごとに鳴らす**（110ms未満は間引く。1発ずつ鳴らすと連続音になって本数が聞き分けられなくなる）。

### 弾道ミサイル（`ballistic`）

**打ち上げ → 予告 → 落下 → 爆発**の四段。撃ち手の足元を発射台にして、閃光と地を這う煙を出して真上へ加速し、煙の柱を引いて7マスぶん上（`BALLISTIC_CLIMB_CELLS`）の見えない高さへ抜ける。上昇の終わりごろから着弾まで、落ちる位置の地面に赤い輪（`TARGETED`）が脈打ちながら絞り込む。そのあと的の斜め上から機首を下にして加速しながら落ち、白い煙の尾を引いて、`impactKind`の見た目を1.5倍で描いて終わる（同梱の「弾道ミサイル」はきのこ雲）。撃った先が見えないぶん、落ちてくる位置の輪を地面へ描いておかないと、画面外から爆発だけが現れる。画面の揺れは落ちてきた瞬間に来る（[光・揺れ・音の経路](#光揺れ音の経路)）。

### 光の剣（`skyblade`）

撃ち手の足元から光の柱が立ち上り、真上を向いた巨大な刃になり、**根元を支点に**対象へ倒れ、当たった所で光に崩れる（立ち上る → 刃になる → 振り下ろす → 弾ける、の四段。再生の24%で立ち上り終え、50%で刃になる）。刃は中心ではなく根元で回す（中心で回すと振り下ろしでなく回転に見える）。刃は、対象への水平の向きを含む縦の面の中で、真上から先端が対象の床に届く角度まで倒す。長さは最低6マス（`SHORTEST`）で、倒れる間に対象へちょうど届く長さまで縮め、先端が対象を越えない。倒れる間は先端が光の尾を引く。

**属性を持たせた大剣**は締めの弾け方を`impactKind`へ委ねる（炎の大剣は燃え、氷は凍り、雷は落ち、土は隆起し、闇は毒霧になる）。`impactKind`を持たない「光の大剣」は爆発で終わる。どの大剣も、当たった所で刃が光に崩れ、床に衝撃の輪が走る。

### 極太ビーム・レーザー照射・ブレス

**極太ビーム**（`beam`）と**レーザー照射**（`raybeam`）は同じ組み方（`domain/effect/scene/shot/streams`の`beamOf`）で、太さ・溜めの長さ・流す粒の数が違う。撃ち手に光を溜め、溜め終わり（極太ビームは再生の30%、レーザー照射は28%。最初の当たりの時刻のほうが遅ければそちら）で放ち、先端は0.08秒で対象へ届く。帯は4本（色の層の本体、柔らかい光、芯のある本体、白い芯）を重ね、太さを脈打たせ、帯に沿って粒を流す。当たった所には光の球・星形の光・床の円盤・焦げ跡を置き、対象の位置に光を置く。極太ビームだけは、放った直後に太く膨らんでから戻り、撃ち手に白い閃光の筋を出し、対象の床に衝撃の輪を走らせる。

**ブレス**（`breath`）は撃ち手の口から炎の玉を流し続ける（中級で毎秒40個、`BREATHED_A_SECOND`）。口元は白熱し、進むほど広がって冷める。流れは0.32秒（`REACHES_S`）で対象に届き、跳ねて床へ広がって燃え、焦げ跡を残して煙を上げる。再生の78%（`FAILS_AT`）で息が切れ、口元から流れが途切れ、残りが対象へ流れて、煙と火の粉が残る。流れの速さは秒で持つ（再生位置の割合で回すと、尺の長いものほど中身が遅くなって勢いが無くなる）。

ブレスが道中に運ぶ粒（火の粉 / 氷晶 / 放電 / 木の葉 / 黒い靄）は系統ごとに変える（`domain/effect/effect-motes`の`effectMoteOf`。`moteStyle`で明示、空なら`tagName`から決まり、「出さない」も選べる）。放電なら流れに沿って小さな稲妻も走らせる。呪印（`curse`）も同じ選択を読み、放電なら麻痺の見た目に替わる。

### 斬撃・打撃

斬撃（`slash`）は、撃ち手の立つ側から対象を横切る弧を刃が掃き、刃の後ろに細る尾を引く。刃が対象を横切る所で火花と十字の光を出す。太刀筋は等級と無関係で、`slashStyle`（一太刀・連撃・居合・薙ぎ払い・唐竹割り）が決める。連撃は5太刀、居合は静止のあと一瞬の線と遅れて開く傷、薙ぎ払いと唐竹割りは溜めてから振り、唐竹割りは地面を割る。刃は床より上に留め、弧が床へ潜る手前で止める。

打撃（`bash`）は一拍溜めてから、当たりの止めの間白く光り、太い棘の星・速度線・火花を出し、床に衝撃の輪を走らせて足元に土埃を上げる。等級3は地面にひびを走らせ、岩を飛ばし、2つ目の輪を続ける。

### 撃破の演出

**撃破の演出はコマ自身に効く**（`dissolve`崩壊 / `gore`血しぶき / `bisect`両断）。崩壊はコマの絵を4×6の格子に`clip-path`で切り、下の段から順に破片として飛ばす（`domain/effect/timeline/body`）。両断は斬り口で2枚に切って互いへ滑らせる（`domain/effect/timeline/blade`）。この絵の破片だけはoverlayが卓の上に重ね、絵の周りの白い線・血・光の欠片・光の輪は場面で描く（`domain/effect/scene/body/body`）。血しぶきは、飛び散る血の滴・脈打つ噴出・床の血だまりをすべて場面で描く。対象の絵は`EffectSpriteOptions.resolveImage`でoverlayから渡し、部位を狙ったときは本体の絵を切る。絵の無いコマは絵を切らず、場面で描く分だけが出る。コマ本体は`defeatReactionOf()`が返す合図（`dissolve` / `bisect` / `flinch`）で、`game-character`が卓のcanvasのコマに倒れる動き（`domain/tabletop/world/piece-motions`の`defeat-dissolve` / `defeat-bisect` / `defeat-flinch`）を再生する。

### 置きっぱなしの場

毒沼・炎の壁のような**置きっぱなしの場**は`EffectField`（`TabletopObject`）として盤面に置き、`EffectFieldService`が同じプリセットを尺で折り返して繰り返す（identifier由来の位相ずらしで並べても同じ動きにならない）。場面では`EffectFrameService`が尺の3/4（`NEXT_ROUND_AT`）ごとに次の周を始める。前の周の煙などが消えきる前に次が始まるので、継ぎ目が見えない。発動中の演出と場は`EffectFrameService`が1つのフレームにまとめ、コマの絵を切る見た目の破片はoverlayがまとめる。

### 環境エフェクト（天候・地表）

戦闘プリセットの繰り返しとは別に、**場の状態そのもの**を描く経路を持つ。種類は`domain/effect/ambience/ambience-kind`の16種で、マップ全体向けの`SKY_AMBIENCE_KINDS`（濃霧・雨・雷雨・雪・降灰・火の粉・砂塵・瘴気・光の粒・水中）と、範囲向けの`GROUND_AMBIENCE_KINDS`（毒沼・地面の炎上・地面の噴出・濃霧・瘴気・溶岩・氷結・光の粒・水）の2つの一覧に振り分ける。水と水中は[水域](water-ground.md#水域)と[水中の天候](water-ground.md#水中の天候)にある。ページのcanvasに描く粒は、経過時間から毎回まるごと計算し直す純関数で、位置を端で折り返して繰り返す。

- **霧と瘴気の濃さは塗りではなく雲の重なりで作る** — 塗りを濃くすると雲が沈んで団子になる。塊は流れながら回り、大きさ・伸び・濃さが別々の周期で揺れる（`haze()`）。平行移動だけだと板が流れて見える
- **稲光は経過時間だけの純関数**（`skyAmbienceFlash`） — 5.2秒（`STRIKE_CYCLE_MS`）ごとに1回、種から決めた時刻に光る。1回で消さず二度光らせないと、雷ではなく写真のフラッシュに見える。雷雨の卓では、`Table3dEngine`が場面を描くたびにこの値で場面の明かりを上げる

**マップ全体（天候）** は`GameTable`の`weatherKind` / `weatherColor` / `weatherDensity`。雨・雷雨・雪（`domain/tabletop/world/weather-fall`の`WEATHER_FALL_KINDS`）は卓の場面が降らせる（`infrastructure/table-3d/weather-layer`）。雨粒と雪片は、カメラの見ている所を中心にした四角の中で、それぞれ決まった出発点から経過時間ぶん進めた所に折り返して描き、四角の端・盤の外・空から出てくる所で薄れる。一度に描くのは最大6000粒（`MAX_WEATHER_FALL`）。ほかの天候の粒と、すべての天候の空気の色（`skyAmbienceWash`）は、`features/tabletop/table-weather-overlay`が画面大の1枚として卓のcanvasの上に重ねる。大きさはhostの`ResizeObserver`で測る（`observeSize`）。盤から天井（壁の高さ、最低10マス）までの箱の8つの角を`pageOfTablePoint`で画面へ投影し、それを覆う楕円の`mask-image`で盤の外へ向けて薄れさせる（`weatherMaskImage`。盤の端まで濃さを保ち、その1.55倍の所で消える）。多角形で切ると、空中にガラスケースのような直線の縁が出る。**床の四角形だけで覆ってはいけない**。盤の上空に降っているぶんが消えて、粒が地面に貼り付いて見える。投影は100msごと（描画を軽くしている間は400ms）に、カメラが動いていればやり直し、動かなくても1秒ごとにやり直す（バーが開くなど、カメラが動かずにページが動くことがある）。空気の色は盤の奥から手前へ薄くなる向きに塗る（`weatherDepthDirection`）。一人称のビューでは、マスクを掛けず画面全体に描く（`fromInside`）。

**範囲**は`TableAmbience`（`TabletopObject`）。マップマスクと同じくテーブルの子なので、マップを切り替えると一緒に切り替わる。`ambience-ground`が面（`groundSurfaceLayer`）と立ち上り（`groundVaporSheets`）を別々の層で返す。`features/tabletop/table-ambience`は、面の塗りと粒を、卓のcanvasがその範囲の地面の四隅を描く画面上の位置へ`matrix3d`で貼り（`quadMatrix`）、立ち上りの板は、板が立つ地面の点が描かれる画面上の位置に、カメラへ向けて立てる。水は自分の粒を持たず、水面は卓の場面が描く（`groundAmbienceHasParticles`）。粒の大きさは`unit`（1マス）を基準に決めるので、範囲を広げても粒が巨大化しない。

- **立ち上りは奥行き方向へ複数枚の板に分ける**（`vaporSliceCount`。奥行き2.5マスごとに1枚、最大5枚） — 板を1枚だけ立てると、奥のものも手前のものも同じ深さに並ぶので、16×16では盤面に帯を貼っただけに見える。粒はそれぞれ範囲の中に自分の点を持ち、カメラから見てその点のすぐ手前に立つ板に、点が板より奥にあるぶんだけ上へずらして描く（下へずらすと板の立つ床より下に沈む）。板は卓の向き（`tableViewRotation`）に合わせて並べ直す。粒の総数は板の枚数で変えず、上限だけを1枚あたり150（`MAX_VAPOR_PER_SLICE`）で数える。範囲全体で上限を数えると、広い範囲ほど粒が薄まり、炎がまばらに浮く
- **大きさは1粒ずつ大きく散らす**（`scaleMin` / `scaleMax` / `scaleBias`） — 揃った大きさで並べると、大炎上ではなく焚き火にしかならない。biasを上げて「小さいものが多く、大きいものが稀」にする
- **炎の先端を暗い色まで落とさない** — 加算合成では暗い色はほとんど何も足さないので、色ランプを最後まで通すと粒の過半が見えなくなって炎が痩せる。白熱させるのは根元だけにして、あとは濃さで消す

- **粒の数はマスで数える** — 面積(px²)を基準にすると、既定の4×4マス（0.04メガピクセル）では数個しか出ず、置いても何も無いように見える
- **オブジェクトを返すcomputedに版を吸わせない** — `versionOf()`を読んでから同じオブジェクトを返すcomputedを挟むと、参照が変わらないのでsignalsが下流へ変化を伝えない。版そのもの（数値）を配って各値がそれを読む。これを間違えるとロックも大きさの変更も画面に出ない
- **canvas 1枚の画素数に上限を置く**（`features/effect/effect-canvas`の`pixelRatioFor`、`MAX_CANVAS_PIXELS`＝400万） — マップ全体を覆う範囲は一辺数千pxになり、高精細画面では数億画素を確保しようとする。画素比は2までで、上限を超える層は粗く描く
- **canvasは範囲より一回り大きく取る**（面は0.9マス＝`SURFACE_PAD_UNITS`、立ち上りは最大の粒の半径＋0.2マス＝`VAPOR_PAD_MARGIN_UNITS`） — 粒はcanvasの形に切り取られるので、粒の直径が範囲と同じくらい大きいと、中心が真ん中にあっても裾が枠で切られて灰色の四角が浮く。中心からの距離で透明度を落としても防げない
- **塗りのグラデーションは`closest-side`** — 既定のfarthest-cornerだと、中心を寄せた塊が箱からはみ出し、はみ出した側が不透明なまま直線で切られる
- **演出を止めていても面の塗り（`groundSurfaceWash` / `skyAmbienceWash`）は残す** — 発動する演出と違い、消すと「そこが毒沼である」という盤面の情報ごと消える
- **OSの設定は既定値であって最終決定ではない**（`application/ui/motion.service`、`auto` / `on` / `off`） — Windowsは描画を軽くする目的で「アニメーション効果」を切る。`prefers-reduced-motion`にそのまま従うと、音だけ鳴って画面には何も出ない卓ができあがる
- **描画ループの持ち主は複数いる** — `EffectPlaybackService.setPersistent(source, boolean)`はソース名で持ち主を数える。真偽値ひとつだと、場と環境演出のうち後から来たほうが前の要求を消してしまう

### 卓の場面での描画

演出は卓のthree.jsの場面の中に、コマや壁と一緒に描く。見た目ごとの振り付け（`Choreography`）は`domain/effect/scene/`配下の純関数で、経過秒・尺・当たりの時刻（`blowsAt`）・発射元・種から、その瞬間に描く物（`EffectFrame`。粒`motes`・帯`ribbons`・床の印`floor`・光`lights`）を卓の座標（卓のpx。xは東、yは南、zは上）で返す。`application/effect/effect-frame.service`が再生中の演出と置きっぱなしの場を毎フレーム1つの`EffectFrame`にまとめ、`application/tabletop/table-3d.service`が`infrastructure/table-3d/effect-layer`の`EffectLayer`へ渡す。描く物が何もなければ、同じ空のフレームを返して時計を読まない。見た目の本体（`domain/effect/scene/effect-frame`）は大きいので別に読み込み（`EffectSceneLooksService`）、卓を最初に描くときに読み始める。読み込みに失敗したら5秒あけて読み直す（`EFFECT_LOOKS_RETRY_MS`）。

overlay（`features/effect/table-effect-overlay`）に残るのは、崩壊と両断が切ったコマの絵の破片だけで、卓のcanvasがそのコマを描く画面上の位置に重ねる（1フレーム400枚まで、`MAX_SPRITES`）。環境エフェクトのうち、雨・雷雨・雪の粒と水面は場面で描き、ほかはページに重ねる（[環境エフェクト](#環境エフェクト天候地表)）。[プレビュー](#プレビュー)（`features/effect/effect-preview`）は、盤と代役のコマを置いた小さな舞台（`infrastructure/table-3d/effect-stage`の`createEffectStage`）に、戦闘カットインは舞台の上の透明なcanvasに、同じ`EffectLayer`で描く（[戦闘カットイン](battle-cut-in.md#戦闘カットイン)）。視界外の対象には描かない。演出を止めているとき（`MotionService.enabled`が偽）は何も描かずSEだけ鳴らす。

- **光と色の2つの層** — 粒・帯・床の印は、どれも光（足し算で重ね、まわりにあふれる）か色（上に塗る）のどちらか（`EffectBlend`）。熱い物は光、煙・砂埃・破片・炎の体は色で描き、白は最も熱い芯と縁にだけ使う。`EffectLayer`は粒・床の印・帯を、光と色の2つずつのバッチで描く
- **バッチは最初から場面に置く** — 6つのバッチは演出が無くても場面にあり、何も描かずに待つ。グラフィックスカードの準備を卓と一緒に済ませるので、最初の演出で卓が止まらない。1フレームに描く量の上限は`EFFECT_FRAME_BUDGET`（光と色それぞれ、粒4096・床の印256・帯の点4096）
- **深度を書かない** — 演出はコマや壁に隠されるが、自分は何も隠さない。粒と帯は目の側へ寄せて描く（粒は`forward`、帯は12px＝`RIBBON_NEARER_PX`）。寄せないと、真ん中に立つコマの絵で切られる
- **床の印は地面の起伏に沿わせる** — 地面の高さ（`domain/effect/scene/effect-ground`の`effectGroundOf`）に沿わせ、印1枚を縦横16に割って起伏に合わせる（`MARK_SEGMENTS`）。高さは盤全体を読むので、演出を描いている間だけ読み、描き始めに渡す。毎フレームは渡さない
- **乱数は種から** — 散らす粒は、キャストの種（`EffectCast.seed`）から作る乱数で1回だけ作って覚え（`domain/effect/scene/parts`の`throwerFor` / `keptFor`）、毎フレーム作り直さない。どの画面でも同じ絵になる
- **対象側は届いてから描く** — 飛翔体・弾道ミサイル・光の剣は、着弾の見た目を着弾の時刻からの自分の時計で描く。ブレスは流れが対象に届くまで、ビームは放つまで、対象側を描かない。届く前から出すと、当たる前に燃えていることになる
- **overlayのスプライトに`will-change`は付けない** — 崩壊は1体につき24枚の破片を出す。全部を合成レイヤーへ昇格させると、その場でレイヤーを確保することになり、確保が終わるまで画面が暗く落ちる。毎フレーム位置も透明度も変わるので、昇格させても得が無い

### 光・揺れ・音の経路

- **当たり** — `domain/effect/effect-blows`の`effectBlowsOf`が、打つ見た目（`STRIKING_KINDS`。斬撃・飛翔体・爆発・打撃など）について、最初の対象に当たる時刻・止める長さ・揺れ・押し返しを`EffectBlow`として出す。止める長さは等級1〜3で60・90・140ms、押し返しは0.06・0.10・0.16マス。前に止めた当たりから180ms未満の当たりは止めず、止める長さの合計は300msまで。回復や障壁は当たりを持たない。段で組んだ演出は、打つ見た目の着弾の段ごとに1つ持つ
- **当たりの止め** — 再生の時計は当たりごとに止まる（`heldEffectClock`）。止めたぶん、音と揺れの予約も後ろへずらす（`wallClockOf`）。演出を止めている画面では止めない
- **揺れ** — 揺れる見た目（爆発・閃光・きのこ雲・衝撃波・岩石破砕・地隆・打撃・極太ビーム・重力・落雷・弾道ミサイル。`domain/effect/effect-shake`の`SHAKING_KINDS`）は、等級2で`soft`、3で`hard`に揺れ、1は揺れない。`EffectPlaybackService`は止めのある当たりの瞬間に`shake`を立て、340ms（`SHAKE_MS`）で戻す。続けて来たら強いほうを取り、時間だけ延ばす。撃った瞬間に揺らすと撃った側が殴られたように見えるので、当たりの瞬間まで待つ。揺れは卓のcanvasを包む視界大の要素（`game-table`の`#root`。`overflow-hidden`でクリップされる）に`animate-effect-shake-soft` / `animate-effect-shake-hard`のクラスで掛け、一人称のビューも同じクラスを使う。振れ幅はCSS変数にせず、強さごとのキーフレーム（`src/styles/map-effects.css`の`effectShakeSoft` / `effectShakeHard`）で持つ。継承するCSS変数を書き換えると、その下のすべての要素のスタイルが無効になる
- **押し返しと踏み込み** — `domain/effect/effect-reaction`の`effectJoltsOf`は、当たったコマを止めの間そのままにし、撃ち手から離れる向きへ押し返して（向きが無ければ下へ沈めて）、420msで戻す。押し返しは重なっても0.25マスまで。撃ち手は打ち出す見た目（`LEANING_KINDS`）のとき、最初の対象へ0.12マス踏み込んで戻る。`application/effect/effect-reaction.service`が各席で計算し、`TablePiecesService`がコマを描く位置だけをずらす。部位は本体として動かす。コマ自体は動かさず、何も送らない
- **光** — 各見た目は、まわりを照らす光（`EffectLight`。位置・色・強さ・届く距離）を`EffectFrame.lights`に入れる。爆発は一瞬、炎は燃えている間、まわりの床とコマを照らす。`application/effect/effect-light.service`が強い順に2つ（`MAX_EFFECT_LIGHTS`）を選び、卓の場面に最初から置いた2つの`PointLight`へ渡す。光の無い間は強さ0で待たせる。灯りの数が変わると場面を組み直すことになるため。演出の光は影を落とさない
- **音** — 音の時刻は、描画と別に`domain/effect/effect-sound-times`がプリセットだけから出す（音を鳴らす側が描画のコードを読み込まずに済む）。`EffectPlaybackService`が止めのぶんずらして予約する。発射音は55ms、着弾音は70ms（アローレインは110ms）より近いものを間引く。演出を止めている画面でも音は鳴らす

### 音

SEは効果音ラボ・On-Jinの素材を取り込み、`PresetSound`経由で割り当てる。音のidentifierはファイルのパスなので、編集画面では`domain/media/preset-sound-labels`がファイル名からi18nの表示名（`feature.effect.sounds.*`）へ引き直す（持ち込んだ音はファイル名だけを見せる）。**演出の尺は音の実尺から導出**する（`soundMs`をseedに持たせ400〜6000msに収める）ので、絵だけ先に終わって音が残ることがない。

### プリセットの編集と持ち出し

プリセットは**編集できる**。`features/effect/effect-preset-editor`が種類・系統・等級・色・大きさ・尺・ずらし・対象規則・SE・種類ごとの項目（弾の見た目 / 弾数 / 間隔 / 着弾演出 / 太刀筋）を直接モデルへ書き込み、範囲は`EffectPreset`のgetterが丸める。どの項目を出すかは`domain/effect/effect-preset-form`の純関数が種類から決める。**試し撃ちはローカル再生**（`EffectCastService.preview()`が`EffectPlaybackService`を直接叩き、`EFFECT_CAST`を送らない）。卓の上のコマに音つきで再生するので、対象になるコマが要る。編集画面の上部には[プレビュー](#プレビュー)を置き、`ObjectChangeService.versionOf`の値を`version`に渡して、値を変えるたびにその内容で再生し直す。

一覧は検索・等級／対象数／系統での絞り込み・系統の折りたたみ・最近使った履歴を持ち、印には演出の形から起こしたSVGグリフを当てる。一覧からは追加・複製（`duplicatedEffectName`で連番）・削除（右クリックメニュー、`effect-library-context-menu`）ができ、`gmOnly`のプリセットはPLの一覧に名前ごと出さない。置いてある演出（`EffectField`）は一覧の最後に見出しつきで並べ、ここから片づける。領域の並びとキーボードの操作は[エフェクト集パネルの配置](#エフェクト集パネルの配置)にある。

エフェクト集の持ち出しは`EffectPresetSet`（`InnerXml`の入れ物。`ObjectStore`には残さない）。`EffectPresetSet.of([preset])`で**1つだけ**書き出せ（タイル右クリックと編集パネルの「書き出す」）、形式は集合と同じなのでドロップの読み込み経路も共通。`EffectPreset`は`toAttributes` / `parseAttributes`でidentifierをXMLに残す（`ChatMessage`と同じ手。既定では`ObjectSerializer.parseXml`が読むたびに新しいidentifierを振る）ので、**併合の第一の鍵はidentifier**（`domain/effect/effect-preset-merge`の`takeIntoLibrary`）。同じidentifierがあればそこへ、無ければ同名へ`toContext()` / `apply()`で中身を丸ごと移す（フィールドを列挙しないので段リストのような後付けも自動で乗る）。どちらも無ければ追加。identifierで重ねた結果その名前が別のエフェクトと衝突するときは、戻ってきた側を`duplicatedEffectName`で連番にする（名前はチャット記法やシートの演出欄から呼ばれるため、先にその名前を使っていた方を動かさない）。プリセットは部屋データとしても保存され、「既定を反映」で既定プリセットを最新のseedへ再適用・欠けたものを再作成する（自作プリセットには触れない）。
