# テーブルに置く物

## 範囲（射程）シェイプ

- **カスタム範囲** — セル単位で描けるペインターパネル、`CUSTOM`範囲型とセルパターンユーティリティ、グリッド整合レンダリング
- 多角形シェイプ（三角 / 五角 / 六角）とシェイプ切替、回転可能な範囲
- 描画ループの計算量削減（パフォーマンス）

## 立体射程

- **立体の種類** — `RangeArea.solidKind`（`domain/tabletop/solid/solid-kind`。SyncVarは`solid`）。平面（空文字）・柱（`column`）・球（`sphere`）・円錐（`cone`）・直線（`beam`）の5つで、柱はすべての形に使え、球は円形、円錐はコーン、直線は直線の射程にだけ使える。形に合わない値は柱として読む（`solidKindOf`）。柱の高さは`solidHeight`、球と柱を発動者のまわりで動かせる距離は`solidReach`、円錐と直線の仰角は`pitch`、発動者からのずれは`casterOffsetX`・`casterOffsetY`（卓のマス）に持つ。空文字は0と読まず、既定（高さ3・届く距離6）に戻す
- **形** — `rangeFootprint`が平面の形を凸の部品（多角形か円）に分け、任意マスはマスごとの部品にする。`solidOf`はそれを柱・球・円錐・直線として卓のピクセルで組む。長さ・幅・高さ・届く距離は、どれも射程のマス（まとめマスの卓ではまとめたマス）で数える
- **発動者と半球** — 射程が追従するコマが発動者になる。球と柱は発動者の足元からのずれを持ち、発動者の足元を中心にした半径＝届く距離の球の中を動く。発動者が宙にいれば、真下の地面より上の部分だけを使う（`clampIntoReach`）。外へ引くと、中心への線に沿って外周まで引き戻すので、外周をなぞって滑る。球と柱を離したら、マスへ寄せたあとの`movable.onend`で、ずれと高度を書く（`SolidRangeService.settleRoundCaster`）。円錐と直線は頂点を発動者の体の真ん中に置き、先端のハンドル（`SolidAimDirective`）で狙う点を動かして向ける。持っているあいだの向きは自分の画面にだけ描き、離したときに`rotate`と`pitch`へ書く。動かしているあいだは、半球と、中心から置いた点への線を補助線（`TableWorld.guides`）で描く
- **描画と当たり判定** — 置き場所は`SolidRangeService`が1か所で決め、threeの場面（`TableWorld.solids`、`infrastructure/table-3d/solid-layer`）・当たり判定（`PickShape`の`solid`）・HUDの箱（`blockPageBoxes`の`SOLID_PART`）・範囲内の判定がその形を読む。立体の射程には平面の絵を描かない。面は塗りの色を最大0.35の不透明度で塗り、縁は境界線の色の太い線（`solidWireSegments`）で描く。面は深度テストを受けるが深度を書かないので、地面と地形の陰になった部分は隠れ、奥の物は透けて見える。HUDの箱は画面に写した点の凸包を`clip-path`にし、地面の上に寝た物と同じく、立つ物の箱より下に重ねる。目の後ろの点は箱に入れない。押下は、奥にキャラクターかダイスがあればそちらへ渡す（`TablePickService`の`passingSolids`）。マップマスクやカードの上では、立体のほうが押される
- **範囲内を対象にする** — コマの中心を通る縦の線（足元＋高度から、大きさのマス数だけ上まで）が少しでも立体に入れば範囲内とする（`solidTouchesSegment`）。交戦エリアに加わっているコマは、水平の位置だけをエリアの中心で読む。平面の射程の判定は変えない
- **版の違い** — 古い版は立体の欄を知らないが、`syncData`をそのまま持ち回るので、古い版がその射程を動かしても立体のまま残る。古い版の画面では平面の射程として描かれる。古い版が発動者を動かすと射程はコマの真上に置き直されるが、新しい版は「発動者の位置＋ずれ」から描くので、立体の位置は変わらない

## 物差し

- **持つ** — `RulerService.inHand`。ツールバーとFABの`ruler`（`MENU_COMMANDS`の切り替え）、卓の`M`キー、コマの右クリックの**ここから測る**（`startFrom`）から持つ。見学には出さない
- **引く** — `handRulerPressesOn`が卓の要素でキャプチャ段階の押下を先に受け取るので、持っているあいだは卓の押下がコマに届かない。コマの上に置いた端は、そのコマの足元の中心（高度を含む）につながる。卓の上に置いた端はマスの中心に寄り、Altを押しているときとスナップなしの卓では寄せない。引いているあいだのホイールで、先の端を高度の刻み（1マス）ずつ上げ下げする（`liftEnd`）
- **測る** — `measureBetween`（`domain/tabletop/ruler/ruler-measure`）が、直線・水平・高さの差と、部屋の`diagonalMove`（斜め移動）を高さにも当てたマス数を出す。四角の卓は3方向をまとめて数える。`equal`は最大、`alternating`は最大に次の半分を足し、`double`は最大と次の和、`none`は3つの和になる。ヘクスの卓は、卓の上の歩数と高さを同じ規則で組む。グリッドなしの卓ではマス数を出さない。`cellDistanceUnit`がメートルかフィートで`cellDistance`が正なら、直線・水平・高さは`cellDistance`を掛けた長さで出し、マス数はマスのまま数える（`rulerReadingOf`）。物差し専用の単位は持たず、移動の換算と同じ設定を読む
- **見せる** — 線は場面の補助線で、濃い縁取りの上に明るい線を重ね、両端に輪を付け、宙の端からは地面まで線を下ろす。読みは線の真ん中の上（`table-ruler-overlay`）と、画面の下の帯（`ruler-band`）に出す
- **共有** — 引いている物差しは`PeerCursor.measuring`と`measuringTable`で流す（80msに1回まで）。受け手は自分が見ている卓の物差しだけを描き、端がつながったコマを見られないとき、または端が霧で隠れた未踏の地点にあるときも描かない（`RulerReadingService.maySee`）。卓を切り替えると、自分の線は消える
- **置く** — 帯の**置く**で`TableRuler`（`@SyncObject('table-ruler')`。両端は`line`）を作る。部屋の保存に入り、GMのオブジェクト一覧に出る。端は端のハンドルで、全体は線で動かす（`RulerGrabDirective`）。全体を動かすと、コマとのつなぎは外れる。右クリックで固定・コマとのつなぎを外す・コピー・削除ができる。古い版は`table-ruler`を知らないので読み飛ばし、古い版で保存し直すと物差しは消える

## 共有メモ

- **整形表示** — `TextNote.textFormat`（`''`は通常、`'formatted'`は整形）。本文は書き換えないので、切り替えても文字は1字も変わらない。描画は自前の行単位のレンダラ`ui/text-decoration/format-note-text`で、行頭の`#`〜`###`の見出し、`- `と`1. `のリスト、`> `の引用、バッククォートのコードとフェンス、ルビ、URLのリンクを読む。`*`や`_`の強調は読まない（`2*3`のような式を崩すため）。先に全文をエスケープしてから決まったタグで包むので、書いた内容がスクリプトの実行や画像の読み込みにならない。リンクは生の文から`linkifyjs`の`find`で拾い、できたHTMLを読み直さない。markedを入れなかったのは、卓上のメモの部品が初期バンドルに入り、予算の残りをほぼ使い切るため。卓上・シート・概要パネルで同じ表示になる
- **高さの制限** — `limitHeight`のときは、読む表示の外枠にも`max-height`（`height`×マス）を付け、本文は枠の中でスクロールする。編集中の入力欄は中身に合わせて伸び、同じ上限で止まる
- **裏から見たメモ** — 直立させたメモを裏から見ると、題名と本文は見えず、メモの紙の色（パネルの背景色、テーマの`--ui-panel-bg`）がその不透明度で見える。メモの部品が絵を撮るときにパネルの背景色を読んで渡し（`pictureForCanvas`の`paper`、`paintedColorOf`）、canvasは表の絵と同じ位置に逆向きの色だけのスプライト（`#back`）を重ねる（`textNoteSprites`）。背景に画像を敷いたメモも、裏は色だけにする。寝かせたメモには裏を描かない

## ホワイトボード

- **卓に立てる板** — `WhiteBoard`（`domain/tabletop/white-board`、`@SyncObject('white-board')`、テーブルの子）。SyncVarは`isLock` / `rotate` / `pitch` / `color`（既定`#f4f1e8`）/ `isDropShadow` / `scene`で、幅・高さは共通データ（未設定は4×3マス）に持つ。卓の右クリック「ホワイトボードを作成」は、表示中のテーブルと同じ幅・奥行きの板を、北端から1マス外に立てた状態（`pitch`＝90）で置く。2枚目以降は既存の板の隣へずらす（`TabletopActionService.createWhiteBoard`）。寝かせて置くと、皆が見ている地図を覆ってしまうため
- **角度** — `pitch`は0〜90の整数度（`clampBoardPitch`。有限でない値は0）。手前の下辺を蝶番にして`rotateX`で起こす（中心で回すと手前半分が卓に沈む）。右クリック「角度」の寝かせる / 斜めに立てる / 立てる（0 / 45 / 90）と、設定欄の「傾き」で変える。高さを変えても`setBoardHeightKeepingFoot`が足元の辺を動かさないので、立てた板が手前へずれない
- **載せたものを運ぶ面** — 板に落とした物は、種類を問わず（キャラクター・地形・マップマスク・共有メモ・カード・山札・ダイス・コイン・灯り・地面の効果・射程・板）、`location.surface`に板の識別子を、座標に板基準の値を持つ（`boardSurfaceOf`）ので、板を動かす・回す・立てるたびに一緒に付いてくる。落とし先の面は、`MovableDirective`の`surfaceUnderPointer`が`TablePickService.faceAt`で決める。ポインタから伸ばした視線が、床・絵のある壁・ホワイトボードのどれに当たるかを見る。ドラッグ中の板が自分の面に落ちないよう、ドラッグ中の物自身とそれに載っている物には視線を素通りさせる。板の上では縁からのはみ出しを許し、床と壁の上では面の内側に収める（`TableSurfaceService.overhangs`）。板が無くなったコマは`TablePiecesService`が床に描くが、コマ自体は書き換えない（板を戻せばまた板の上に出る）。「載っているものを降ろす」と板の削除では、板の位置を足して見た目の位置のまま卓へ戻す（`domain/tabletop/white-board-contents`・`WhiteBoardService`。板を面にしているすべての物が対象）
- **ボードに書く** — 右クリック「ボードに書く」で、マップエディター系の描画パネル`WhiteBoardEditorComponent`を開く（遅延読み込み。板1枚につきパネル1枚）。板は完成画像だけでなく描画シーン（`scene`。マップエディターの`MapScene`のJSON）を持つので、前に書いたものも後から消しゴムで消せる。描画はレイヤー単位で、グループ化・固定・不透明度・方眼を持つ。新しい線は、選択中のレイヤー、受け入れられる最上位のレイヤー、新規レイヤーの順に入る（`white-board-sheets`の`layerFor`）。「目の細かさ」を変えても板の実寸は変わらない（`ruleBoard`）
- **板が着る絵と自動保存** — 編集が600ms止まると`BoardKeeper`（`white-board-keeper`）が保存する。`scene`を書き、補助線を除いたシートをWebP（品質0.92）に描いて`ImageStorage`へ足し、板の`imageIdentifier`を差し替えて旧画像を消す。保存待ちのままパネルを閉じたときは`scene`だけを書く。ほかの参加者には画像本体が名前より後に届くので、板は`ObjectChangeService.fileVersion()`も購読している（購読しないと、誰かが動かすまで白紙のまま）。「画像として保存」は白地のPNGを手元にダウンロードするだけで、部屋には送らない
- **動く絵は焼かずに重ねる** — アニメーション画像は静止画の「着る絵」から外し、`bg-contain`と同じ縮尺・余白で`<img>`として上に重ねる（`white-board-live-pictures`の`livePicturesOf`）。切り抜き・マス目クリップがあるもの（`crop` / `clipToCells`）と、上のレイヤーに何か描いてあるもの（重ねると上の線や文字を覆うため。機能レイヤーは数えない）は焼き込んで止める。焼くか重ねるかの判定`hangablePictureIds`は板とエディターが共有するので、二重に描かれることも欠けることもない。「板を透過する」は地の不透明度だけを0にして直前の値を覚えておくので、地図の上に書き込みだけを浮かせられる
- **裏から見た板** — 板を裏から見ると、板の色がその不透明度で見えるだけで、書いた物や貼った絵は見えない（鏡写しにしない）。canvasは表の絵を片面で描き、同じ位置に逆向きの色だけのスプライト（`#back`、`look`は`colour`）を重ねる（`whiteBoardSprites`）。不透明度が0の板には裏を描かず、動く絵の箱は`backface-hidden`で裏から消す。裏から押しても板をつかめる
- **保存** — 貼った画像の名前はXMLの属性には無く、`scene`のJSONの中（`imageIdentifier`と、接頭辞`image:`付きの`textureId`）にしか無い。そこで`WhiteBoard.carriedImageIdentifiers`が拾い、`SaveDataService.withCarried`が部屋の保存zipにも単体保存にも同梱する。右クリック「このボードを保存」は板だけを`whiteboard_<名前>`として書き出し、載っているコマは含めない（部屋のコマがたまたま載っているだけなので）
- **詳細ポップアップと拡大表示** — 板にマウスを乗せると、`white-board-face`（`WhiteBoardFaceComponent`）と名前が出る。この部品は色・着る絵・動く絵を板の縦横比のまま枠に収めたもので、載っているコマは含めない。カードと同じ「拡大して見る」ボタンで画面いっぱいに広げられ（`overview-panel`）、ポップアップと拡大表示が同じ部品を使う。ポップアップは、板全体を覆う面の要素から開く

## コイン

- **コイン** — `Coin`（`domain/coin/coin`、`@SyncObject('coin')`）。SyncVarは`face`（`front`か`back`、既定`front`）・`isLock`・`rotate`・`zindex`で、大きさ（未設定は1マス）は共通データに、表と裏の画像は画像データに持つ。卓の右クリック「コインを作成」で置き、コインの右クリックの「コインを投げる」、今の面に応じた「表にする」か「裏にする」、「コインを編集」で扱う
- **投げる** — `CoinFlipService.flip`（`application/coin/coin-flip.service`）が表と裏を1/2ずつの確率で選ぶので、前と同じ面が出ることもある。`callFlipCoin`で全員の画面のコインを回し、自分の画面ではネットワークの往復を待たずに回し始める（`ObjectChangeService.notifyCoinFlipped`）。900ms後、投げた人が読んでいるチャットタブへ「{{who}} が {{name}} を投げました → {{face}}」をシステムメッセージとして送り、その時点でコインが消えていれば送らない。表か裏かは2面のダイスと同じなので、ダイスと同じく読んでいるタブに出す
- **絵のない面** — 画像を設定しない面は金色のコインとして描き、表には星と光の筋を、裏には月桂樹の葉を刻む（`domain/coin/coin-emblem`。描くのは`infrastructure/table-3d/coin-sides`）
