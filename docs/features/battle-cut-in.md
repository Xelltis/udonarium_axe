# 戦闘カットイン

## 戦闘カットイン

攻撃する側と受ける側のコマを左右に並べた帯を全員の画面に出し、エフェクト・数字・バーの減り・撃破を見せる（`features/battle-cut-in`）。

- **送るのは場面の写し** — 送る側の端末が、変化の前後でコマを読み、名前・絵の識別子・リソースの前後の値・撃破したか・演出の識別子をまとめて`BATTLE_CUT_IN`で送る（`domain/battle/battle-scene`、`application/battle/battle-launch.service`）。受け手は描くだけなので、変化が遅れて届く画面でも同じバーの減り方になる。同期オブジェクトは作らず、部屋に残らない。旧版のピアはイベントを知らないので何も出ない
- **前を読むのは同期で** — チャットの`《vs》`は、`resourceEditMessage$`を聞いたその場で`takeBattle()`を呼ぶ。ダイスボットは`loadGameSystemAsync`を待ってから値を書くので、これより前に読める。変化を待つのは`finishAfterChange()`で、見ているリソースの変更通知のあと200ms待ち、前の読みと比べて数字が本当に動いたときだけ送る。触っただけの通知（起動直後の書き戻しなど）で先に送ってしまうのを防ぐため。5秒待っても動かなければ、そのときの数字で送る。数字を動かさない行（`lineChangesResources`が偽）は待たない
- **最初の通信に入れない** — 場面を組み立てる`BattleLaunchService`は`BattleLaunchLoaderService`が初回に読み込み、受け取って再生する側は`BattleCutInReceiverService`を`BattleCutInEventHandlerService`が初回に読み込む。オーバーレイは`@defer (when …)`。`prefetch on idle`は付けない（アプリで唯一の利用になり、idleトリガーの実行時コードがinitialに入る）。舞台にしか使わないグラデーションや影は、Tailwindのクラスにせずコンポーネントの定数から`[style]`で渡す（クラスにすると全員が読み込むスタイルシートに入る）
- **舞台は卓の描画を流用** — 床を`rotateX(64deg)`（`BATTLE_VIEW`）で寝かせたCSSの3Dの板にコマを立て、エフェクトは卓と同じ見た目（`domain/effect/scene/effect-frame`の`stageEffect`）を、卓と同じ`EffectLayer`で板に重ねた透明なcanvas 2枚に描く（`infrastructure/table-3d/effect-stage`の`createEffectOverlay`）。床の印はコマの下のcanvasに、ほかはコマの上のcanvasに描く。canvasのカメラは、板の透視（`BATTLE_PERSPECTIVE_PX`）・床の中心の高さ（`BATTLE_FLOOR_TOP`）・拡大・傾きに合わせて置く。1マスの大きさは、卓のコマがおよそ1.5マスの高さで立つのに合わせ、舞台のコマの高さ110pxを1.5で割る（`BATTLE_SCENE_CELL_PX`）。斬撃も卓と同じ大きさで描く。canvasを作れないブラウザでは、コマの絵の破片のほかは描かない。崩壊と両断が切るコマの絵の破片は卓と同じ`cutPictureSprites`で板の上に重ね、攻撃の破片は体の高さまで上げ（`BATTLE_EFFECT_RISE_PX`）、撃破の破片は上げずに、コマの絵を描く高さ（`defeatPictureHeight`）から基準の大きさを決めて絵に合わせる。舞台のコマは`animate-defeat-*`のキーフレームで消える。卓のコマも同じ名前・長さ・形の動き（`domain/tabletop/world/piece-motions`の`defeat-*`）で消えるので、崩れた破片と二重に見えない
- **時間割は純関数** — 開く → 踏み込み → 着弾（`effectLandingTimes`の最初）→ バーが減る → 撃破 → 閉じる、を`domain/battle/battle-timeline`が経過時間から出す。攻撃側のリソース（MPなど）は撃った瞬間に減らす。アニメーションを停止にしている画面は、閉じる直前の様子を静止画で2.6秒出す
- **組と攻撃演出はコマの属性** — `GameCharacter.battleSide`（`left` / `right` / 空）と`battleEffect`（エフェクト名）。識別子は保存で振り直されるので、組を部屋の設定に識別子で持たない。組での再生は、手番 → 押した人のコマ → 左の先頭、の順に組にいるコマが攻撃する（`lineupBout`）。リモコンと右クリックの「このコマで攻撃」は`playLineupAs`で、手番に関係なくそのコマが攻撃する。コマの攻撃演出は名前で引き、GM専用のエフェクトでも見つける（設定したのはコマを扱える人なので）。チャットの`《名前》`はふだんどおり`findByName`で引く
- **部屋の設定** — `Config._battleCutIn`に既定と違う項目だけをJSONで持つ（`domain/battle/battle-settings`。舞台・登録した画像と選んだ画像・撃破の有無・撃破のリソース名・撃破の演出）。空・読めない値は既定（撃破あり・HP・崩壊）。撃破は「0より大きかった値が0以下になった」ときだけで、増えるほど悪いリソースは最大値に達したとき
- **舞台の絵** — 舞台は10（`BATTLE_THEMES`）。5つのジャンル（`BATTLE_GENRES`）それぞれに夜と昼がある。夜はジャンル名のまま（`fantasy`など。昼を足す前からの名前なので、そのとき選んだ舞台は同じ絵で読める）、昼は`fantasy-day`のように`-day`を付ける（`battleThemeOf`）。既定は`fantasy-day`で、知らない値も既定と読む。場面に`theme`として載せて送るので全員が同じ絵を見る。絵は`assets/images/battle/`のWebP（Adobe Fireflyで生成した16:9）で、舞台を再生したときに初めて読む。パネルの選択肢は`thumb/`の縮小版を使う。帯の縦横比は画面ごとに違うので、絵ごとの`object-position`（`battle-themes`の`focus`）で地平線と見どころを残す。帯は画面の高さの84%、コマの足元は帯の72%の高さに置く。縁取り・名前欄の色・「撃破」の色は舞台ごとに決めてある
- **登録した画像** — GMが「画像を登録」で選んだ画像の識別子を`pictures`に足し（24枚まで、`BATTLE_PICTURE_LIMIT`）、そのまま`background`に入れて選ぶ。舞台を選ぶと`background`を空にする。読むときは`background`をかならず`pictures`に含め、上限を超えた分は後から足したものから落とす（選んでいる画像は残す）。場面には`background`の識別子を載せ、受け手にまだ画像が届いていなければ舞台の絵を出す。登録した画像の上では、何が描かれているか分からないので、縁取り・名前欄・「撃破」を決まった配色（`BATTLE_PICTURE_LOOK`）で描く。画像の識別子は`Config`の中のJSONにしか出ず、XMLをたどっても見つからないので、`Config.carriedImageIdentifiers`で部屋のセーブに入れる
- **個人設定** — 出すかどうかは`BattleCutInPreferenceService`（localStorage、既定は出す）。出さない画面では、受け取った場面から攻撃のエフェクトを卓のコマに`EffectCastService.playHere()`で出し、撃破があれば着弾とバーの減りのあとに撃破の演出も出す
- **入口** — チャットの`《vs》`（`domain/effect/effect-chat-token`の`hasBattleChatToken`。同じ行の`《名前》`は卓に撃たずカットインで使う）、パネル、リモコン（ボタンと「戦闘カットインでも見せる」）、コマの右クリック、スイッチの動作`battle`（旧版は`unknown`として保ったまま何もしない）。全員に出す入口のうち、チャットの`《vs》`・パネルの「全員に再生」・リモコン・コマの右クリックは`canEditTabletop`の人だけ（見学者は「自分だけで見る」のみ。見学者の発言の`《vs》`は何も起こさない）。スイッチはGMが置いたものなので見学者も押せる。チャットの行が戦闘になるかは`chatLineBout`で決め、エフェクトの側も同じ関数で、戦闘にならない行（話者がコマでない・相手がいない）では卓にエフェクトを撃つ。数値の変化を待つのは、話者や対象が持つリソースを`+`・`-`・`=`で変えるコマンドがある行だけ（`lineChangesResources`）
