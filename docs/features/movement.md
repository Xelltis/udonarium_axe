# 移動と戦闘

## 移動範囲

- **移動範囲を組む所** — 盤面を読むのは`MoveRangeService`（`application/tabletop/move-range.service`）、範囲を組むのは純関数`buildReach()`（`domain/tabletop/move/reach-build`）。サービスは移動範囲が入っている卓で、壁面ではなく床の面に置いたコマだけを相手にし、移動力をシートの`moveRangeElementNames`（既定`'移動,移動力,Speed,速度'`）のうち最初に数のある欄から読んで1マスの距離で割る（`domain/tabletop/move/move-cells`）。地形のラスタ・足場の高さ・見えているコマ・パーティの同盟・移動コスト表・交戦エリアを`ReachInputs`に詰めると、`buildReach()`が通れないマス・1歩の値段（`costOf`）・止まるマス（`stopsAt`）・止まれないマス（`restsAt`）を組んで`reachableCells()`に渡す。値段は半マス単位の歩数で数える（道の扱いは[機能塗り](map-editor.md#機能塗りマップエディター)）。画面に出し続ける範囲（選んだコマと、他人が計画しているコマ）は、コマと移動の種類ごとに、`reachToken`（卓・`Config`・コマの並び・パーティ・地形・移動コスト・視界・交戦エリア）とコマの版に照らして使い回す（`REACH_CACHE_LIMIT`＝64件）。持ち上げたときと計画を開くときは、動いたばかりの壁がまだ誰にも告げられていないことがあるので、卓から読み直す
- **厳密な移動** — `Config.moveStrict`（部屋の決めごと、文字列boolean）。入っている部屋では、コマを掴むと運ぶ代わりに移動の計画が開く（`game-character.component`の`onGrab()`が`MovePlannerService.begin()`を呼ぶ）。Shiftを押しながら掴んで計画を開かずに運べるのはGMだけ（キーを押すだけで誰でも抜けられるなら、決まりとして卓を縛れないため）。計画を開けないコマ（移動力の欄がない・移動範囲が切ってある）は、これまでどおりどこへでも置ける。ただし交戦エリアに止められたコマは、GM以外には運べない。設定が終点と経路の2つに分かれていたころに保存した部屋は、`_moveStrictPath`が`'1'`でも厳密な移動と読み、書くときに`_moveStrictPath`を空にする（`domain/peer/config`）
- **移動の計画** — `MovePlanService`（`application/tabletop/move-plan.service`）。入口はコマのメニューの「移動」（移動範囲を出せるコマにだけ出す）、Shiftを押しながら掴む、厳密な移動の部屋で掴む、の3つで、どれも`MovePlannerService.begin()`を通る（グリッドなしの卓を折れ線で引く部屋では`FreeMovePlanService`へ渡す）。コマはその場に置いたまま`cheapestPath()`（`domain/tabletop/move/cheapest-path`）でポインタまでの最安経路を引き、クリック/タップかEnterで`run()`が1マスずつ歩かせる（1歩は`application/tabletop/piece-step.service`の`PieceStepService`）。Shift+クリック・右クリック・長押しが`settle()`で経由点を置き、同じ場所をもう一度押すと`unsettle()`が最後の1つだけ取り消す。経由点を置くたびに、残りの移動力で`reachableCells()`を引き直す。Escか、歩く道のない所を押すと中止する。リーチと同じ`ReachTerms`（`MoveRangeService.termsOf()`）で値段を付けるので、描いた線と数える歩数がずれない。組み立てている間は`PeerCursor`の`movingCharacterIdentifier` / `movingTableIdentifier` / `movingWay` / `movingJumping` / `movingKind`で部屋へ配り、各画面が受け取ったコマの移動範囲を自分で引き直して破線で描く（範囲そのものは配らない。見えていない敵の位置が漏れるため）。入力を受けるのは`features/tabletop/table-move-range-overlay/move-plan-event-handler.service.ts`（計画中だけdocumentを聴き、開いた押下の離しで出るクリックは無視する）
- **移動の種類** — `Config`の`_moveKinds`（部屋設定の「移動の種類」）。「名前:倍率:上限(m)」をカンマで区切って並べ、`parseMoveKinds()`（`domain/tabletop/move/move-kind`）が読む。先頭が既定で、空欄なら倍率1の名前のない種類（`PLAIN_MOVE_KIND`）だけになる。範囲の広さは`cellsByKind()`が移動力に倍率を掛け、上限があれば1マスのメートルで割ったマス数で抑えて、整数マスに切り捨てる。計画中は画面下の帯で選び替えられ、最初の経由点を置いたあとは変えられない（`MovePlanService.setKind()`）。交戦エリアの「超過時に離れられる種類」と「割り込みに使う種類」も、この名前で種類を指す
- **グリッドなしの卓の折れ線** — `Config`の`_pathMove`（部屋設定の「グリッドなしの卓では、経路を折れ線で引く」、既定は切）。入っていてグリッドなしの卓なら、`MovePlannerService`が計画を`FreeMovePlanService`（`application/tabletop/free-move-plan.service`）へ渡す。経路はマスではなく直線の脚をつないで引き、長さをメートルで数える。脚は残りの移動力で切れ、越えられない地形と入れない交戦エリアの手前で止まる。止める交戦エリアに入るか、立っているエリアから出ると移動が終わる（`domain/tabletop/move/free-path`）。跳び越えはなく、経路の点は`PeerCursor.movingPoints`で配る
- **跳び越え** — 計画中にスペース、または画面下の帯の「歩く／跳ぶ」で切り替える（`MovePlanService.toggleJump()`）。跳んでいる間は高さで止まらなくなり、`terrainBlocksJump()`（`domain/tabletop/move/blocked-cells`）が拾う**登れない地形だけ**が残る。`ReachTerms`が歩き用（`blocked`）と跳び用（`leapt`）の2つの`CellBits`を持ち（地形のほかは共通なので1度だけ集めて双方へ被せる）、切り替えのたびにいまの位置から`reachableCells()`を引き直す。範囲は紫で描き分ける。歩かせるときは`PieceStepService`が到着マスの地形の天面（`landingHeightAt()`）を`posZ`に直接置く（**重力は自分より上のものには乗せないので、任せると壁の上に立てない**）。高さが変わる1歩は弧を描いて跳ぶ（`hopHeightAt()` / `hopLiftFor()`、跳ぶ高さは段差の0.8倍で、少なくとも0.3マス。これだけあると進行の3割で着地点の高さを越えるので、壁の面を登るようには見えない）。降りるのは切り替え不要（床は歩きでも行ける）。どちらの規則で動いているかは`PeerCursor.movingJumping`で部屋へ配り、他人の範囲もその規則で引き直す（`domain/tabletop/move/landing-height`）
- **跳躍の距離** — `RoomRules.jumpCells`（0は移動力いっぱい）。`MovePlanService.legRoom()`が`toggleJump()` / `settle()` / `lookAt()`の3か所で`Math.min(残り, stepsFor(jumpCells))`を返す。脚ごとに掛かるので、経由点を置くたびに1回ぶんの跳躍に戻る
- **渡るのに余分にかかる地面** — `buildReach()`の`costOf`が`moveCostCells()`の項を足す。値段の順は`1 + 移動の仕方の上乗せ + 地面 + 押し込み + 通り抜け + ZOC`で、離脱の`breakOutToll()`は「出る一歩」への課金なので最後。マス単位の値段を最後に`stepsFor()`で歩数にし、`reachableCells`側で`Math.max(1, Math.ceil(歩数)) * corner`が掛かるため、**斜めコストは乗算**（ZOCの追加コストと同じ）。上乗せが何もない卓にも素の`PLAIN_GOING`（1マス＝2歩）を渡す（探索の既定の1は半マスにあたるため）。`MoveRangeService`はコスト表を`dearToken`（`collectionOf(TableMoveCost.aliasName)`＋各`versionOf`）でmemoする。**卓の版だけでは子の属性変更を拾えない**ため
- **歩く以外の移動** — `MOVE_MODES`（`domain/tabletop/move/move-mode`、`walk` / `climb` / `swim` / `crawl` / `fly`）を`GameCharacter.moveMode`に持たせ、`MOVE_MODE_TERMS`が`toll`（1マスごとの上乗せ）・`paysGround`（地面の追加コストを払うか）・`clears`（跳び越えと同じものを越えるか）を返す。`buildReach()`は`toll`を`costOf`の先頭に足し、`paysGround`が偽なら`moveCostCells()`を引かず、`clears`が真なら`blocked`を`leapt`に差し替える（跳び越え用の集合をそのまま使い回す）。`clears`の種類は盛った地面の崖でも止まらない。入口はコマの右クリックメニューの「移動の仕方」で、**移動の計画を出せるコマにだけ出す**（リーチの無いコマには意味が無い）
- **まとめマス** — `GameTable.squareSpan`（既定1、上限`MAX_SQUARE_SPAN`＝4、テーブル設定の「移動と射程の1マス」）。四角のグリッドの卓だけで使い、ヘクスとグリッドなしの卓は常に1と読む（`squareSpanOf()`）。`moveGridOf()`（`domain/tabletop/move/move-grid`）が`squareGridOver()`で卓のマスを束ねた粗い格子を作り、移動・経路・射程・ZOCはその1つを1マスと数える。割り切れない端は、切れたまま1マスと数える。地形・塗り・高さ・コマは卓のマスのまま持ち、移動コストは中のマスで最も高い値（道が1つでも通っていれば道）、地形で塞がるかは`squaresClosedBy()`が壁がまとめたマスを横切っているかで決める。スナップが「グリッド」なら、コマはまとめたマスの中の置いたマスに止まる（`keepsToCells`）。一人称の1歩は卓のマスずつ
- **通り抜けと停止を割る** — `ReachOptions.restsAt`（`domain/tabletop/move/reachable-cells`）。偽のマスは`reached`に入れないが**枝刈りはしない**ので、その先は届く。`cheapestPath()`はgoalが偽なら`null`。`MovePlanService`は`plan.reach`に`terms.cells`を使い、引き直しに`...terms.options`を展開して渡すので、計画も同じ判定に従う。そのため**止まれないマスは経由点にもできない**。`buildReach()`が`restsAt`を立てるのは、ほかのコマが立つマスのうち通れても止まれないもの（`passageCells()`の`noStop`）
- **パーティごとの通り抜けとZOCの敵味方** — `relationBetween()`（`domain/tabletop/move/piece-relation`、`same` / `other` / `none`）と`passageCells()`（`piece-passage`、`block` / `pass` / `cost` / `share`）。`RoomRules`の`samePartyPassage` / `otherPartyPassage` / `noPartyPassage` / `piecePassageCost`（既定1）。**既定は`piecesShareCells`から導く**（`diagonalMove`が`moveDiagonally`に落ちるのと同じ手。`true→share` / `false→block`）ので、触らない部屋は寸分同じに動く。ZOCの敵味方は`RoomRules.hostilityBy`（部屋設定の「敵味方の分け方」）で決める。既定の`npc`は`isNpc`で分け（所属を持たないコマが多いため）、`party`では`relationBetween()`が`other`と答える相手だけが敵になり、どのパーティにもいないコマは誰の敵にもならない（`isHostileTo()`、`domain/tabletop/move/zone-of-control`）
- **大きさの差ですり抜ける** — `RoomRules.sizeSlipsPast`（既定は切）。`passageCells()`は、`block`になる相手のうち大きさが`SLIPS_PAST_CELLS`（2マス）以上違うものを`pass`に読み替える。通れても止まれない
- **パーティ同士の同盟** — `Party.allies`（識別子をスペース区切り。`FogMemory.found`と同じ書き方）。編成パネルの「同盟:」で選ぶ。`allianceOf()`（`domain/party/party-alliance`）が`PartyAlliance = (a, b) => boolean`を組み、**片側が名指しすれば成立**（両方に書かせると、半分だけ書いた状態が気づかないうちに効かないままになる）。`relationBetween(piece, mover, allied)`が同盟相手を`same`に落とすので、通り抜けと、敵味方をパーティで分ける卓のZOCの両方が一度に変わる。既定は`NO_ALLIANCE`なので、触らない部屋は寸分同じ。`MoveRangeService`は`partyToken`（`collectionOf(Party.aliasName)`＋各`versionOf`）をreach tokenに混ぜて、同盟を切り替えたら全リーチを引き直す
- **狭い隙間への押し込み** — `RoomRules.squeezes`（既定は切）。大きなコマは足跡の全マスが空いていないと入れないが、入れると、本来の大きさで入らないマスでも、ひと回り小さい足跡（`pieceFitsOn()`の`across`）で入れば通す。畳んだ足跡の角は`piece-on-grid`の`sizeShiftOf()`で出す。どちらの大きさでも入らないマスは`buildReach()`が`blocked`に足し、畳んで入るマスには`costOf`が1を足す。**大きさ2のコマは畳むと1マスなので述語が`null`になる**。その場合は「どこでも入る」と読む
- **通り抜けも見えているコマだけを見る** — `MoveRangeService.build()`が`isTokenVisible()`で濾した一覧を`buildReach()`に渡し、通り抜け（`passageCells`）とZOC（`heldGroundAround`）の双方がそれだけを見る。**へこみは位置だけでなく陣営も漏らす**（味方は通れて敵は通れないため）

## 交戦エリア

- **持ち方** — `EngagementZone`（`@SyncObject('engagement-zone')`、`domain/tabletop/zone/engagement-zone`、卓の子）は位置と形だけを持つ。欄は`centreX` / `centreY` / `capacity`（定員。空なら大きさの表どおり）/ `shape`（`square`か空で円）/ `forming`で、全部テキストにしてある。属性が欠けて届いたエリアを、原点に立つエリアと読まないため。誰が加わっているかは各コマの`GameCharacter.engagementZone`に書く（2人が同時に加わっても別のオブジェクトに書くので衝突しない）。大きさは人数から毎回出し、保存しない
- **作る・結合する・消える** — 部屋設定の「交戦エリアを使う」（`Config`の`_zoneEnabled`、既定は切）。同じ点（「同じ点とみなす距離(m)」、既定1m）にいる敵にコマのメニューから交戦を宣言すると、相手の点を中心に円のエリアができる。どちらかがすでにエリアにいれば、もう一方がそこに加わる（`EngagementZoneService.declare()`、`application/tabletop/engagement-zone.service`）。手で置くか計画した移動で敵と同じ点に止まったときは、画面下の知らせに「交戦する」を出す（`offerFight()`）。大きさは「大きさの表」（`DEFAULT_ZONE_SIZES`＝`'4:2:3,8:3:5,12:4:7,16:5:9,20:6:11'`、人数の上限:半径(m):正方形の一辺(m)）を人数で引き、最後の行の人数が定員の上限になる。「人数として数える値」にシートの欄を書けば、その値をコマの人数として数える。中心がほかのエリアに入ると結合し、敵がいなくなると消える。どう結合して消えるかは純関数`zoneStateOf()`（`domain/tabletop/zone/zone-state`）が加わっているコマから出し、操作した端末がすぐに書く。エリアを通さない変化（コマの削除や手で運んだとき）は、`TIDY_DELAY_MS`（500ms）待ってから1つの端末が書く。書くのはエリアの整理に対応した版（`PeerCursor.zoneProtocol`が`'1'`）の席のうち、GMでpeerIdが最も小さい席（GMがいなければ全員のうち最小の席。`keepsOrder()`）
- **移動との関係** — `zoneMoveLimits()` / `zoneReachTerms()`（`domain/tabletop/zone/zone-queries`）が、エリアに加わっているコマをエリアの中心から歩き出させ、定員を超えるエリアを通れないマスに、止めるエリアを止まるマスにして`buildReach()`へ渡す（`ZoneReachTerms`）。加わっていて離れられないコマには範囲を出さない（`noReach`）。離れられるのは、前のラウンドまでに「次の手番で離れると予告する」を選んだとき（`zoneLeaveRound`）、自分の陣営がほかの陣営の「人数比の倍率」（既定2）倍を超えるとき、定員を超えたエリアから「超過時に離れられる種類」で動くとき（`leaveReasonOf()`、`domain/tabletop/zone/zone-leave`）。陣営は[移動範囲の敵味方](#移動範囲)と同じ`hostilityBy`で分ける（`sideOfPiece()`）。乗り物と前の乗り手は1組で数え、人数は2体の合計にする（`frontRidersOf()`）。定員を超えたエリアの中で、加わらずに手番を始めたコマはそのエリアに加わる（`pullInAtTurnStart()`）。移動範囲の`RoomRules.zocEngages`も隣り合うコマを1つの戦いにまとめるので、両方が入っていると部屋設定に注意を出す
- **移動の割り込み** — 部屋設定の「移動の割り込みを使う」（`Config`の`_interruptEnabled`）。計画した移動を歩かせる前に、`MoveInterruptService.negotiate()`（`application/tabletop/move-interrupt.service`）が移動を自分の`PeerCursor.movingDeclared`で告げる。割り込めるコマに答える端末（持ち主、持ち主のいないコマはpeerIdが最小のGM）は、自分の`PeerCursor.interruptAnswer`に割り込む地点か見送りを書く。全員が答えるか、GMが「今すぐ決める」を押す（`interruptVerdict`）か、`INTERRUPT_WAIT_MS`（15秒）が過ぎると、始点に最も近い有効な割り込みで止まり、割り込んだコマと新しいエリアを作る。行動順を回している間に作ったエリアは手番の終わりまで`forming`で、点線で描く。どの端末も自分のカーソルにしか書かないので、答えが上書きし合わない。入っているときは、エリアに入る移動と中から出る移動も、エリアの側が止めるかを選び、止めると動いたコマはエリアの中心に移って加わる（`stopsByChoice()`）。答える人のいないエリアと、切ってあるときは、エリアがいつも止める。計画の帯の「止められない移動」は最初の経由点を置く前に選び、割り込みでもエリアでも止まらない（`unstoppableMove`）
- **コマの状態** — コマのメニューの「交戦エリア」から付け外す。値は`'1'`か空。`offField`（「場から外す」、どのエリアにも数えない）、`unseen`（「姿が見えない（移動を止められない）」、止めたときはその場でエリアを作る）、`downed`（「倒れている（行動できない）」、エリアから外れる）、`heldFast`（「その場から動けない」）。同じ点の敵をつかむと、つかまれたコマの`grabbedBy`につかんだコマの識別子を書き、つかまれたコマは自分では動けずに相手について行く。部屋設定の`_zoneStealthUnseen`を入れると、ステルス中のコマも`unseen`と同じに扱う
- **射線チェック** — コマのメニューの「射線チェック」は、ターゲットにしたコマまでの射線を純関数`lineOfFire()`（`domain/tabletop/zone/line-of-fire`）で調べる。撃つ側とターゲットのエリアを除き、線が横切るエリアと、どのエリアにも加わらず中にも立っていない、場に出ている撃つ側の敵で、線から「射線を遮る半径(m)」（既定0.5）以内にいるものを遮るものと数える。撃つ側のシートの項目かバフに「遮りを無視する能力」の名前があれば数えない。エリアの外から中へ撃つと、そのエリアの誰にでも当たりうる
- **初期配置** — GMが使うパネル（`features/character/battle-placement-panel`、メニューの「初期配置」）。双方の先頭のコマと、相手のいる向き（8方向）と距離を選ぶと、相手の先頭をその距離と向きに置き、それぞれの陣営を先頭の周りに集める。場から外したコマは動かさない。距離は「初期配置の距離表」（`_placementDistances`、「名前:距離(m)」）から選び、「距離による修正表」（`_distanceModifiers`、「距離の上限(m):修正」）のうち今の距離にあたる行を出す。距離の代わりに状況や移動の種類の名前を書いた行には、パネルで当てはまるものに印を付ける（`domain/tabletop/zone/battle-placement`）

## 乗り物と部位

- **乗る・降りる** — 状態は乗る側の`GameCharacter`の文字列の欄に持つ。`ridingOn`は乗っているコマの識別子、`rideSeat`は空が前で操る、`passenger`が後ろに同乗、`cargo`が積まれる、`part`が部位。乗り物にするのはコマのメニューの「乗り物」の「乗り物にする」（`mountable`）で、「同乗できる」（`mountPassenger`）・「積める数」（`mountCargo`。積める乗り物は同乗を取らない）・「技能がなくても乗れる」（`mountAnyone`）・「乗る高さ」（`mountSeatHeight`）を決める。乗り物の上に置くか、計画した移動で乗り物の上に止まると、画面下の知らせに「乗る」などを出す（`RideService.offerRide()`、`application/tabletop/ride.service`）。同じ点にいるか、乗り物の台座の上に真ん中があれば乗り物の上と見なす。乗っているコマを乗り物の外に手で置くと降りる（`afterPutDown()`）。乗り降りはチャットに出し、手番の行動を使うかを添える。操れるコマが前で乗り降りするときと、積まれたコマを降ろすときは使わず、ほかは使う（`domain/tabletop/ride/ride-rules`）
- **乗っている間の移動** — 前に乗ったコマを動かすと、乗り物の移動として計画を開く（`RideService.moverFor()`）。後ろの同乗者と積まれたコマは自分では動かず、乗り手のいない乗り物はGMにしか動かせない。乗っているコマは乗り物と一緒に動き、乗る高さに立つ。既定の高さは、コマの高さを指定した乗り物なら絵の上端、指定していなければ大きさの半分。`mountSeatHeight`にはマス数・`380px`のようなピクセル・`75%`のような割合を書く。セル数しか知らない版は、ピクセルと割合を自分の既定として読む（`readSeatHeight()`）。乗り物ではないコマの移動範囲では、乗り物とその乗り手のマスを止まれる地面にする（乗りに行くため。`inTheWayOf()`）
- **手番との関係** — 縛るのは行動順を回しているときだけ。乗り降りは1手番に1回（`rideChangedTurn`）、乗り物が動けるのは1ラウンドに1手番（`rideMoveTurn` / `rideMoveM`）。手番中に降りたコマが自分で歩けるのは、前で操っていたか積まれていて、乗り物がまだそのラウンドに動いていないときだけ（`rideMoveRefusal()`）。前の乗り手が乗り物と後ろの同乗者の手番をまとめて取り、部位の手番は本体にまとめる（`turnCarriers()`）。手番の目印は`ラウンド:手番のコマの識別子`の文字列（`turnMarkOf()`）
- **転ぶ・落ちる** — 「転んでいる」（`prone`）。乗っているコマが倒れるか転ぶとそのコマが、乗り物が倒れるか転ぶと乗っている全員が落ちて転ぶ（`fallersWhenDown()`）。前の乗り手が落ちると同じ乗り物に積まれたコマも落ち、後ろの同乗者は残る。落下距離は乗り物が動いた距離の1/5を切り上げた値で、部屋設定の最低距離（`_fallMinM`、既定`DEFAULT_FALL_MIN_M`＝2m）を下回らない（`fallDistanceM()`）。チャットに距離を出し、「落ちたときに振る式」（`_fallDamage`）があれば`{m}`を落下距離に置き換えて振る。自分の手番に転んだコマは、次の手番まで起き上がれない（`proneTurn`）
- **操る技能とふたり乗り** — 部屋設定の「乗り物を操る技能の欄」（`_rideSkillField`）を書くと、その値が1以上のコマだけが乗り物を操れる。操れないコマは「技能がなくても乗れる」にした乗り物にだけ前に乗れる。「乗るのに要る値の欄」（`_rideRequireField`）を書くと、乗り物のシートのその値より技能が低いコマは乗れない（`frontRefusal()`）。「ふたり乗りのバフ」（`_twoUpBuff`、チャットのバフと同じ書き方）を書くと、前と後ろに2人とも乗っている間だけ両方に付け、外すときは付けたバフ（`rideTwoUpBuff`）だけを外す。同じ名前のバフをもう持っているコマには付けない
- **部位** — `rideSeat`が`part`のコマ。`PiecePartsService`（`application/tabletop/piece-parts.service`）が付け外しを持ち、同じ所に立つコマを部位にできる。部位の部位は作れない。部位は卓に描かず、名前・バー・バフを本体の名札の下に並べ、手番は本体にまとめる。乗り物とは分けてあり、降りる・落ちる・乗る高さは部位にはたらかない（`PieceLinksService.mountOf()`は部位を返さない）。本体を卓・インベントリ・墓場などへ移すか消すと、同じ所にいる部位もついて行く（`GameCharacter.partsAlong()`）
- **部位の行** — 名札の行は`PieceRidingLabels`（`features/character/game-character/piece-riding-labels`）が1行ずつの値に組む。バフは本体の「バフの表示」（`BuffViewMode`）に従い、行はアイコン（`badges`）・詳細（`buffRows`）・個数（`buffCount`）のうち選ばれた1つだけを持つ。描くのは本体のバフと同じテンプレート（`buffsView`）。乗っているコマの行と、名札の中の本体の行も同じに従う。部位の行は`appTooltip`に`detail`（内容を見られる部位。見られなければ`null`）を渡し、乗せるか、タッチで押すと、その部位の詳細の小窓を出す。行は本体のコマの要素の中にあるので、`TooltipDirective`は内側の行にポインタがあるあいだ外側（本体）の小窓を出さず、行から本体へ移ると本体の小窓に戻す。タッチの1回の押下は、行のターゲットの切り替えと小窓の両方に届く（本体のコマを押したときに選択と小窓の両方が動くのと同じ）。`detail`が`null`の行では、本体の小窓がそのまま出る
- **部位の見た目** — 部位のメニューの「部位の見た目を編集」（`features/character/part-look-editor`）。2Dは、部位の絵を本体の絵に重ねる（`partLayer`、位置と幅は本体の絵に対する割合と前後の順）か、本体の絵を塗って部位の範囲を切り分ける（`partMask`、96×96のマス目を基数36の連長で書く）。3Dは本体のモデルの面をブラシで塗る（`partFaces`）。三角形の番号は塗ったモデルでしか通じないので、モデルごとに分けて持ち、本体が別のモデルに替わっても塗った面を残す。部位が欠けると、重ねた絵・塗った所・塗った面が消える。欠けるのは、部位が「倒れている」ときか、コマに出す最初のリソースが尽きたとき（`isPartLost()`、`domain/character/part-look`）。卓で部位の所をAlt押しするとその部位をターゲットにし、右クリックで部位のメニューを出す。ドラッグは本体を動かす（`application/tabletop/piece-part-pick.service`）
- **結びつきの問い合わせ** — つかむ・乗る・部位の結びつきは、`PieceLinksService`（`application/tabletop/piece-links.service`）と純関数`piece-bonds`（`boundTo()` / `bondGroupOf()` / `boundBelow()`、`domain/tabletop/move/piece-bonds`）の1か所で答える。交戦エリア・乗り物・移動の各経路が同じ答えを使う。部位に対応していない版では、部位は本体に重なった別のコマとして見え、本体の絵とモデルは部位の見た目を描く前のまま見える

## 同行（パーティ）

- **同行（パーティ）** — キャラクター単位のパーティ編成で視界とコマの可視性を共有。GMツールバーの専用パネル（「同行」、`features/gm-tools/party-list`）から編成し、`Party`（`domain/party/party`）はルームの保存データに含まれる。PL側は所有キャラクター一覧で所属と同行者を確認できる（編集はGMのみ）。パーティ同士の同盟は[移動範囲](#移動範囲)にある
- **パーティのプレイヤー** — `Party.players`（ユーザーの識別子をスペース区切り、編成パネルの「プレイヤー:」）。チェックしたプレイヤーは、持ち主と同じくそのパーティのコマの視界を共有し、一人称でもそのコマから見られる。GMが一人称の視点を共有している間は、そのコマを歩かせられる。1つのコマをみんなで動かす卓のための欄。ユーザーの入っているパーティは、コマを持っているパーティと`players`に名前のあるパーティを合わせて`partyIdsOwnedBy()`（`domain/party/party-membership`）が出す
- **この地点に集める** — 卓の右クリックの「この地点を中心にパーティを配置」から、そのパーティのコマを指した地点の周りへ寄せる（GMのみ）。メニューは純関数`buildGatherPartyMenu()`（`features/tabletop/create-menu/create-object-context-menu`）が組み、`CreateObjectMenuService.gatherPartyMenuAt()`が`TabletopActionService.gatherParty()`へつなぐ。並べ方は純関数`domain/tabletop/move/gather-cells`の`gatherSpotsAround`に切り出してあり、押した升目から`forEachMoveNeighbour`で近い順に広げ、ほかのコマが立つ升目（`occupiedCells`）とコマの大きさ分の広さを見て決めるので正方・ヘクスの別なく働く。卓に出ていないメンバーが居るパーティはサブメニューが2行に分かれ（卓上のみ／卓外も出す・どちらも体数付き）、確認ダイアログを挟まずに押す前に選べる。動かしたコマは`update()`で部屋へ、`notifyChanged()`で自分の画面へ告げる
- **パーティを置く処理** — 「この地点に集める」と、ダンジョン生成の「入口に集めるパーティ」（`DungeonBuildService`）は、どちらも`PartySetOutService`（`application/tabletop/party-set-out.service`）で置く。メンバーは、乗っている乗り物か、部位として付いている本体ごと置く（パーティの外の乗り物も置き去りにしない）。置いたコマの部位・乗っているコマ・つかんでいるコマも一緒に来る。一緒に来るコマを残るコマがつかんでいれば放す（残ったコマが次に動いたときに引き戻さないため）
