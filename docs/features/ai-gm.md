# AI GM

ClaudeにGMの席を任せる仕組み。[AI連携（MCP）](ai-link.md)と同じブリッジ・やりとり・道具を使い、MCPのクライアントの代わりにブリッジ自身がClaude APIを呼ぶ。
APIキーはブリッジの環境変数にだけ置き、ブラウザに入れない。Axeは他人の入力を表示するので、XSSが1つあればブラウザのキーは読まれる。SDKもブラウザでの利用を既定で止めている。

## 構成

```
Axeのタブ（GMの席）
  ├ AI GMのパネルと AiGmService: 開始・停止・設定・指示・メモ、起きたことの中継
  └ 道具（AgentToolRunner。AI連携と同じ）
        │ WebSocket（ws://127.0.0.1:47610/axe、やりとりの版4）
ブリッジ（axe-mcp.mjs gm）
  ├ GmHost: 番を回す時の判断、状態の通知
  └ GameMaster: 会話・キャッシュの配置・区切り直し・費用
        │ HTTPS（@anthropic-ai/sdk、ANTHROPIC_API_KEY）
Claude API
```

- ループと費用の上限は、キーと同じブリッジに置く。タブが渡せるのは開始・停止・指示・起きたことだけで、任意のリクエストを中継させない。タブが決める上限額は始めるたびに数え直すので、タブが乗っ取られて始め直しを繰り返したときのために、ブリッジにも起動している間の上限（`--max-usd`・`AXE_GM_MAX_USD`、初めは20ドル）を置く。これはどの始め直しにもまたがって数え、タブからは変えられない
- 道具はAI連携と同じく`call`と`result`でタブが走らせる。許可の確認・見える範囲の絞り込み・AIの印・パネルの履歴はそのまま効く
- 番を回す前に待つ時間（静かになるまでの数秒）はブリッジで測る。隠れたタブはタイマーが間引かれるので、タブは起きたことを起きた順に送るだけにする
- 内容は`core/agent`の`agent-gm`（手引き・道具の一覧・番の書き出し）、`tools/axe-mcp/src/gm`（`GameMaster`・`GmHost`・料金表）、`features/ai-gm`（`AiGmService`・番を回す規則`aiGmWakeOf`・パネル）。`features/ai-gm`は`ai-link`だけに依存する

## やりとり

`AGENT_PROTOCOL_VERSION`は4。`hello`に`mode`（`mcp`か`gm`）と、`gm`なら選べるモデルの一覧を載せる。パネルは`gm`のブリッジにつながったときだけ開始の操作を出す。

| 向き  | 種類        | 中身                                                                                                                                                                                                            |
| ----- | ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| タブ→ | `gm.start`  | 設定（モデル・考える深さ・上限額）・指示・メモ・`fresh`                                                                                                                                                         |
| タブ→ | `gm.update` | 設定・指示・メモ（動いている間に変えたとき）                                                                                                                                                                    |
| タブ→ | `gm.events` | `AgentEvent`と、番を回す理由（`line`・`called`・`turn`）                                                                                                                                                        |
| タブ→ | `gm.nudge`  | パネルの**進めてもらう**と、GMからの一言                                                                                                                                                                        |
| タブ→ | `gm.stop`   | 止める                                                                                                                                                                                                          |
| →タブ | `gm.status` | `run`（`off`・`waiting`・`thinking`）・止まった理由・使った額・上限・文脈の大きさ・会話を保っているか・最後の失敗・料金の分からないモデルで使ったトークン数と上限（`tokens`）・答えた開始の依頼の数（`starts`） |
| →タブ | `gm.notes`  | AIが書き直したメモ                                                                                                                                                                                              |
| →タブ | `gm.said`   | AIが道具の外で書いた文                                                                                                                                                                                          |

読み取りは長さと範囲を確かめる（指示は5万字、メモは8千字、一言は2千字、イベントは1回に500件まで。上限額は0より大きく1000ドル以下）。
`AiLinkService`は最後の`gm.status`と`gm.notes`を覚えておき、あとから作られた`AiGmService`に渡す。ブリッジのメモはブラウザに残ったメモより新しいので、そちらを採る。

## 提供元

`GameMaster`はAPIを`GmApi.stream()`だけを通して使い、会話・道具・区切り直しはClaude APIの形で持つ。提供元を替えるのは、この口の裏だけである。

- Claude（初めの値）は`@anthropic-ai/sdk`をそのまま渡す
- `--provider openai`は`openAiApi()`（`tools/axe-mcp/src/gm/openai-api.ts`）を渡す。Claude APIの形の要求をChat Completionsの形に写して送り（`chatRequestOf`）、応答をClaude APIの形に写して返す（`messageOfChat`）。思考・考える深さ・キャッシュの指定は送らない。失敗は同じHTTPの状態のClaude APIのエラーにして投げるので、キーが通らないときの止まり方は変わらない
- モデルの一覧は`gm-models.ts`が持ち、`useGmModels()`で提供元のものに差し替える。`--model`で渡した名前を`namedModel()`でモデルにし、`--price`があれば単価を付ける
- 単価のないモデルは`costOf()`が0を返すので、額では止められない。`GmLedger`の`spentTokens` / `limitTokens`で、ブリッジが動いている間のトークン数を数えて止める（`--max-tokens`、初めは200万）。そのモデルを動かしている間、`gm.status`に`tokens`を載せ、パネルは額の代わりにトークン数を出す
- キーは`AXE_GM_API_KEY`から読む。Claudeは`ANTHROPIC_API_KEY`のまま

## 番を回す時

タブの`aiGmWakeOf`がイベントごとに理由を付ける。

- `called`: 呼び名（初めは「GM」。大文字と小文字を区別しない）を含む行、AIの席あての秘話
- `turn`: AIが動かすコマの手番。AIが動かすコマは、`isNpc`が立っているコマと、AIの席の`userId`がオーナーのコマ
- `line`: 「発言に応える」のときだけ、聞くタブ（選ばなければ全部）での人の行

AIの行（`by_ai`）・システムの行・AIの席の人（人のGM）の行には理由を付けない。理由のないイベントも次の番に渡す。
`GmHost`は理由を受けたら、イベントが4秒来なくなるまで待ち、最初の理由から15秒たてば待たずに回す。**進めてもらう**はすぐ回す。考えている間に来たイベントは溜めて、番が終わってから同じ規則で回す。1つ前の番の途中でタブが切れたら、その番の理由とイベントを戻し、つながり直してから回し直す。

## 会話

- モデルはClaude Opus 5.5（初めの値）・Sonnet 5.5・Haiku 5.5。思考は`adaptive`、`output_config.effort`は**考える深さ**を`low`・`medium`・`high`に当てて必ず送る。`max_tokens`は16000
- 道具は`AGENT_TOOLS`から`wait_for_events`を除いた分（起きたことは番の始めに渡す）と、ブリッジだけの`update_notes`。JSON Schemaをそのまま渡し、`eager_input_streaming`を付ける。入力はタブの`AgentToolRunner`が確かめ、`update_notes`はブリッジが`checkAgentInput`で確かめる
- systemは手引き`GM_GUIDE`（`CHAT_SYNTAX_GUIDE`を含む）と、人の指示とメモ。後ろのブロックに1時間のキャッシュの印を付け、会話の末尾はリクエストの上の`cache_control`（自動のキャッシュ、5分）に任せる
- 番ごとにuserの行を1つ足し、理由とイベントのJSONを1行ずつ書く。GMからの一言と、動いている間に変えた指示とメモは`role: "system"`の行で足す。プレイヤーの発言はsystemの行と別の経路で届く
- 返ってきた`content`は思考のブロックも含めて丸ごと足し、履歴を書き換えない。中身のない応答（出力の前に断られたもの）は足さない（中身のないassistantの行は、最後の行でなければAPIが受け付けない）。APIが受け付けなかったリクエスト（`BadRequestError`）のあとは、会話を置いてメモから始め直す。例外は応答のなかった最後のsystemの行だけで、取り外して次の番にもう一度伝える（systemの行の後ろには応答が要る）
- `stop_reason`が`tool_use`なら道具を順に走らせて続け、`end_turn`で番を終える。`max_tokens`と`refusal`では応答の中の道具を走らせずに失敗として答えを付け、番を終える。1回の番のリクエストは16回まで
- 読めない応答（ストリームの途中で崩れた道具の入力）は2回まで頼み直す。APIのエラーは頼み直さない（SDKの再試行に任せる）
- モデルを変えたら会話を置く。思考のブロックはそのモデルとその会話にしか読めないため

### 区切り直し

文脈（`input_tokens + cache_creation_input_tokens + cache_read_input_tokens`と出力）が8万トークンを越えたら、番の終わりにAIにメモの書き直しを頼み（その間は`update_notes`だけを許す）、会話を置く。
次の番は、手引きと指示とメモのsystem、`get_room`の答えと最近のチャット30行のuserで、新しい会話を始める。どのモデルでも同じ方法で動く。区切り直しは番の終わりにしか見ないので、1回の番の中のリクエストが10万トークンを越えることはあり、Haiku 5.5のそのリクエストは高いほうの単価で数える。サーバー側の要約（compaction）は使わない。
ブリッジを起動し直したときも、同じく指示とメモから始め直す。

### 費用

`costOf`が`usage`と料金表（モデルごとに入力・5分と1時間のキャッシュの書き込み・読み出し・出力。2026-11-17に料金のページで確かめた値）から1回ずつ積む。Haiku 5.5はプロンプトの合計が10万トークンを越えたリクエストを高いほうの単価で数える。
上限額か、ブリッジの`--max-usd`に届いたら、次のリクエストの前に止める（`halted: 'budget'`）。タブの上限は始めるたびに0から数え、ブリッジの上限は起動している間ずっと数える。途中で読めなくなって頼み直した応答も、そこまでの`usage`（ストリームの`currentMessage`）を数える。表示は見積もりで、請求額はClaude Consoleが正しい。

### 止まるとき

| `halted` | とき                                                                         |
| -------- | ---------------------------------------------------------------------------- |
| `asked`  | **止める**。考えている途中のリクエスト（`signal`）と走っている道具を取り消す |
| `budget` | 上限額に届いた                                                               |
| `key`    | `AuthenticationError`・`PermissionDeniedError`                               |
| `failed` | 番の失敗が3回続いた                                                          |
| `seat`   | つないだ席がGMでなくなったか、AI連携の範囲が`read`になった                   |

断り（`refusal`）の代わりのモデルへの切り替え（SDKの`betaRefusalFallbackMiddleware`）は使わない。会話の途中でモデルが替わると、思考のブロックの扱いと費用の数え方が複雑になるため。

## タブの側

- 設定・指示・メモはlocalStorageの`axe.ai-gm`にだけ置き、同期も部屋の保存もしない。`readAiGmPreferences`は読めない値や欠けた欄を初めの値で読み、空の上限額を0と読まない
- 動いている間（`gm.status`の`run`が`off`でない間）、`AgentEventLog.waitFor`で起きたことを待ち続け、理由を付けて`gm.events`で送る。ログが止まっていてすぐ返るときは1秒待つ（マイクロタスクで回り続けないため）
- 送った位置（`cursor`）はブリッジに届いたときだけ進める。接続が切れても保ち、つながり直したら続きから送る。AI GMが止まったら手放す
- AIの席の人の行とAIの席あての秘話は、席の名前ではなく、行の`from`と`sendTo`の`userId`で見分ける（名前は重なりうる）。聞くタブはこの部屋にあるタブだけを数える
- 設定・指示・メモの変更は止まっている間も`gm.update`で送る。ブリッジは止まっている間もメモを保ち、つなぎ直したときに`gm.notes`で返すため
- AI連携が`gm`のブリッジにつながったとき、AI GMのパネルが開いていなければ開く（`AiLinkService.noteGmPanel`でパネルが開いていることを伝える）。`AiGmService`はパネルから作られるので、AI連携のパネルからつないでも起きたことが送られる
- 始めるとき、AI連携の範囲を`write`に借り（`AiLinkService.lendWrite`）、止まったら始める前の範囲に戻す（`takeBack`）。借りる前の範囲は`axe.ai-link`の`lentFrom`に覚えるので、ページを開き直しても戻せる。戻すのは、動いていたAI GMが止まったとき、ブリッジが開始を断ったとき、つなぎ直して止まっているのを知ったとき、GMを動かさないブリッジにつないだとき。開始の依頼のあとに届く`gm.status`は、`starts`が依頼の前より増えていれば依頼への答えで、増えていなければ範囲を知らせた返事なので、戻さない。借りている間に人がパネルで範囲を選んだら、その選択を残して戻さない。始めたときと止まったときは、システム通知の`room`で全員向けの行を出す（`feature.aiGm.notice.*`）。ページを開き直して動いている状態を受け取ったときは出さない
- ブリッジもGMの席で`write`のときだけ始め、知らないモデルを断る。`gm.update`が知らないモデルを指したときは、モデルだけ変えずに残りの変更を受ける（値段のないモデルは費用が0と数えられ、上限が効かなくなるため）。選んでいるモデルが`hello`の`models`にないことは、パネルが自分で見て出し（`AiGmService.modelNotRun`）、その間は開始を送らない。ページを開き直してもブリッジを起動し直しても出る。ブリッジが開始で知らないモデルを断るのは、それでも送ってきたタブへの備えで、断りは`problem`に出す。動いている間に席が変わってGMの席でなくなったら止める
- タブが切れて番を取り消したときは、その番の始めの行がもう会話に入っていれば、理由だけを戻して番をもう一度回す（イベントと一言は2度伝えない）

## テスト

- 番を回す規則・やりとりの読み取り・手引きは`core/agent`と`features/ai-gm`の単体テスト
- `GameMaster`は偽のAPI（`fake-api.ts`）で、リクエストの前半が前回と同じであること（キャッシュが読まれる形）、上限、取り消し、`stop_reason`ごとの扱い、区切り直しを確かめる。`GmHost`は本物の`TabLink`とテスト用のタブで、待ってから回すこと・止めること・タブが戻ったら回し直すことを確かめる
- e2eの`ai-gm.spec.ts`はMessages APIのSSEを返すローカルのサーバーに`ANTHROPIC_BASE_URL`でブリッジを向け、開始・一言・停止と、キーがブリッジからしかAPIに届かないことを確かめる。課金される本物のAPIは呼ばない
