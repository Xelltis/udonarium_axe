# 行動順・ターゲット・バフ

## 行動順

- **手番の回り方** — ラウンドの状態は部屋に1つの`TurnState`（`@SyncObject('TurnState')`）の`round`・`phase`（`idle` / `roundStart` / `acting` / `roundEnd`）・`currentIdentifier`・`actedIdentifiers`に持つ。押すたびに何をするかは`domain/tabletop/turn-machine`の純関数（`roundNext`・`roundAdvance`など）が決め、`application/turn/turn-order.service`の`TurnOrderService`が返った効果を順に実行する。手番は卓のインベントリと同じ並び（部屋の並べ替え）で回り、「手番をもたない」（`GameCharacter.noTurn`）とインベントリ非表示のコマには回らない。乗り物と後ろの乗り手は、前の乗り手の手番に一緒に動く（`domain/tabletop/turn-roster`の`buildTurnRoster`）。押せるのは見学以外の役割（`canTakeTurns`）。押すたびに前の状態と変わったバフを`TurnState.history`に積み（`domain/tabletop/turn-history`の`TURN_HISTORY_LIMIT`で60手まで）、「1つ前に戻す」と「ラウンドを戻す」はそこから戻す。告知は通知の種類「ラウンド・手番の進行」の行き先へ出し、パーティから見えないコマの手番は「見えない相手の行動です。」と名前を伏せる
- **行動順のツールバー表示** — GMツールバーとPLツールバーの「行動順」（`MENU_COMMANDS`の`turnIndicator`、`ui/turn/turn-indicator`）は、ラウンド数（`R1`）と、陣営ごとなら陣営、手番のコマの名前を出す。行動順を回していないあいだ（`phase`が`idle`）は出さない。読む人に見えないコマの手番では名前を出さず、陣営があれば陣営だけ、無ければ「見えない相手の手番」と出す。GMツールバーには「前へ」（1つ前に戻す）と「次へ」がある。PLツールバーでは、手番のコマが卓にいれば名前を押すとその場所へ画面を移し、自分のキャラクターの手番なら「次へ」で次へ渡せる。「次へ」の場所はほかの人の手番でも空けておき、手番が移ってもバーがずれないようにしてある
- **ラウンド送りは未行動を置き去りにしない** — 「ラウンドを進める」の`advanceRound()`は、`unactedCharacters()`が残っているあいだ`ConfirmService.ask()`で名前を並べて確認する（先頭8体（`UNACTED_NAMES_SHOWN`）＋残り数）。手番が回らないインベントリ非表示のコマは数えない。押し忘れと意図的なスキップは区別がつかないので、止めるのではなく判断を返す形にしてある。`advanceRound()`は`Promise<void>`を返すので、呼び出し側（`InventoryRoundService.advanceRound`）は`void`を付ける
- **陣営交互ラウンド** — `Config.turnOrderMode`が`faction`（「陣営ごと（フェイズ制）」）のとき、ラウンドは陣営のフェイズを順に開く（`domain/tabletop/turn-side`の純関数群）。陣営は`Party`をそのまま使い、無所属は番兵`@none`の1陣営にまとめる。`Config.factionSkipUnassigned`（「パーティに入っていないコマは行動しない」）をオンにすると、無所属の陣営を外す。順番は`Config.factionOrder`（CSV）だが**正規化は読むだけ**で、消えたPartyは落とし、未登録のPartyは`ObjectStore`に入った順で末尾に足す（同時作成の取りこぼしを書き戻しで固定しないため）。`TurnState.currentSide`も読むたび`roundSide()`（`turn-machine`）が`resolveCurrentSide()`で解決するので、進行中にPartyを消してもフェイズは固まらない。フェイズ内は`Config.factionPhaseMode`の`free`（開いても手番は渡らず、「この手番にする」で選んだ1体が取る）と`initiative`（開いた時点で先頭へ渡る）の違いだけで、**「次へ」はどちらもその陣営の未行動へ手番を渡し**、未行動がいなくなってから次の陣営を開く。1押しでフェイズを丸ごと閉じると、押し忘れた側の手番が気づかないうちに消えるため。`orderedCharacters()`は陣営順に並べ替えて返すので、並びをたどる側は陣営を知らなくてよい
- **一覧も陣営で区切る** — 陣営ごとに回すとき、`bandRowsBySide()`（`features/inventory/game-object-inventory/inventory-list`）がリッチ表示と簡略表示（表）の行を陣営順に束ねる。卓のタブ限定で、フォルダ表示・検索中は束ねない（それ自体がまとめ方なので二重になる）。どの陣営にも属さない行は末尾に見出し無しで置く
- **待機と割り込み** — ラウンド中、まだ動いていないコマは「待機させる」で後回しにでき、待機中のコマは「割り込む」で手番を取れる（`TurnOrderService.hold()` / `interrupt()`、可否は`turn-roster`の`mayHoldTurn` / `mayInterruptTurn`）。インベントリの右クリックと、行動順の帯の「手番のコマを待機させる（あとで割り込めます）」から使い、待機中のコマに手番を渡すと割り込みになる。待機中のコマは順番を飛ばされ、待機していないコマが動き終えてから並び順で手番を取る（陣営ごとなら全陣営のフェイズのあと）。割り込まれた手番は行動済みにならず、割り込んだコマの手番を閉じた次の押下で再開する。手番中に待機したコマは、戻ってきても手番開始の処理（`turnStart`のバフ・地面・`TurnHooksService`）を二度は走らせない。手番開始で減ったバフは待機させた時点で戻し、手番が戻ったときにもう一度減らす。これは見学以外の席がすべて`PeerCursor.turnProtocol`が`'1'`の版のときだけで、旧版の席が混じると戻さない（旧版は戻ったときに減らし直さず、バフが1ラウンド長く残るため）。待機の状態は`TurnState.holding`（`held`・`begun`・`interrupted`・`givenBack`のJSON）、手番開始で減らしたバフは`TurnState.turnOpening`に書く。空か読めない`holding`は、待機を知らない版の部屋も含めて誰も待機していないと読む（`readTurnHolding`）
- **チャットのコマンド** — 発言の先頭の語が`&T`・`&TE`・`&TW`・`&TI`・`&TB`・`&RS`・`&RN`・`&RB`・`&RR`か、同じ働きの日本語の語（`&手番`など）なら、行動順を操作する（`domain/tabletop/turn-chat-command`の`TURN_CHAT_COMMANDS`と`readTurnChatCommand`）。読むのは`&`と名前だけの語で、`/`で欄が続く語、`-`で終わる語、名前が先へ続く語（`&TEAM`）はバフのコマンドのまま読む。`resourceCommandSites`は先頭のコマンドの語をバフとして拾わない。実行するのは`application/turn/turn-chat-command.service`の`TurnChatCommandService.say()`で、コマンドの語を1行として送り、`TurnOrderService`のボタンと同じメソッド（`setCurrent`・`next`・`hold`・`interrupt`・`prev`・`advanceRound`・`retreatRound`・`reset`）を呼んでから、残りを別の行として送る。`&RS`は`phase`が`idle`か`roundEnd`のときの`next()`、`&TE`は`next()`そのもので、`&RN`は未行動の確認の答えを待ってから残りを送る。発言を送る経路（`features/chat/chat-send.service`、`CharacterMacroService`の`send` / `sendAsSelf`、ノベルモードの入力欄）がここを通るので、チャットウィンドウ・パレット・ホットバー・スイッチの行に同じに効く。受け取った行は処理しないので、P2Pでも二重に進まない。可否は`refusalOf()`が決める。使える席はボタンと同じで、どのコマンドも見学以外（`TurnOrderService.canTakeTurns`）の席が使う。GMかPLか、発言者や手番のコマが誰のものかでは分けない。行動順ウィジェットのボタンとコマの絵が`canEditTabletop`だけで分けているのに合わせてあり、自分のコマの手番にだけ出るPLツールバーの「次へ」には合わせない。ボタンが押せない状態（戻す記録がない、待機できない、待機していない、まだ始まっていない）では、コマンドも同じ`canUndo`・`mayHold`・`mayInterrupt`・`round`を読んで断る。`&T`は`turnOrderMode`が`faction`で`factionPhaseMode`が`free`、ラウンド中で、発言者のコマが行動順にいて待機も行動もしておらず、その陣営が`currentSide`のときだけ通す。断るときは`sendSystemMessageOnePlayer`で打った席にだけ`feature.turnOrder.commandRefused`を出し、理由の文は入力欄の指摘と同じ`feature.chat.lint.turn.no.*`を使う。入力欄では`scanChatSyntax`が`turn`のスパンを作って残りを別の発言として読み、指摘は`ChatLintContext.turnCommandRefusal`から同じ`refusalOf()`を引く
- **手番の効果音** — 手番が始まると、そのコマの持ち主の画面でシグナル、ほかの全員の画面でティックを鳴らす（`features/media/turn-sound`の`TurnSoundEventHandlerService`、音は`core/audio/turn-chime`の`TURN_SE_SIGNAL` / `TURN_SE_TICK`）。NPCと持ち主のいないコマの手番は、GMも含めて全員にティックを鳴らす。部屋設定の「戦闘」タブの「手番の効果音」で切り替え、シグナルは`Config.turnSignalEnabled`（`_turnSignal`が`'off'`以外なら真）、ティックは`Config.turnTickEnabled`（`_turnTick`が`'on'`のときだけ真）。通知音のチャンネルで鳴らすので、音量と消音は各自の通知の設定に従う。`TurnState.turnStart`（`識別子@ミリ秒`）から30秒（`JUST_BEGUN_MS`）を過ぎた手番では鳴らさない。部屋に入ったときや再接続したときも、手番を渡すときと同じ通知で今の手番が届くため。同じ手番では1回だけ鳴らし、セッションログの再生中と配信用の透過画面では鳴らさない
- **手番のコマへ画面を移す** — 手番が始まると、各自の画面を手番のコマへ寄せる（`features/tabletop/turn-focus`、`TableFocusService.focusOn`）。メニューの「手番のコマへ画面を移す」で、全員の手番・自分のキャラクターだけ・移さないを順に切り替え、選んだものはlocalStorageの`ui-turn-focus`（`all` / `own` / `none`、既定`all`）に置く（`application/ui/turn-focus-preference.service`）。部屋の決まりではなく見方なので、ブラウザごとに持つ。寄せるのは卓にいて、その人に見えるコマだけ（暗闇のコマへ寄せると居場所が分かるため）。コマを持っている・移動を計画している・エフェクトの対象を選んでいる・地面のブラシを使っている・ダンジョンドリィマスターモードや後ろから追う視点のあいだは動かさない。30秒の決まり、1手番1回、再生中と透過画面では動かないことは効果音と同じ。初めて寄せたときだけ、止め方を書いたお知らせを「移さない」のボタン付きで10秒出し、出したことを`ui-turn-focus-told`に書く

## ターゲットと目標値

- **ターゲット** — コマのターゲットは`GameCharacter.targeted`に持ち、同期しない。付くのは付けた人の画面だけ。付け外しは`application/tabletop/piece-target.service`の`PieceTargetService`を通す。`T`キーで選んだコマだけをターゲットにする操作は[卓とテーブル](tabletop.md#複数選択一括操作)にある。卓のコマが1体でもターゲットなら、画面下に「ターゲット N体」と「すべて外す」の帯を出す（`features/tabletop/target-band`。重ね順は`Z_TABLE_BANDS`でパネルより上）。「すべて外す」は選んでいる途中のエフェクトの対象も解く
- **ターゲットを自動で外す** — `features/tabletop/target-release`は、読む人に見えなくなった卓のコマ（暗闇・霧・ステルス・視点の移動）からターゲットを外す。GMはすべて見えるので外れず、PLの目で卓を見ているときはそのPLと同じに外れる。手番が移ると（同じコマの手番の始め直しとラウンドを閉じるときも）卓のターゲットを全部外す。付けたままにすると、次にターゲットに向けた行が意図しないコマに当たるため。部屋に入って最初に受け取った手番では外さない。インベントリにいるコマの印と、エフェクトの対象選びは触らない
- **ターゲットに向けた行** — 単独の語の`t:`を書いた行は、ターゲットにしたコマへ1体ずつ向けて送る（`2d+8 魔法行使 t:`は1体ごとに1回振る）。`t:`の語そのものは発言に残さない。結果の後ろには` [名前]`を付け、2体目からは発言者自身に効くコマンドを外す（`DiceBot.deleteMyselfResourceBuff`。外さないと発言者が対象の数だけ動かされるため）。`t:範囲`か`t:area`は全員に1回だけ振り、全員の名前を`、`でつないで括弧に入れる（`domain/chat/chat-palette`の`aimsAtOnce`、`domain/chat/character-macro`の`aimedAt`）。括弧には収まる名前しか残らないので、向けた相手は`ChatMessage.aimedTogether`に識別子のJSONの配列で持つ。1体ずつの結果は`ChatMessage.rolledAt`に相手の識別子を持ち、名前を隠したコマでも誰に振ったかが分かる。どちらも初期値を持たず、書かない版の行は空として読む。`t{名前}`ではターゲットの値を読む
- **{目標値}** — `{目標値}`は`domain/chat/target-number`の`findTargetNumberSource()`が、タブの新しい行から順に探して埋める。自分に向けた振りの結果と、タブに固定した結果（`ChatTab.pinnedTargetNumber`）のうち新しいほうを採る。どちらも無ければ、ほかの人が誰にも向けずに振った結果と、GMが書いた「目標値13」のうち新しいほうを採る。シークレットの行、表示されない行、ほかのコマに向けた結果は使わない。`{目標値}`を埋めて振った行（`ChatMessage.answersTargetNumber`が`'1'`）の結果は、抵抗のように自分の目標値に対して振ったものなので、次の目標値にしない。シートかパレットに「目標値」という項目があればそちらが先に答え、何も見つからなければ`{目標値}`のまま送る
- **GMが書いた目標値** — GMの行（`senderRole`がGM）と、GMが仕込んだスイッチの行（`ChatMessage.mastersWords`）は、ダイスを振らなくても`presentedTotalOf()`が数を読む。`目標値13`・`目標値：13`・`目標値は13`と全角の数字を読み、`目標値2倍`・`目標値10+2`・`目標値13〜15`は読まない。`目標値13→15`は15と読む。1行に違う数が2つあれば読まない
- **目標値の固定と選び直し** — 発言のメニューの「この結果を目標値にする」「この目標値を固定する」でタブの`{目標値}`を固定し、「目標値の固定を外す」で外す。固定は全員のタブに効くので、見学以外でそのタブに発言できる役割だけが使える（`mayPinTargetNumber`）。シークレットと秘話の行は固定できない。チャットの入力欄の「目標値」は、自動で見つけた数と出どころを出し、新しい結果8件（`application/chat/chat-lint.service`の`TARGET_NUMBER_CHOICES`）から選び直せる。選び直した結果は、その1回の送信にだけ使う

## バフと状態異常

- **バフの残ラウンドを減らす時機** — バフはそれぞれ減る時機を持つ（`domain/character/buff-timing`の`BUFF_TIMINGS`。既定の`roundEnd`のほか`turnStart`・`turnEnd`・`none`）。時機は属性`cs-buff-timing`、手番を数えるコマ（トリガーキャラクター）は`cs-buff-trigger`に書き、トリガーが空ならバフを付けたコマ本人の手番で減る。パネルは識別子を、チャットの`@名前`は名前を書くので、`isBuffDueAt()`はどちらでも照合する。`none`（「消えない」）は時間でも`&R-`でも減らない。いつ減らすかは`domain/tabletop/turn-machine`が`buffs`の効果として出し（ラウンドを閉じる`finishRound`で`roundEnd`、手番を渡すときに`turnStart`、手番を閉じるときに`turnEnd`）、`application/turn/turn-order.service`の`expireBuffs`が`BuffManager.expireAt()`で減らす。対象は卓とインベントリの全キャラクターで、墓場だけ外す（パレットから話すコマは卓の外でもバフを持つため）。尽きたものを消して失効をチャットへ通知する。進行操作をしたピアだけが実行するので、P2Pでも二重に減らない。戻す操作では減らさず、履歴に残した前のバフへ戻す。`TurnState.buffDecay`（既定ON・SyncVar）で部屋ごとに切り替え、行動順の帯と部屋設定の「戦闘」タブの「ラウンドが進むとバフの残りを減らす」から変える
- **数えるたびに動かす・切れても戻さない** — `&!`の量の後ろに`~n`を書くと、残ラウンドが減るたびにステータスをさらにn動かす（`5~-1`は5動かしてから1ずつ戻す。`BuffModifier.step`、属性`cs-buff-mod-step`）。演算子を`++` / `--`にすると、最初の量を減るたびにも動かす。ステータス名の前に`:`を付けると、バフが切れても動かした分を戻さない（`:HP/+/0~-3`は減るたびにHPを3削る毒になる）。戻さないバフは切れる回にも動かし、戻すバフは切れる回には動かさない。戻さないバフは動かした量を`cs-buff-mod-kept`、減るたびの量を`cs-buff-mod-kept-step`に書き、旧版が読む`cs-buff-mod-applied`は0にして`cs-buff-mod-step`は消す（`domain/character/buff-modifier`の`writeBuffModifier`）。旧版にはステータスを動かしていないバフに見えるので、外してもダメージを戻さず、減るたびに動かしもしない
- **相手の〜** — 効果欄の項目の先頭に`相手の`を付けると（`相手の物理特攻+2`）、そのコマ自身のステータスは動かさず、そのコマに向けた行で発言者の`{物理特攻}`に2を足す（`domain/character/aimed-at-buff`の`AIMED_AT_MARK`と`aimedAtBonusesOf`）。足すのは量で動かす項目だけで、値に留める項目と、最大値などリソースの一部を指す項目は足さない
- **効果が動く時機** — 減るたびに動かす量（`BuffModifier.step`）は、バフごとに動く時機を持てる（`domain/character/buff-timing`の`BUFF_EFFECT_TIMINGS`。`roundEnd`・`turnStart`・`turnEnd`）。属性`cs-buff-effect-timing`に書き、空・無し・知らない値は「持たない」と読む（`buffEffectTimingOf`）。持たないバフは残ラウンドが減るときに動き、`none`のバフはラウンド終了ごとに動く（残ラウンドは減らず、バフは残る）。持つバフはその時機にだけ動き、減るときには動かない。手番は`cs-buff-trigger`に関係なくバフを持つコマ本人の手番で、残ラウンドが尽きたバフは動かさない（`isBuffEffectDueAt`）。`BuffManager.expireAt()`がバフごとに「動かす→減らす」の順で処理するので、`turn-machine`が出す`buffs`の効果の位置と、実行するピアが1つであることは変わらない。手番開始で動いた分は`dueAt()`が`TurnState.turnOpening`に入れ、待機で戻す。`decreaseRound()`（`&R-`・リモコン）は、時機を持たないバフを`none`も含めて1回動かし、持つバフは数えるだけにする。戻さないバフが切れたときは、切れた時点の累計を`expireAt()`の`ranOut`に入れ、`noteRanOut()`が手の前との差を`lastMoved`に書くので、同じ手で動いて切れた分もまとめて戻る。チャットでは4つ目以降の欄に`発生:手番終了`（`tick:turnEnd`）と書き、`resourceCommandSites`はこの欄の`:`でリソース操作を切り出さない。読めない時期は付けずに`buff.badEffectTiming`、動かす量のないバフへの指定は`buff.idleEffectTiming`をリントが出す。付け直し（重ねがけ以外）で書かなければ外す。旧版は属性を無視し、減るときに動かす
- **バフの重ねがけ** — `&`の直後の`+`（`&+猛攻撃/攻撃+2/3`・`&+!`も可、リモコンはバフ名の前に`+`）で、同名バフを上書きせず積む。効果欄の足し算は`domain/character/buff-stack`の`stackBuffEffect()`（数値の前後の語が一致するときだけ足す。`攻撃+2`と`防御+1`は足さずに書き換え）、積む側は`BuffManager.stackRound()` / `stackModifier()`。`+` 2つ（`&++`）なら残ラウンドも足す（`extendRound()`。効果欄を空にすれば持続だけ延ばせる）。**`+` 1つの残ラウンドは長いほう勝ち**で、省略時は据え置き、消えないバフはどちらも消えないまま。`stackModifier()`は`applied`を足して持つので、外すと全部まとめて戻る（**上限で頭打ちになった分は足されない**）。`=`（値に留める）だけは二度留めても同じなので掛け直す。**既定は上書き**で、`+`を書いたときだけ積む（既存のパレットとマクロを動かさないため）。バフマネージャーの記法ビルダーにも**重ねがけ**と**ラウンドも足す**のチェックがあり、`=`を選んでいるあいだは`builderCanStack()`で欄ごと出さない
- **バフの量に計算式** — `&!`の量は`readBuffAmount`（`domain/character/buff-modifier`）が読む。素の数はそのまま、それ以外は`evalCalcFormula`に`{ division: 'floor' }`で渡し、割り算ごとに切り捨てる（`floor` / `ceil` / `round`の括弧の中だけは小数のまま計算して最後に丸める）。命令は半角の`/`で欄を分けるので、割り算は`÷`か全角の`／`で書く。全角の数字と記号、`×`も読む。0で割るなど有限でない結果は読めない扱い。計算フィールドは`evalCalcFormula`の既定（`exact`）で、小数のまま割る。状態異常の量と記法の組み立て欄も同じ関数を通り、組み立て欄は量の`/`を`÷`にして書き出す
- **卓全体から外す** — `&&none-`は消えないバフ、`&&2R-`は残り2ラウンドのバフ、`&&毒-`は「毒」という名前のバフを、卓にいる全キャラクターから外し、動かしたステータスを戻す（`domain/character/buff-bulk-removal`）。`none`の位置には「消えない」と読める語ならどれでも書け、全角の`＆`・`Ｒ`・`－`も読む。チャットから使えるのはGMだけで、ほかの人には「バフの一括解除はGMだけが使えます」と返す（`domain/data/resource-edit-processor`の`sweepBuffs`）。バフマネージャーの「バフの一括解除（GM）」は同じ規則で数を出し、確認してから外す。チャットからもバフマネージャーからも、どの条件の一括解除も`ResetRecorder`が控えるので、報告の行から元に戻せる
- **名前にかかわらず外す** — `BuffRemovalRule`（`domain/character/buff-bulk-removal`）は、条件で選ぶ`held`・`rounds`・`name`のほかに、コマのバフを名前にかかわらず外す`all`・`buffs`・`debuffs`を持つ（`isBuffClearance`）。チャットでは発言者のコマに`&*-`・`&*バフ-`（`&*buff-`）・`&*デバフ-`（`&*debuff-`）、ターゲットに`t&*-`、卓全体に`&&*-`と書く。`&*-`は`parseBuffClearanceCommand`が名前で外す読み方より先に読み、`&&*-`は`parseBuffRemovalCommand`がほかの条件より先に読む。`*`の後ろがどの語でもなければ、今までどおり名前で外す。まとめて外す決まりは6つとも、ふたり乗りで付いたバフを乗っているあいだ残し、件数にも入れない（`rowsKeptForRiding`。`rideTwoUpFrom`が空でないコマの、`rideTwoUpBuff`の行と、その行に`cs-buff-group`でぶら下がる行）。`removeBuffsWithParts`は本体と`partsAlong()`の部位から外し、`removeBuffsAcross`は渡したコマを1体ずつ扱う。本体と一緒にターゲットにした部位は`isClearedWithBody`で飛ばし、2回数えない。件数は先頭行で数え、報告にバフの名前は書かない。バフを隠したコマの中身が出るため
- **バフの区分** — バフの行は属性`cs-buff-kind`（`buff`か`debuff`）を持てる。属性がない行、空文字、知らない値は「印なし」と読む（`domain/character/buff-kind`の`buffKindMarkOf`）。バフかデバフかを決めるのは純関数`buffKindOf(data, ailments)`の1か所で、次の順に見る。印があればその区分。印がなく、名前が部屋の状態異常の一覧にあればデバフ。どちらでもなければバフ。色と、ステータスを動かす向きは読まない。`cs-buff-group`でぶら下がる行は、先頭行の印とバフの名前で決まる。行を読み終えたあとのバッジは、同じ順を`buffKindFrom(mark, name, ailments)`で見る（`BuffBadge.kindMark`）
- **区分を書く所** — 記法では、見た目の欄の`デバフ`・`debuff`・`バフ`・`buff`を`parseBuffKindWord`が読み、アイコンにしない（`parseBuffAppearance`）。ラウンドの欄に書いた語は、タイミングと同じく、ラウンドを省いた見た目の欄として読む（`splitBuffRounds`）。`BuffAppearance.kind`は`BuffManager`の`snapshot` / `restore`を通るので、行動順の「前へ」とリセットの取り消しで戻ったバフも区分を保つ。状態異常を付けると`plantStatusAilment`が`debuff`を書き、あとで一覧から消してもデバフのまま残る。手で選ぶ`markBuffKind`は、バフでもデバフでも先頭行に印を書く（バフ編集の行、バフマネージャーの詳細）。リモコンのバフ欄とバフマネージャーの組み立ては、選択欄を手で選んだときだけ印を書く（`buffKindMarkPicked`）。デバフを選べば`debuff`、バフを選べば、名前が一覧にあるときに限って`buff`を書く。選ぶまでの選択欄は、名前から決まる区分を表示し、印は書かない。印のないバフが一覧の名前ならデバフと読まれるのを変えないため。バッジは、デバフのとき丸の中の右下に`▼`を出す（`features/character/buff-badge`）
- **状態異常のカタログ** — 部屋の状態異常の一覧は`StatusAilmentCatalog`（`@SyncObject('status-ailment-catalog')`、識別子は`StatusAilmentCatalog`に固定）の本文に1行1件で書く。属性に置くと、XMLを読み戻すときに改行が空白に畳まれて全件が1行になるため。1行は名前のあとに`color:`・`icon:`・`rounds:`・`timing:`・`stat:`・`op:`・`amount:`・`effect:`を並べ（空白を含んでよい`effect:`は最後）、知らない語は読み飛ばす（ほかの版が書いた行も、その欄だけを失って残りは読める）。起動時にカタログが空なら12件（毒・出血・燃焼・麻痺・睡眠・石化・混乱・魅了・恐怖・暗闇・沈黙・鈍足）を入れ、空でなければ触らない（`domain/character/builtin-status-ailments`の`createDefaultStatusAilments`）。捨てて自分で書いた部屋に配り直さないため。コマに付けた状態異常は普通のバフになり（`plantStatusAilment`）、チャットのバフコマンドで状態異常の名前を書いても、書いた欄で上書きした状態異常として付く。ステータスを動かす欄は[マップエディターとスイッチ](map-editor.md#機能塗りマップエディター)の「状態異常がシートを動かす」にある
