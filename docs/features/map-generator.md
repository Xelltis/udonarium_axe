# マップ生成

## マップ生成

- **ボタン1つで組み立てる** — ダンジョンかフィールドかを選ぶ。壁や木立は地形（terrain）として、地面は1枚の絵として、新しいテーブルへ置く。地形はそのまま視線と光を遮るので、置いた時点から視界システムに反映される
- **シード** — 同じシードなら同じ形が出る。振り直しはパネルのサイコロボタンから
- **生成前のプレビュー** — 置かれるものをSVGで描き、地形の個数と同期データ量を出す。地形が350個（`MAP_HEAVY_TERRAINS`）を超えると警告し、700個（`MAP_MAX_TERRAINS`）を超えると生成を止める（`domain/tabletop/map-blocks`）
- **卓は自動で切り替わらない** — セッション中に用意してもプレイヤーが飛ばされない。移動はパネルのボタンから。振り直すと前回の卓を破棄する。生成したもの（地形・扉・明かり・地面の絵）は卓と一緒に消える

### ダンジョン

- **雰囲気プリセット** — 石造迷宮 / 地下墓所 / 遺跡 / 洞窟 / 溶岩洞 / 氷窟 / 砂の墳墓 / 違法BAR / 廃ビル / コンテナ倉庫。生成アルゴリズムと既定素材に加えて、暗闇の深さ・環境光・グリッド表示までプリセットが決める。違法BAR・廃ビル・コンテナ倉庫は部屋に家具を置き、部屋の役割を店や建物の呼び名で呼ぶ（違法BARの最奥は「元締めの部屋」）。違法BARは入口の間から出る扉をすべて壁に見せかける（`hideDoorsOf`）。定義は`DUNGEON_ATMOSPHERES`（`domain/tabletop/dungeon/dungeon-atmosphere`）
- **部屋数** — 3〜20で指定し、盤面の広さはそこから決まる（石造迷宮の8部屋は、既定の通路幅1で35×27マス。3部屋で27×19、20部屋で49×37）。部屋と迷路で組む雰囲気では、通路の幅（1〜4マス）を1マス広げるごとに盤の一辺を元の半分ずつ伸ばす。洞窟系は同じ部屋数でも盤を0.85倍にする。どの雰囲気でも盤は横50マス・縦38マス（`MAX_BOARD_WIDTH` / `MAX_BOARD_HEIGHT`）を超えない（`boardSizeFor`、`domain/tabletop/dungeon/dungeon-generator`）。洞窟系は空洞どうしがつながるため、要求より少ない数に落ち着くことがある
- **壁の高さ** — 0.5〜6マスで指定する。雰囲気の既定（石造2 / 洞窟3 / 遺跡1.5など）に追随し、手で動かすとそこで固定される。扉も同じ高さで立つ
- **入口** — 階段（地下へ降りる）か坑道口（外へ通じる）を選ぶ。坑道口は外壁を1か所だけ破って通路網につなぐもので、トンネルの入口や山肌の洞窟にあたる。地下2階から先は階段、1階や洞窟は坑道口、という使い分けを想定している。雰囲気ごとに既定がある（石造迷宮・地下墓所・砂の墳墓・違法BAR・廃ビルは階段、遺跡・洞窟系・コンテナ倉庫は坑道口）
- **扉** — 通路を塞ぐ薄い板として置く（1マスを埋めるのではなく、通路の向きに合わせて厚み1/4マスの板を中央に立てる）。視線は遮る。最奥の部屋は壁の開口をすべて閉じて施錠し、鍵は最奥を通らずに歩いて行ける部屋へ置く。1か所でも開いていれば回り込まれて鍵の意味がなくなるため、扉の枚数ではなく壁の穴を数えて閉じる（洞窟系は扉を持たないので施錠もしない）
- **部屋の役割** — 入口の間 / 大広間 / 宝物庫 / 最奥 / 行き止まり / 小部屋。入口からの床の上の距離で深さを測って割り当てる（迷路は全部屋を互いにつなぐので、部屋どうしのホップ数では深さが測れない）
- **扉の幅と両開き** — 最小と最大を1〜4マスで決める。2マス以上にすると扉が入るぶんだけ入口の壁を削り、通路のほうが狭ければ手前も1マス掘って敷居にする。両開きの割合を上げると、偶数の幅から選ばれた扉が半分ずつの2枚になる（幅4なら2マスが2枚）。扉1枚が地形1個なので、広げるほど地形の個数は増える
- **壁を登れなくする** — 入れると、できあがる壁と扉が[登れない地形](tabletop.md#テーブル表示2d--3d)になる（既定は切）。階段は登るためのものなので対象外。扉は開けば通る（`DungeonBlockOptions.sheerWalls`）
- **通路の作り方** — 部屋を置いたあと、残った岩を迷路で埋め、「ちょうど2つの領域に接する壁セル」＝コネクタを全域木で1つずつ開いてつなぐ。少数のコネクタを余分に開いて環を作り、最後にどこへも通じない行き止まりを刈り取る（[Bob NystromのRooms and Mazes](https://journal.stuffwithstuff.com/2014/12/21/rooms-and-mazes/)方式）。迷路は既に開いている場所から2マス離れた岩にしか掘り進めないため、**通路が部屋の壁に密着することが原理的に起きない**。扉もコネクタの定義そのものなので、開口の判定を別に持たなくてよい
- **部屋の形** — 矩形・円・十字・重なり矩形。雰囲気ごとに使う形を選ぶ（石造は矩形と重なり、地下墓所は矩形と十字、遺跡は円も）。矩形だけの間取りは定規で引いたように見えるため
- **罠を仕掛ける** — 生成リクエストの`trapCount`（既定0）。`placeTraps()`（`domain/tabletop/dungeon/trap-placing`）が床セルから重複なく引き、入口の間・階段・家具の上を避け、3マス以内に2つ置かない。種類は`TRAP_PRESETS`（`domain/tabletop/trap-presets`、`pit` / `dart` / `blade` / `alarm` / `rune`）で、部屋と通路で引く表を分ける。**家具の後に引く**ので、罠を頼まない部屋は同じ種から寸分同じに出る。`DungeonBuildService.setTraps()`が`TableTrigger`として置き、`open`は偽のまま（見える罠は罠ではない）
- **危険地帯が実際に危ない** — `MapPaint.hazard`（`HazardKind`）を溶岩洞の`cave.hazardKind`とフィールドの`FieldPoolPlan.hazard`から載せ、`DungeonBuildService.layHazards()`が`TableMoveCost`と`TableTrigger`を置く。見た目は`blocks.ambiences`側に寄せた（`layoutToBlocks()`がhazard矩形ごとに`TableAmbience`の種を積む）ので、**アンビエンスを二重に置く経路が無い**
- **GM用の概要** — 部屋番号・寸法・接続・施錠・鍵の在り処・松明の位置を、生成パネルの中に一覧で出す（コピーできる）。共有メモは卓の子ではなく全卓に残ってしまうため、盤の上には置かない

### フィールド

- **雰囲気プリセット** — 森林 / 草原 / 海岸 / 湿地 / 雪原 / 荒野 / ビル群 / ビル群(SF) / スラム街 / ゴミ処理場 / 農村 / 蛮族の砦 / 石造りの砦。地面の帯・生えるもの・天候・明るさをプリセットが決める（湿地は霧と薄暗がり、雪原は吹雪、荒野は砂塵）。ビル群からゴミ処理場までの4つは[市街](#市街)、農村と2つの砦は[村と砦](#村と砦)の決まりで地面と建物を置く。この節の地面の帯・海岸の傾斜・水の帯・地面の起伏は、森林から荒野までの開けた土地の6つに当てる（`FIELD_ATMOSPHERES`、`domain/tabletop/field/field-atmosphere`）
- **地面の帯** — 価値ノイズを3オクターブ重ね、別のノイズで読む位置をずらして（ドメインワープ、`warpedFbm`、ずらし幅`WARP`＝0.6）高さを作る。4オクターブ目は1マスより細かい模様になるので3つで止める。ずらさずに読むと、等高線のような同心の丸が並ぶ。この高さに水の溜まりやすさのノイズ（`damp`）を混ぜ、低い順に帯へ割り当てる（森林なら泥濘・草原・黒土）。帯の境は高さの値ではなく盤面の高さの順位で切るので、どの盤面でも各帯がプリセットの頼んだ割合（`upTo`）を占める（`domain/tabletop/field/field-layout`、`field-noise`）
- **海岸の傾斜** — 高さに盤面全体の傾き（`gradient`、海岸0.6・湿地0.15）を混ぜると、水が片側へ寄って渚になる。ノイズだけでは水が真ん中に池として溜まる。傾ける向きは四方からシードが選ぶ
- **水の帯** — 海岸・湿地・雪原は、いちばん低い帯（海岸は2つ）に水を張る。海岸は海と浅瀬（濁り0.2と0.15）、湿地は泥濘の上の濁った水（濁り0.8・汚れ0.6・落ち葉0.25）、雪原は凍った水（氷1）。水の帯には何も生やさない（`bare`）。水は帯ごとに`TableAmbience`の水域として置き、水面は盤の高さ、濃さは0.6（`FIELD_WATER_DENSITY`）。四角では帯を最小個数の矩形で覆い、ヘクスでは1列ずつの連なりにする（`areasOver`、`domain/tabletop/field/water-areas`）。水と氷の描き方と、氷の上に立つ決まりは[水域と地面](water-ground.md)にある
- **地面の起伏** — パネルの「地面の起伏（マス）」は0〜6マスを0.5刻みで選び、既定は2（`DEFAULT_FIELD_RELIEF`）。0なら平らなまま。開けた土地だけを、帯を切ったのと同じ高さに沿って盛り、いちばん低い所を盤の高さ、いちばん高い所を指定の高さにする。市街は盛らない。村・砦は、敷地（道・庭・床・畑・水田、柵と壁と扉、建物、作物、物、火のマス）とその外側1マスを、敷地の中心（砦は壁が囲む中心、村は敷地の重心）での野の高さにならし（0未満にはしない）、外へ2マスの帯で野の高さへ線形につないでから、その先を野と同じ式で盛る（`terraceSettlement`、`domain/tabletop/field/settlement-terrace`）。建物・壁・柵・作物が段差に掛からないための台地で、起伏0なら平らなまま。水の帯がある盤では岸から水の下を掘り下げ（深さは帯の`depth`で、海岸1.5・湿地0.4・雪原0.5マス。盛った高さを超えない）、水面を盤の高さに保つ。水のそばの陸は水面より0.1マス（`SHORE_RISE_CELLS`）高く始め、岸を線にする。盛った盤には段で組む「丘」を置かない（`reliefOf`）。地面を盛る仕組みは[水域と地面](water-ground.md)にある
- **植生の濃淡** — 生える確率をもう1枚のノイズで揺らす。森は濃いところと薄いところを持ち、一様に撒いたようにはならない
- **塞がらない** — 茂みは上下左右のうち2つ以上が埋まっているマスには置かない（`CROWD_LIMIT`）。木・岩・岩場などは1つずつの物として置き、同じ種類どうしを種類ごとの間隔（`spacing`。木は3マス、巨木は14マス）より近づけない。木立が壁になって歩けない盤面になるのを防ぐ
- **置かれるもの** — 木は幹と、地面から1.5マス浮いた3段の樹冠でできる（幹は幅0.38・高さ1.9、樹冠は下から広がり4.8・3.2・1.6マス）。木ごとに0〜0.6マス持ち上げて高さをばらつかせる。樹冠は広がりが1マスを超える段だけが視線を遮る。茂みは高さ0.45、岩は3段で高さ0.84、岩場は3マス四方・高さ2.4で視線を遮る。巨木は幅1マス・高さ2.6の幹に広がり6.6マスの樹冠を載せ、下に何も生やさない。荒野にはサボテン、ゴミ処理場には廃材の山、スラム街には街路樹が立つ。茂みだけはマスごとに置き、同じものが隣り合えば4マス（`FIELD_MERGE_SPAN`）までひとかたまりにまとめる。ほかは段ごとに回転・つぶれ・ずれを変えた物として1つずつ置く。水面には何も置かない（`FIELD_PROP_SHAPES`、`domain/tabletop/field/field-blocks`）
- **3Dモデルで置く** — 「木・岩・サボテン・廃材を3Dモデルで置く（3Dの卓で見えます）」（既定は入）では、木・茂み・岩・岩場・巨木・サボテン・廃材の山・街路樹を同梱のモデルで描く。モデルは場所から決め、6マス四方の木立は同じ種類にそろえ、4本に1本は別の種類にする（`fieldModelAt`、`domain/tabletop/field/field-models`）。草原・湿地・雪原は森林と別の木を生やす（湿地はヤナギやマングローブ、雪原は雪のモミ・トウヒや冬枯れの木）。「季節」は春に桜を混ぜ、秋に広葉樹を紅葉させてカエデとイチョウを混ぜ、冬に広葉樹を冬枯れに、針葉樹を雪のものに替える。モデルで描く物は、描いたモデルと同じ幅と高さの地形1つになる（[3Dモデル](models.md#同梱のモデル)）
- **広さと茂みの多さ** — 20〜60マス（縦は横の3/4、最低12マス）と0〜100%。開けた土地では多さ0なら地面だけの更地が出る。市街と村・砦では建物や畑の詰まり具合になる
- **素材** — 地面のピッカーはプリセットの主となる帯（森林なら草原）を差し替える。障害物のピッカーは壁の素材を着ている物（木の幹や建物の壁など）の側面を差し替える。樹冠や岩のように地面の素材を着ている物と、サボテンやコンテナのように素材の決まっている物（`PROP_OWN_WALL_TEXTURE_IDS`）はそのまま。障害物の素材を選ぶまでは、どの物もプリセットの素材を着る。残りの帯はプリセットのまま（`features/dungeon-generator/field-materials`）
- **概要** — 地面の帯ごとの割合（多い順）・立っているものの種類ごとの数（市街は建物の棟数も）・灯りの位置をパネルに出す（`buildFieldSummary`、`domain/tabletop/field/field-summary`）

### 市街

- **通りと敷地** — ビル群・ビル群(SF)・スラム街・ゴミ処理場は、地面の高さではなく通りの割り付けで地面を塗る。盤を横切る通りを1つの格子で切り、通りの間の街区を歩道で囲み、街区を敷地に分けて、空けておく敷地（`vacancy`）のほかに建物を1つずつ建てる。盤の端は街区の途中から始め、盤の外にも町が続いて見えるようにする。割り付けは`layTown()`（`domain/tabletop/field/town-layout`）、プリセットごとの決まりは`TownPlan`
- **4つの市街** — ビル群は高さ2.5〜7マスのビルを盤の中央ほど高く建て、4.5マスを超えるビルは、敷地が4マス四方以上なら1〜2マスの基壇の上に、敷地の縁から1マス引っ込めて立てる。歩道に街灯を立てる。ビル群(SF)は3.5〜8マスで、雨の夜にシアンとマゼンタの光の柱を歩道に立てる。スラム街は街区を奥行き3マスの長屋で縁取って中を裏庭に残し、2.5〜4マスの建物の屋上に木の水槽を載せることがあり、歩道に街路樹を植える。ゴミ処理場は高さ1〜1.8マスのトタン小屋を少し傾けて建て、街区の列ごとに通りの位置をずらし、雨の中で通りの低い所（22%）を泥濘の水たまりにする
- **建物の描き方** — 建物は敷地ごとに1つの地形（基壇のあるビルは2つ）で、屋上設備を載せることがある。3Dモデルで置くときは、壁の素材ごとの部品一式（`TOWN_KITS`、`domain/tabletop/field/town-models`）を箱いっぱいに繰り返して描く（[glbのextras](models.md#コマと地形のモデル)の`facade`）。ヘクスでは建物を1マスに1つの地形で組み、建物にはモデルを使わない

### 村と砦

- **割り付け** — 農村・蛮族の砦・石造りの砦は、`laySettlement()`（`domain/tabletop/field/settlement-layout`）が割り付け、同じシードなら同じ形になる。マスごとの地面は`SETTLEMENT_ZONES`の6区分（開けた地面・道・庭・建物の床・耕した土・水田）で、雰囲気の地面の帯をこの順に塗る。「茂みの多さ」は家・畑・物の詰まり具合（0〜100、既定50）として読む。建物は外壁の内側を仕切り壁で3マス以上の部屋に分け、仕切りごとに扉を1枚、外へ出る扉を1枚付ける
- **農村** — 盤を横切って少しずつ曲がる幅2マスの道に沿って、木の壁の家を3〜5軒（多さで増減し、最低2軒）並べる。家は扉を道へ向け、家の前にランタンを置く。半分ほどの家は板壁の納屋と干し草を持つ。空いた所に5〜8枚（多さで増減）の畑を作り、野菜・麦・とうもろこしの畑は柵で囲んで一辺に2マスの出入り口を空け、稲は柵のない水田にする。道ばたに井戸、荷車と干し草も置く
- **蛮族の砦** — 盤の中央を楕円の丸太の柵で囲み、南に両開きの門を付け、柵の上に見張り塔を立てる（塔のそばに火鉢）。内側には2部屋の族長の館（炉つき）と、大きな焚き火を囲む天幕（入口は扉のない開口）、トーテムを置き、門から盤の端へ小道を通す
- **石造りの砦** — 盤の中央を四角い石垣で囲み、四隅と南の門の両脇に塔を立て、門には上へ開く鉄格子を吊る。石畳の中庭の奥に3〜5部屋の天守、壁沿いに兵舎と厩舎を建て、井戸を置き、門から盤の端へ道を通す
- **壁と扉** — 壁は9種（`SETTLEMENT_WALL_KINDS`）で、高さは種類ごとに決まる（丸太の柵2.5・見張り塔4・石垣3.5・塔5・木の壁2・石の部屋の壁3・柵0.6・納屋の板壁2.5・天幕2マス）。扉と門は、かかる壁と同じ高さで立つ。柵だけは視線を通し、登って越えられる（`LOW_WALLS`）。ほかの壁は視線を遮り、登れない（`domain/tabletop/field/settlement-blocks`）
- **畑** — 麦・とうもろこし・稲の畑は通りにくく（`SLOWING_CROPS`）、余分な移動コスト1を`TableMoveCost`として置く。野菜の畑は普通に歩ける。水田には浅い水（水面0.08マス、濁り0.8）を張る。3Dモデルで置くときは、作物を厚さ0.02マスの床の地形の上に描くので、畑に入ったコマは地面に立ち、作物は視線を遮らない
- **3Dモデル** — 3Dモデルで置くときは、丸太の柵と石垣を外向きにそろえたタイルで、家・部屋・納屋・天幕の壁と柵を[つながる壁](#つながる壁)で、塔と見張り塔を1つずつのモデルで描く。ヘクスでは塔と見張り塔をブロックで組む

### つながる壁

- **隣の壁へ腕を伸ばす** — glbのextrasの`fit`が`joined`のモデル（[3Dモデル](models.md#コマと地形のモデル)）で描く地形は、`wallJoinsOf()`（`domain/tabletop/world/wall-joins`）がつなぎ方を決める。地形が立つマスごとに中心へ`hub`の部品を立て、同じモデルの地形か扉が隣にある辺へ、中心からその辺まで腕の部品を伸ばす。これで直線の壁は1本につながり、角・T字・十字も組み上がり、扉の脇では壁が扉まで伸びる。四角では4方向、ヘクスでは6方向の辺を見る。どこにも腕を伸ばさない地形は、つなぎ方を持たずにモデルどおりに描く
- **どの壁がつながるか** — つなぐかどうかはモデルのファイルが決める。`ModelFitService`（`application/tabletop/model-fit.service`）が手元のモデルのJSONだけを1度読んで`fit`を覚え、`Table3dService`がつながる壁の地形と、霧に隠れていない扉を集めて`wallJoinsOf()`に渡す。同梱のモデルでは石の部屋の壁・丸太の壁・木骨の壁・柵・板壁・天幕の壁がこれにあたる。マップエディターの[3Dオブジェクト塗り](map-editor.md#機能塗りマップエディター)で1マスに1つずつ置いた壁も、生成した壁と同じようにつながる

### 共通のしくみ

- **床はマップエディタの塗り** — 床は地形ではなく、マップエディタと同じセルレイヤーとして塗り、1枚の画像に焼いてテーブルの表面に貼る。床は何も支えず、視線も光も通すので、地形にする理由がない。地形にすると床1枚あたり12個の同期オブジェクトを使い、地下墓所20部屋では塗りの204個に対して323個になる。焼いた画像は誰の子でもないので、卓を捨てるときに画像保管庫からも消す
- **明かり** — 暗闇のプリセットでは光源オブジェクトを卓の子として立てる。絵柄はキャラコマと同じ立ち方で、マスの中央に立つ。狭い部屋には壁掛け松明かランタン（壁の高さより1マス低いところまで上げて、壁に掛かって見える）、広い部屋には焚き火・火鉢・ランプスタンド。フィールドでは焚き火を離して置く。壁ブロックそのものを光らせるとその地形が光を遮らなくなり、最大12マス四方の穴が開くため、明かりは必ず独立したオブジェクトにする
- **矩形マージ** — 隣り合うセルをまとめて1つの地形にする。ダンジョンを1マス1地形で置くと、まとめたときの約14倍の地形になり、同期するオブジェクトも視線計算が横切る辺も同じだけ増える（`mergeMaskToRects`、`domain/tabletop/dungeon/rect-merge`）。まとめる一辺は、ダンジョンで12マス（`MAX_MERGE_SPAN`）、フィールドで4マス（`FIELD_MERGE_SPAN`）まで。上限は700個（350個で警告）
- **マスの形** — 四角とヘクス（縦・横）を選べる。ヘクスの卓の地形は`min(width, depth)`マス幅の花形に描くので、5マスをまとめた地形は1マス分しか描かれない。そのためヘクスではまとめず、1セル1ブロックにする（`mergeSpanFor`、`domain/tabletop/map-grid`）。同じ盤面では上限を大きく超えるため、ヘクスでは一辺を0.75倍にする（`HEX_BOARD_FACTOR`、面積で約44%減）。全雰囲気 × 部屋数3/8/20 × シード4種 × ヘクスの縦横で上限700に収まることを`dungeon-generator.spec`が確かめている。レイアウトが掘る隣接は東西南北の4方向で、これはオフセット格子ではヘクスの6隣接に含まれるため、四角で歩けた道はヘクスでも歩ける。テーブルはヘクス盤と同じ列数・行数で作る（`tableSizeFor`）。卓もヘクスを列で数えるので、盤の実寸をマスの大きさで割り戻すと列が足りなくなる
- **未探索の覆いは置かない** — 盤面いっぱいのマスクは下の地形へのクリックをすべて奪ってしまうため。隠したい場合は卓のメニューから手でマップマスクを置く
