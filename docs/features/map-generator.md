# マップ生成

## マップ生成

- **ボタン1つで組み立てる** — ダンジョンかフィールドかを選ぶ。壁や木立は地形（terrain）として、地面は1枚の絵として、新しいテーブルへ置く。地形はそのまま視線と光を遮るので、置いた時点から視界システムに反映される
- **シード** — 同じシードなら同じ形が出る。振り直しはパネルのサイコロボタンから
- **生成前のプレビュー** — 置かれるものをSVGで描き、地形の個数と同期データ量を出す。地形が350個（`MAP_HEAVY_TERRAINS`）を超えると警告し、700個（`MAP_MAX_TERRAINS`）を超えると生成を止める（`domain/tabletop/map-blocks`）
- **卓は自動で切り替わらない** — セッション中に用意してもプレイヤーが飛ばされない。移動はパネルのボタンから。振り直すと、新しい卓ができてから前回の卓を破棄する。全員が前回の卓を見ていたときだけ、新しい卓へ移す。生成したもの（地形・扉・明かり）は卓と一緒に消える。破棄は手で卓を消すときと同じ`GameTableService.remove`を通る（部屋にもう無い卓と最後の1枚は消さない）。地面の絵は、部屋のどの物も使っていないときだけ消す（同じシードで作り直した卓は同じ絵を使う。`MapGenerationService.discard`・`replace`）

### ダンジョン

- **雰囲気プリセット** — 石造迷宮 / 地下墓所 / 遺跡 / 洞窟 / 溶岩洞 / 氷窟 / 砂の墳墓 / 違法BAR / 廃ビル / コンテナ倉庫 / 下水道 / 魔術師の塔。生成アルゴリズムと既定素材に加えて、暗闇の深さ・環境光・グリッド表示までプリセットが決める。違法BAR・廃ビル・コンテナ倉庫・下水道・魔術師の塔は部屋に家具を置き（[家具](#家具)）、部屋の役割を店や建物の呼び名で呼ぶ（違法BARの最奥は「元締めの部屋」）。違法BARは入口の間から出る扉をすべて壁に見せかける（`hideDoorsOf`）。下水道は通路と部屋に水を流す（[下水道](#下水道)）。魔術師の塔は円い階を掘る（[魔術師の塔](#魔術師の塔)）。定義は`DUNGEON_ATMOSPHERES`（`domain/tabletop/dungeon/dungeon-atmosphere`）
- **部屋数** — 3〜20で指定し、盤面の広さはそこから決まる（石造迷宮の8部屋は、既定の通路幅1で35×27マス。3部屋で27×19、20部屋で49×37）。部屋と迷路で組む雰囲気では、通路の幅（1〜4マス）を1マス広げるごとに盤の一辺を元の半分ずつ伸ばす。洞窟系は同じ部屋数でも盤を0.85倍にする。どの雰囲気でも盤は横50マス・縦38マス（`MAX_BOARD_WIDTH` / `MAX_BOARD_HEIGHT`）を超えない（`boardSizeFor`、`domain/tabletop/dungeon/dungeon-generator`）。洞窟系は空洞どうしがつながるため、要求より少ない数に落ち着くことがある
- **壁の高さ** — 0.5〜6マスで指定する。雰囲気の既定（石造2 / 洞窟3 / 遺跡1.5など）に追随し、手で動かすとそこで固定される。扉も同じ高さで立つ
- **入口** — 階段（地下へ降りる）か坑道口（外へ通じる）を選ぶ。坑道口は外壁を1か所だけ破って通路網につなぐもので、トンネルの入口や山肌の洞窟にあたる。地下2階から先は階段、1階や洞窟は坑道口、という使い分けを想定している。雰囲気ごとに既定がある（石造迷宮・地下墓所・砂の墳墓・違法BAR・廃ビル・下水道は階段、遺跡・洞窟系・コンテナ倉庫は坑道口）。上り下りの絵は雰囲気が選べ、下水道は上りをはしごの絵にする（`DungeonAtmosphere.stairs`）
- **扉** — 通路を塞ぐ薄い板として置く（1マスを埋めるのではなく、通路の向きに合わせて厚み1/4マスの板を中央に立てる）。視線は遮る。最奥の部屋は壁の開口をすべて閉じて施錠し、鍵は最奥を通らずに歩いて行ける部屋へ置く。1か所でも開いていれば回り込まれて鍵の意味がなくなるため、扉の枚数ではなく壁の穴を数えて閉じる（洞窟系は扉を持たないので施錠もしない）
- **部屋の役割** — 入口の間 / 大広間 / 宝物庫 / 最奥 / 行き止まり / 小部屋。入口からの床の上の距離で深さを測って割り当てる（迷路は全部屋を互いにつなぐので、部屋どうしのホップ数では深さが測れない）
- **扉の幅と両開き** — 最小と最大を1〜4マスで決める。2マス以上にすると扉が入るぶんだけ入口の壁を削り、通路のほうが狭ければ手前も1マス掘って敷居にする。両開きの割合を上げると、偶数の幅から選ばれた扉が半分ずつの2枚になる（幅4なら2マスが2枚）。扉1枚が地形1個なので、広げるほど地形の個数は増える
- **壁を登れなくする** — 入れると、できあがる壁と扉が[登れない地形](tabletop.md#テーブル表示2d--3d)になる（既定は切）。階段は登るためのものなので対象外。扉は開けば通る（`DungeonBlockOptions.sheerWalls`）
- **通路の作り方** — 部屋を置いたあと、残った岩を迷路で埋め、「ちょうど2つの領域に接する壁セル」＝コネクタを全域木で1つずつ開いてつなぐ。少数のコネクタを余分に開いて環を作り、最後にどこへも通じない行き止まりを刈り取る（[Bob NystromのRooms and Mazes](https://journal.stuffwithstuff.com/2014/12/21/rooms-and-mazes/)方式）。迷路は既に開いている場所から2マス離れた岩にしか掘り進めないため、**通路が部屋の壁に密着することが原理的に起きない**。扉もコネクタの定義そのものなので、開口の判定を別に持たなくてよい
- **部屋の形** — 矩形・円・十字・重なり矩形。雰囲気ごとに使う形を選ぶ（石造は矩形と重なり、地下墓所は矩形と十字、遺跡は円も）。矩形だけの間取りは定規で引いたように見えるため
- **罠を仕掛ける** — 生成リクエストの`trapCount`（既定0）。`placeTraps()`（`domain/tabletop/dungeon/trap-placing`）が床セルから重複なく引き、入口の間・階段・家具の上を避け、3マス以内に2つ置かない。種類は`TRAP_PRESETS`（`domain/tabletop/trap-presets`、`pit` / `dart` / `blade` / `alarm` / `rune`）で、部屋と通路で引く表を分ける。**家具の後に引く**ので、罠を頼まない部屋は同じ種から寸分同じに出る。`DungeonBuildService.setTraps()`が`TableTrigger`として置き、`open`は偽のまま（見える罠は罠ではない）
- **危険地帯が実際に危ない** — `MapPaint.hazard`（`HazardKind`）を溶岩洞の`cave.hazardKind`とフィールドの`FieldPoolPlan.hazard`から載せ、`DungeonBuildService.layHazards()`が`TableMoveCost`と`TableTrigger`を置く。見た目は`blocks.ambiences`側に寄せた（`layoutToBlocks()`がhazard矩形ごとに`TableAmbience`の種を積む）ので、**アンビエンスを二重に置く経路が無い**
- **GM用の概要** — 部屋番号・寸法・接続・施錠・鍵の在り処・松明の位置を、生成パネルの中に一覧で出す（コピーできる）。共有メモは卓の子ではなく全卓に残ってしまうため、盤の上には置かない

### 下水道

- **水路** — 通路のマスのうち、周りの8マスがすべて通路のマスを水路にする（`cutWaterways`、`domain/tabletop/dungeon/sewer-channels`）。下水道の通路幅の既定は3マスで、中央の1マスが水路になり、両脇が歩道に残る。幅1〜2マスの通路には水路ができない。入口・出口・坑道口と、その周りの1マスは水にしない
- **集水槽** — 役割が大広間か行き止まりの部屋では、周りの8マスがすべてその部屋のマスを集水槽にし、壁沿いに1マスの縁を残す。その役割の部屋がない盤では、入口も出口もない部屋のうち最も広い1つを集水槽にする
- **橋** — 水が入口から床を切り離す所では、つなぎ直すのに要る最少のマスを水にせず残す。どの床にも、入口から水に入らずに歩いて行ける
- **流れと堰** — ひと続きの水路ごとに、歩いて集水槽へ最も近いマスを流れ出る所とし、水路に沿ってそこへ流す。集水槽がない盤では、ダンジョンの出口に最も近いマスへ流す。流れ出る所から数えて3マス（`outfallCells`）は集水槽と同じ深さに掘り、水路の水は堰を越えてそこへ落ちる（[落ちる水](water-ground.md#水域)）。3マス以下の水路には堰を作らない。水は乱数を使わずに決める
- **高さ** — 床を盤から1マス持ち上げて歩道とし、水路は底0.4マス・水面0.75マス、集水槽と堰の先は底0マス・水面0.3マスにする（`WaterwayPlan`、`domain/tabletop/dungeon/dungeon-atmosphere`）。水域は盤より下に置けないので、水面を歩道より低く見せるために床のほうを持ち上げる。地面の標本のうちマスの境目に乗るものは高いほうのマスに合わせ、岸の斜面を水のマスの中に収める。壁・扉・階段・家具の足元に当たる標本は歩道の高さに保ち、立つ物が水の底へ下がらないようにする（`reliefOfWaterways`）
- **排水管** — 集水槽の長い2辺の中央で、壁際の縁の1マスを水にし、そこに排水管を立てる。奥が岩でないマス、扉の隣のマス、橋に残したマスには立てない。3Dモデルで置くときは同梱の排水管のモデルでマスいっぱいに描き、口から集水槽へ水が落ちる（[排水口から落ちる水](water-ground.md#水域)）。排水管は通れて、視線を遮らない。足元の地面は水の底まで掘ってあるので、その分だけ地形を持ち上げて歩道の高さに立てる（`spoutBlock`、`domain/tabletop/dungeon/dungeon-blocks`）
- **水の見た目と害** — 水は濁り0.65・汚れ0.3で、水路は速さ0.55で流れ、集水槽は流れない。水のマスには、移動コスト1の`TableMoveCost`と、手番の始めに1d6のダメージと状態異常「毒」を与える`TableTrigger`（名前は「汚水」。部屋から見える状態）を置く（`WaterwayPlan.wading`、`DungeonBuildService.layHarms`）。危険地帯の種類は増やしていない。水域は`cave.hazardKind`の経路を通さずに置くので、アンビエンスを二重に置く経路は増えない
- **部屋と物** — 部屋は点検口・集水槽・密輸品の隠し場・ポンプ室・沈殿槽・作業室と呼ぶ。ポンプ室と作業室には配管を敷き、密輸品の隠し場には木箱と樽を、点検口と作業室には樽を積む。物はどれも壁際に置く（`room-furnishing`の`corners`と`pipeRun`）。樽と木箱は、2面が壁の隅から始めて、壁沿いと積んだ物の隣へ2〜4個のかたまりに育てる。配管は部屋の縁のうち、背が壁で出入口から1マス以上離れた最長の区間に、端（床へ下りる）・直管・バルブ付き（直管`every`本に1本）・曲がり（角）・端の順で1マスずつ敷く。作業室の配管は6マスまで（`most`）。壁際の物は部屋の床を2つに分けないことを置くたびに確かめ（`staysJoined`）、分けるなら置かない。配管の部品のモデルは1マスいっぱいの箱を持ち、辺の中央で隣とつながるので、モデルで立てるときは塊の幅を絞らない（`FurnishingShape.whole`）。向きは`spin`に90°刻みで入れる（モデルは直管が西→東、曲がりが西→南、端が西へ出る向きで、盤を見下ろして時計回りに回す）。壁は下水道のレンガ壁、扉は上へ開く鉄格子、明かりは壁のランタンで、開けた所に火は置かない
- **数** — 水域と、移動コストと害の範囲は、地形の上限に数えない。部屋数3・8・20、シード4つ、マスの形3つの組み合わせで、どれも150以下に収まることを`sewer-channels.spec`が確かめている

### 家具

- **置き方** — 家具は雰囲気の`furnishings`の計画ごとに、役割（と部屋の性格）の合う部屋へ置く（`furnishRooms`、`domain/tabletop/dungeon/room-furnishing`）。`grid`（柱の格子）・`scatter`（周りの空いたマスに散らす）・`stacks`（コンテナの列）・`corners`（隅の山）・`pipeRun`（壁沿いの配管）のほかに、次の置き方がある
- **カウンター** — `counter`は、長い壁から1マス離して部屋の長さより2マス短い帯を置き、前に1マスおきの席を並べる。帯の正面は壁と反対を向く。`back`があり、部屋の奥行きが5マス以上で、その壁に扉も通路もなければ、壁際に1マスずつその物を並べ、帯との間に給仕が立つ列を空ける
- **壁際** — `wall`は、壁に背を向けて部屋の内側を向く物を、壁ごとの区間に連ねて置く。区間の順と連ね始めるマスは種が選び、1つの連なりは1種類で`most`個まで（既定3）。数は床`every`マスに1つ。扉・通路・入口と出口の周りには置かず、床が二つに分かれる所にも置かない。`above`があれば、連なりごとに1つ、真ん中の物の上に重ねて掛ける（BARのネオン看板）
- **真ん中** — `centre`は部屋の真ん中に1つ置く。真ん中が下りの階段などで空いていなければ、周りに空きのある最も近い所に置く。縦と横の長さが違う物は、部屋の長い向きに寝かせる
- **列** — `rows`は、入口の辺の向かいの壁の真ん中に`back`を置いて部屋の内側へ向け、その手前2マス目から1マスおきの列に席を並べる。席は`back`を向き、真ん中の列は通路に空ける（教会の長椅子と祭壇）。入口の辺は、部屋の外（通路や通り）へ出る口のある辺で、隣の部屋へ通じる口はそれがないときだけ数える（`wayInWeight`）。身廊の祭壇は、聖具室の扉ではなく表の扉の向かいに立つ
- **向きと大きさ** — `counter`・`wall`・`centre`・`rows`で置いた物は向き（`DungeonFurnishing.facing`）を持ち、南向きに作ったモデルをその向きに回す。壁際の物は背が壁に付く。数マスの物（寝台は1×2、ルーレット台は2×1、魔法陣は3×3、`FurnishingShape.cells`）は、モデルで置くときどの盤でも1つのブロックにする。床に描く物（`floor`）は床だけのブロックにし、上を歩ける
- **部屋の性格** — 雰囲気の`roomSets`は、同じ役割の部屋に性格を掘った順に割り当てる（`assignRoomSets`、`domain/tabletop/dungeon/room-roles`）。乱数を使わないので、性格を持たない雰囲気の出力は変わらない。計画は`set`が部屋の性格と合うときだけ置き、概要はその部屋を性格の名前で呼ぶ（`roleIn.<呼び名>.<性格>`）
- **モデル** — 家具は同梱のモデルで描き（`FURNISHING_MODELS`）、モデルを使わない設定では塊で組む。ネオン・画面・薬・炎・魔法陣は光る（[光る部分](models.md#コマと地形のモデル)）

### 違法BAR

- **部屋と物** — 表の店には売り台・商品棚・自販機・木箱、酒場にはバーカウンター（背後に酒棚、前にスツール）・ネオン看板を掛けたボックス席・丸テーブル・ジュークボックス・スピーカーを置く。賭場には真ん中のルーレット台・賭博台・看板を掛けたスロット台の列、元締めの部屋には大机・ボックス席・水槽・ローテーブル・金庫、密造酒の貯蔵庫には樽と木箱の山と蒸留器を置く。個室は順にラウンジ（ボックス席とローテーブル）とゲーム部屋（アーケード筐体とスピーカー）になる
- **素材** — 壁は暗いレンガ（`wall_bar_brick`）、床は黒いテラゾー（`bar_terrazzo`）。家具の光が引き立つよう、壁と床には光るものを描いていない。前の既定だったネオンの壁とタイル（`wall_neon`・`neon_floor`）は、ビル群(SF)と、それで塗った部屋のために残してある

### 魔術師の塔

- **円い階** — 部屋の計画の`round`は、円い場所を正方形の盤に掘る（`roundOf`、`domain/tabletop/dungeon/rooms-and-mazes`）。円は盤のマスの中心が置かれる位置で測るので、ヘクスでも円になる。周り8マスのどれかが円の外にあるマスは掘らずに外壁として残し、扉の候補にもしない。壁も崩さない。円の外のマス（`DungeonLayout.outside`）には地形も床も置かない。入口をトンネルにすると、円の外壁を掘り抜いて口を開け、円の外は掘らない（`openTunnelMouth`は盤の端か円の外までを掘る）
- **盤の大きさ** — 同じ部屋数の長方形の盤と同じ面積の円に、縁と四隅の掘れない分を足した正方形にする（`ROUND_SLACK`、1.15倍）。一辺は長方形の盤の幅の上限（50マス）まで広げ、20部屋でも頼んだ数に近い部屋を掘る。ヘクスの盤は4分の3にせず、長方形の盤の高さの上限（38マス）までの一辺を0.95倍にする（`ROUND_HEX_LONGEST`）。ヘクスは1マスが1つの地形なので、それより広げると地形の上限700を超える。部屋は5〜7マス
- **部屋と物** — 入口の間は螺旋階段の間で、燭台とガーゴイルを置く。大広間は召喚の間で、真ん中に光って回る魔法陣を描く。宝物庫は秘宝庫で、浮かんで回る水晶の台と宝箱を置く。最奥は魔術師の書斎で、書き物机と本棚と書見台を置く。行き止まりは素材庫で、壺と樽と薬棚を置く。小部屋は順に書庫（本棚と書見台）・錬金術の工房（真ん中に大釜、錬金台、薬棚）・天文台（真ん中に輪の回る天球儀、望遠鏡）・寝室（天蓋の寝台と衣装棚）になる。魔法陣を大広間に描くのは、最奥の真ん中を下りの階段が取るため
- **明かりと階段** — 壁の燭台は紫・水色・橙に灯り、扉は木の扉、上り下りは螺旋階段

### フィールド

- **雰囲気プリセット** — 森林 / 草原 / 海岸 / 湿地 / 雪原 / 荒野 / ビル群 / ビル群(SF) / スラム街 / ゴミ処理場 / 農村 / 蛮族の砦 / 石造りの砦 / 城下町。地面の帯・生えるもの・天候・明るさをプリセットが決める（湿地は霧と薄暗がり、雪原は吹雪、荒野は砂塵）。城下町は町の割り付けと建物の部屋を持つ（[城下町](#城下町)）。ビル群からゴミ処理場までの4つは[市街](#市街)、農村と2つの砦は[村と砦](#村と砦)の決まりで地面と建物を置く。この節の地面の帯・海岸の傾斜・水の帯・地面の起伏は、森林から荒野までの開けた土地の6つに当てる（`FIELD_ATMOSPHERES`、`domain/tabletop/field/field-atmosphere`）
- **地面の帯** — 価値ノイズを3オクターブ重ね、別のノイズで読む位置をずらして（ドメインワープ、`warpedFbm`、ずらし幅`WARP`＝0.6）高さを作る。4オクターブ目は1マスより細かい模様になるので3つで止める。ずらさずに読むと、等高線のような同心の丸が並ぶ。この高さに水の溜まりやすさのノイズ（`damp`）を混ぜ、低い順に帯へ割り当てる（森林なら泥濘・草原・黒土）。帯の境は高さの値ではなく盤面の高さの順位で切るので、どの盤面でも各帯がプリセットの頼んだ割合（`upTo`）を占める（`domain/tabletop/field/field-layout`、`field-noise`）
- **海岸の傾斜** — 高さに盤面全体の傾き（`gradient`、海岸0.6・湿地0.15）を混ぜると、水が片側へ寄って渚になる。ノイズだけでは水が真ん中に池として溜まる。傾ける向きは四方からシードが選ぶ
- **水の帯** — 海岸・湿地・雪原は、いちばん低い帯（海岸は2つ）に水を張る。海岸は海と浅瀬（濁り0.2と0.15）、湿地は泥濘の上の濁った水（濁り0.8・汚れ0.6・落ち葉0.25）、雪原は凍った水（氷1）。水の帯には何も生やさない（`bare`）。水は帯ごとに`TableAmbience`の水域として置き、水面は盤の高さ、濃さは0.6（`FIELD_WATER_DENSITY`）。四角では帯を最小個数の矩形で覆い、ヘクスでは1列ずつの連なりにする（`areasOver`、`domain/tabletop/field/water-areas`）。水と氷の描き方と、氷の上に立つ決まりは[水域と地面](water-ground.md)にある
- **地面の起伏** — パネルの「地面の起伏（マス）」は0〜6マスを0.5刻みで選び、既定は2（`DEFAULT_FIELD_RELIEF`）。0なら平らなまま。開けた土地だけを、帯を切ったのと同じ高さに沿って盛り、いちばん低い所を盤の高さ、いちばん高い所を指定の高さにする。市街は盛らない。村・砦は、敷地（道・庭・床・畑・水田、柵と壁と扉、建物、作物、物、火のマス）とその外側1マスを、敷地の中心（砦は壁が囲む中心、村は敷地の重心）での野の高さにならし（0未満にはしない）、外へ2マスの帯で野の高さへ線形につないでから、その先を野と同じ式で盛る（`terraceSettlement`、`domain/tabletop/field/settlement-terrace`）。建物・壁・柵・作物が段差に掛からないための台地で、起伏0なら平らなまま（農村の小川の川床だけは起伏0でも掘る）。水の帯がある盤では岸から水の下を掘り下げ（深さは帯の`depth`で、海岸1.5・湿地0.4・雪原0.5マス。盛った高さを超えない）、水面を盤の高さに保つ。水のそばの陸は水面より0.1マス（`SHORE_RISE_CELLS`）高く始め、岸を線にする。盛った盤には段で組む「丘」を置かない（`reliefOf`）。地面を盛る仕組みは[水域と地面](water-ground.md)にある
- **植生の濃淡** — 生える確率をもう1枚のノイズで揺らす。森は濃いところと薄いところを持ち、一様に撒いたようにはならない
- **塞がらない** — 茂みは上下左右のうち2つ以上が埋まっているマスには置かない（`CROWD_LIMIT`）。木・岩・岩場などは1つずつの物として置き、同じ種類どうしを種類ごとの間隔（`spacing`。木は3マス、巨木は14マス）より近づけない。木立が壁になって歩けない盤面になるのを防ぐ
- **置かれるもの** — 木は幹と、地面から1.5マス浮いた3段の樹冠でできる（幹は幅0.38・高さ1.9、樹冠は下から広がり4.8・3.2・1.6マス）。木ごとに0〜0.6マス持ち上げて高さをばらつかせる。樹冠は広がりが1マスを超える段だけが視線を遮る。茂みは高さ0.45、岩は3段で高さ0.84、岩場は3マス四方・高さ2.4で視線を遮る。巨木は幅1マス・高さ2.6の幹に広がり6.6マスの樹冠を載せ、下に何も生やさない。荒野にはサボテン、ゴミ処理場には廃材の山、スラム街には街路樹が立つ。茂みだけはマスごとに置き、同じものが隣り合えば4マス（`FIELD_MERGE_SPAN`）までひとかたまりにまとめる。ほかは段ごとに回転・つぶれ・ずれを変えた物として1つずつ置く。水面には何も置かない（`FIELD_PROP_SHAPES`、`domain/tabletop/field/field-blocks`）
- **3Dモデルで置く** — 「木・岩・サボテン・廃材を3Dモデルで置く（3Dの卓で見えます）」（既定は入）では、木・茂み・岩・岩場・巨木・サボテン・廃材の山・街路樹を同梱のモデルで描く。モデルは場所から決め、6マス四方の木立は同じ種類にそろえ、4本に1本は別の種類にする（`fieldModelAt`、`domain/tabletop/field/field-models`）。草原・湿地・雪原は森林と別の木を生やす（湿地はヤナギやマングローブ、雪原は雪のモミ・トウヒや冬枯れの木）。「季節」は春に桜を混ぜ、秋に広葉樹を紅葉させてカエデとイチョウを混ぜ、冬に広葉樹を冬枯れに、針葉樹を雪のものに替える。モデルで描く物は、描いたモデルと同じ幅と高さの地形1つになる（[3Dモデル](models.md#同梱のモデル)）
- **広さと茂みの多さ** — 20〜60マス（縦は横の3/4、最低12マス）と0〜100%。開けた土地では多さ0なら地面だけの更地が出る。市街と村・砦では建物や畑の詰まり具合になる
- **素材** — 地面のピッカーはプリセットの主となる帯（森林なら草原）を差し替える。障害物のピッカーは壁の素材を着ている物（木の幹や建物の壁など）の側面を差し替える。樹冠や岩のように地面の素材を着ている物と、サボテンやコンテナのように素材の決まっている物（`PROP_OWN_WALL_TEXTURE_IDS`）はそのまま。障害物の素材を選ぶまでは、どの物もプリセットの素材を着る。残りの帯はプリセットのまま（`application/tabletop/map-generation/field-materials`）
- **概要** — 地面の帯ごとの割合（多い順）・立っているものの種類ごとの数（市街は建物の棟数も）・灯りの位置をパネルに出す（`buildFieldSummary`、`domain/tabletop/field/field-summary`）

### 市街

- **通りと敷地** — ビル群・ビル群(SF)・スラム街・ゴミ処理場は、地面の高さではなく通りの割り付けで地面を塗る。盤を横切る通りを1つの格子で切り、通りの間の街区を歩道で囲み、街区を敷地に分けて、空けておく敷地（`vacancy`）のほかに建物を1つずつ建てる。盤の端は街区の途中から始め、盤の外にも町が続いて見えるようにする。割り付けは`layTown()`（`domain/tabletop/field/town-layout`）、プリセットごとの決まりは`TownPlan`
- **4つの市街** — ビル群は高さ2.5〜7マスのビルを盤の中央ほど高く建て、4.5マスを超えるビルは、敷地が4マス四方以上なら1〜2マスの基壇の上に、敷地の縁から1マス引っ込めて立てる。歩道に街灯を立てる。ビル群(SF)は3.5〜8マスで、雨の夜にシアンとマゼンタの光の柱を歩道に立てる。スラム街は街区を奥行き3マスの長屋で縁取って中を裏庭に残し、2.5〜4マスの建物の屋上に木の水槽を載せることがあり、歩道に街路樹を植える。ゴミ処理場は高さ1〜1.8マスのトタン小屋を少し傾けて建て、街区の列ごとに通りの位置をずらし、雨の中で通りの低い所（22%）を泥濘の水たまりにする
- **建物の描き方** — 建物は敷地ごとに1つの地形（基壇のあるビルは2つ）で、屋上設備を載せることがある。3Dモデルで置くときは、壁の素材ごとの部品一式（`TOWN_KITS`、`domain/tabletop/field/town-models`）を箱いっぱいに繰り返して描く（[glbのextras](models.md#コマと地形のモデル)の`facade`）。ヘクスでは建物を1マスに1つの地形で組み、建物にはモデルを使わない

### 村と砦

- **割り付け** — 農村・蛮族の砦・石造りの砦・城下町は、`laySettlement()`（`domain/tabletop/field/settlement-layout`）が割り付け、同じシードなら同じ形になる。マスごとの地面は`SETTLEMENT_ZONES`の6区分（開けた地面・道・庭・建物の床・耕した土・水田）で、雰囲気の地面の帯をこの順に塗る。「茂みの多さ」は家・畑・物の詰まり具合（0〜100、既定50）として読む。建物は外壁の内側を仕切り壁で3マス以上の部屋に分け、仕切りごとに扉を1枚、外へ出る扉を1枚付ける
- **農村** — 盤を横切って少しずつ曲がる幅2マスの道に沿って、木の壁の家を3〜5軒（多さで増減し、最低2軒）並べる。家は扉を道へ向け、家の前にランタンを置く。半分ほどの家は板壁の納屋と干し草を持つ。空いた所に5〜8枚（多さで増減）の畑を作り、野菜・麦・とうもろこしの畑は柵で囲んで一辺に2マスの出入り口を空け、稲は柵のない水田にする。道ばたに井戸、荷車と干し草も置く。そのあとで小川・水車小屋・風車を足す（[小川と水車と風車](#小川と水車と風車)）
- **蛮族の砦** — 盤の中央を楕円の丸太の柵で囲み、南に両開きの門を付け、柵の上に見張り塔を立てる（塔のそばに火鉢）。内側には2部屋の族長の館（炉つき）と、大きな焚き火を囲む天幕（入口は扉のない開口）、トーテムを置き、門から盤の端へ小道を通す
- **石造りの砦** — 盤の中央を四角い石垣で囲み、四隅と南の門の両脇に塔を立て、門には上へ開く鉄格子を吊る。石畳の中庭の奥に3〜5部屋の天守、壁沿いに兵舎と厩舎を建て、井戸を置き、門から盤の端へ道を通す
- **壁と扉** — 壁は9種（`SETTLEMENT_WALL_KINDS`）で、高さは種類ごとに決まる（丸太の柵2.5・見張り塔4・石垣3.5・塔5・木の壁2・石の部屋の壁3・柵0.6・納屋の板壁2.5・天幕2マス）。扉と門は、かかる壁と同じ高さで立つ。柵だけは視線を通し、登って越えられる（`LOW_WALLS`）。ほかの壁は視線を遮り、登れない（`domain/tabletop/field/settlement-blocks`）
- **畑** — 麦・とうもろこし・稲の畑は通りにくく（`SLOWING_CROPS`）、余分な移動コスト1を`TableMoveCost`として置く。野菜の畑は普通に歩ける。水田には浅い水（水面は台地の高さから0.08マス、濁り0.8）を張る。水域の水面は盤からの高さで持つので、台地の高さを足さないと、起伏のある村では水田の地面が水面より高くなり、水が描かれない。3Dモデルで置くときは、作物を厚さ0.02マスの床の地形の上に描くので、畑に入ったコマは地面に立ち、作物は視線を遮らない
- **3Dモデル** — 3Dモデルで置くときは、丸太の柵と石垣を外向きにそろえたタイルで、家・部屋・納屋・天幕の壁と柵を[つながる壁](#つながる壁)で、塔と見張り塔を1つずつのモデルで描く。ヘクスでは塔と見張り塔をブロックで組む

### 小川と水車と風車

- **村に足す** — 農村は、村の割り付けが済んだあとに、小川・水車小屋・風車を足す（`layMillStream`、`domain/tabletop/field/mill-stream`）。乱数は村とは別の種（`seed + 8521`）から取り、道・家・納屋・畑・井戸・荷車・ランタンは1マスも変えない。小川のマス（橋を除く）、水車小屋の小屋、風車は`taken`に入り、敷地に数える。水車小屋と風車の周り2マスには木と茂みを生やさない
- **小川の道筋** — 盤の上の端から下の端まで、幅1マスで4方向につながる道筋を、1歩2・曲がり+4のコストで最短に探す。通れるのは、何も立っていない開けた地面と、道のマス。道はまっすぐ渡り、渡ったマスは橋として、水にも川床にもせずに残す。庭・床・畑・水田と、扉の前、柵の畑の出入り口の外は通らない。ヘクスでは、道以外の立っている物の周り8マスも通らない。ヘクスの地形の箱は隣のヘクスの地面に掛かり、小川の脇の物が川床まで下がるため。道筋のない村には、小川も水車小屋も置かない
- **小川の高さと水** — 小川のマスを台地から0.5マス（`STREAM_DEPTH`）掘り、岸の斜面を小川のマスの中に収める（`digStreamBed`、`domain/tabletop/field/settlement-terrace`）。水面は盤から「台地の高さ−0.2マス」で、0.06マスを下回らない（`streamSurfaceOver`）。流れの向きごとに分けた流れる水域（速さ0.5・濁り0.2）を重ならないように置き、移動コスト1の`TableMoveCost`を重ね、川床を砂利の絵で塗る
- **水車小屋** — 小川がまっすぐ2マス続く所の岸に、3×2マスの1棟を立てる。輪の列が小川に重なり、小屋の2×2マスが岸に立つ。流れの左岸（下流を向いて左）を選び、そこに空きがない村では反対の岸に立てる。輪はどちらの岸でも小川の流れる向きに回る（[流れる水で回る向き](models.md#コマと地形のモデル)）。道から2マス以上離す。盤の端から4マス以上内側の候補があればその中から、橋に近い3つのうち1つを種で選ぶ。足元に川床が掛かるので、地形が下がる分だけ持ち上げて台地の高さに立てる（`liftsTo`、`domain/tabletop/field/settlement-blocks`）
- **風車** — 3×3マスの空きを種から探して1基立て、羽根を道へ向ける。周り2マスに何も立っていない所を先に探し、見つからなければ周り1マスで探す。置き場のない村には立てない
- **描き方** — 3Dモデルで置くときは、風車も水車小屋も1棟を1つの地形にして同梱のモデルで描き、羽根と輪が回る（[回る部品](models.md#コマと地形のモデル)）。ヘクスでも1つの地形にし、箱の中心を、風車は中央のマスの中心に、水車小屋は輪に最も近い小屋のマスの中心に合わせる（`millStandsOn`を`MapBlock.standsOn`に渡す）。モデルを使わないときは、風車を3×3マスの箱で、水車小屋を小屋の2×2マスの箱（高さ2.2マス）で組み、輪は置かない

### 城下町

- **城壁と通り** — 城下町は`laySettlement`が`castleTown`として割り付ける（`domain/tabletop/field/settlement-layout`）。城は盤の外の北にあり、盤の上の端を城壁が走る。真ん中に両開きの門と、その両脇の2×3マスの塔を置き、城壁に6マスおきに旗を掛ける。門の2マスの通路から大通りを下の端まで通し（盤の幅が28マス以上なら4マス、それ未満なら2マス）、盤の高さの55%あたりで横の通り（3マス、高さ22マス未満なら2マス）と交える。幅32マス以上の盤には大通りの両脇に縦の小路（2マス）を通し、横の通りより下に建物2列と小路の入る深さがあれば横の小路も通す
- **広場** — 大通りと横の通りの交わる所に広場を敷く（盤の幅の32%・高さの40%で、8〜14×7〜11マス）。真ん中に3×3マスの噴水、上と下の縁に広場を向いた露店（大通りの幅は空ける）、噴水の東と西にベンチ、四隅に花の箱と街灯を置く。大通りと横の通りの縁にも、8マスおきに街灯を立てる
- **区画** — 通りの間に残った矩形を、長い向きに間口5〜8マスの区画に切り、奥行きが許すだけ背中合わせの列にする（1列の奥行きは5〜7マスで、余れば列の間を1マスの路地にする）。区画は、通りに接するマスの多い辺へ扉を向け、通りに接しなければ空いた土地に接する辺へ向ける
- **建物** — 門に最も近い区画に衛兵の詰所、広場に近い広い区画（7×8マス以上）に教会、広場に近い広い区画（6×7マス以上）に宿屋と酒場を建てる。鍛冶屋・パン屋・雑貨屋も通りに面した区画に1つずつ建て、残りの区画は民家にする。多さに応じて、いくつかの区画を空き地に残す
- **部屋** — 建物は村の家と同じく、全部が壁と扉の部屋で、教会と詰所は石の壁、ほかは木組みの壁で建てる。部屋数は種類ごとの範囲を、床の広さで抑える（1部屋あたり教会30・宿屋と酒場20・詰所9・ほか12マス）。入口の内側のマスに最も近い部屋を表の部屋、残りを奥の部屋として、種類ごとの名前を付ける（`TOWN_ROOM_KINDS`。宿屋なら食堂と客室、詰所なら詰め所・兵舎・武器庫）
- **家具** — 部屋の家具は、ダンジョンの家具と同じ仕組みで置く（`furnishSettlement`、`domain/tabletop/field/settlement-furnishing`）。壁を岩、扉を扉、建物の床を部屋、外を通路として渡し、部屋の名前ごとの計画（`TOWN_ROOM_PLANS`）で置く。宿屋の食堂と酒場には酒場のカウンター・暖炉・テーブル・椅子・樽、客室には寝台とチェスト、鍛冶屋には鍛冶炉・金床・武器掛け、パン屋にはパン窯と粉袋、店先には売り台と雑貨棚を置く。教会には祭壇と長椅子の列と燭台、詰所には机と武器掛けと二段寝台、民家の台所には暖炉・テーブル・食器棚、寝室には寝台・衣装棚・チェストを置く
- **看板と灯り** — 宿屋・酒場・鍛冶屋・パン屋・雑貨屋は、扉の隣の木組みの壁のマスに吊り看板を掛け、通りへ向ける。看板と城壁の旗は壁のマスを分け合うので、モデルで置くときだけ置き、歩くのを妨げない（`HUNG_FIXTURES`）。通りに面した戸口の2つに1つの脇に、ランタンを灯す。扉の正面のマスは空け、地面に立つ物と火は1マスに1つだけ立てる（`Plot.stand`・`Plot.light`・`Plot.keepClear`）。そのため広場の物は建物のあとに置く
- **地面と描き方** — 路地と庭は草地、通りは小さな石畳、広場は大きな敷石、建物の床は板で、庭には木が育つ。3Dモデルで置くときは、通りの物（`TOWN_FIXTURE_KINDS`）と家具を同梱のモデルで描き、木組みの壁は村と同じモデルにする。暗さは夕暮れの0.3

### つながる壁

- **隣の壁へ腕を伸ばす** — glbのextrasの`fit`が`joined`のモデル（[3Dモデル](models.md#コマと地形のモデル)）で描く地形は、`wallJoinsOf()`（`domain/tabletop/world/wall-joins`）がつなぎ方を決める。地形が立つマスごとに中心へ`hub`の部品を立て、同じモデルの地形か扉が隣にある辺へ、中心からその辺まで腕の部品を伸ばす。これで直線の壁は1本につながり、角・T字・十字も組み上がり、扉の脇では壁が扉まで伸びる。四角では4方向、ヘクスでは6方向の辺を見る。どこにも腕を伸ばさない地形は、つなぎ方を持たずにモデルどおりに描く
- **どの壁がつながるか** — つなぐかどうかはモデルのファイルが決める。`ModelFitService`（`application/tabletop/model-fit.service`）が手元のモデルのJSONだけを1度読んで`fit`を覚え、`Table3dService`がつながる壁の地形と、霧に隠れていない扉を集めて`wallJoinsOf()`に渡す。同梱のモデルでは石の部屋の壁・丸太の壁・木骨の壁・柵・板壁・天幕の壁がこれにあたる。マップエディターの[3Dオブジェクト塗り](map-editor.md#機能塗りマップエディター)で1マスに1つずつ置いた壁も、生成した壁と同じようにつながる

### 共通のしくみ

- **床はマップエディタの塗り** — 床は地形ではなく、マップエディタと同じセルレイヤーとして塗り、1枚の画像に焼いてテーブルの表面に貼る。床は何も支えず、視線も光も通すので、地形にする理由がない。地形にすると床1枚あたり12個の同期オブジェクトを使い、地下墓所20部屋では塗りの204個に対して323個になる。焼いた画像は誰の子でもないので、卓を捨てるときに画像保管庫からも消す
- **明かり** — 暗闇のプリセットでは光源オブジェクトを卓の子として立てる。絵柄はキャラコマと同じ立ち方で、マスの中央に立つ。狭い部屋には壁掛け松明かランタン（壁の高さより1マス低いところまで上げて、壁に掛かって見える）、広い部屋には焚き火・火鉢・ランプスタンド。フィールドでは焚き火を離して置く。壁ブロックそのものを光らせるとその地形が光を遮らなくなり、最大12マス四方の穴が開くため、明かりは必ず独立したオブジェクトにする。明かりの動きは種類ごとのプリセット（ほとんどがゆらめき）に従い、生成パネルの「灯りの動き」でなし・ゆらめき・明滅のどれかに揃えられる（`DungeonBuildOptions.lightMotion`、`GeneratedLightMotion`）。選んだ値はブラウザのlocalStorage（`axe.generator.lightMotion`）に残し、初めは雰囲気どおり
- **矩形マージ** — 隣り合うセルをまとめて1つの地形にする。ダンジョンを1マス1地形で置くと、まとめたときの約14倍の地形になり、同期するオブジェクトも視線計算が横切る辺も同じだけ増える（`mergeMaskToRects`、`domain/tabletop/dungeon/rect-merge`）。まとめる一辺は、ダンジョンで12マス（`MAX_MERGE_SPAN`）、フィールドで4マス（`FIELD_MERGE_SPAN`）まで。上限は700個（350個で警告）
- **マスの形** — 四角とヘクス（縦・横）を選べる。ヘクスの卓の地形は`min(width, depth)`マス幅の花形に描くので、5マスをまとめた地形は1マス分しか描かれない。そのためヘクスではまとめず、1セル1ブロックにする（`mergeSpanFor`、`domain/tabletop/map-grid`）。モデルの家具・噴水・屋台・水車小屋・木の枝葉のように数マスで1つの地形は、卓に置く1か所（`blockCorner`）で、箱の中心を矩形のどれかのマスの中心に合わせる。どのマスかは`MapBlock.standsOn`で決め、ないときは中心に最も近いマスにする。生成器の作業台のプレビューと地面からの持ち上げ（`blockLiftsTo`）も同じ関数で位置を出す。同じ盤面では上限を大きく超えるため、ヘクスでは一辺を0.75倍にする（`HEX_BOARD_FACTOR`、面積で約44%減）。全雰囲気 × 部屋数3/8/20 × シード4種 × ヘクスの縦横で上限700に収まることを`dungeon-generator.spec`が確かめている。レイアウトが掘る隣接は東西南北の4方向で、これはオフセット格子ではヘクスの6隣接に含まれるため、四角で歩けた道はヘクスでも歩ける。テーブルはヘクス盤と同じ列数・行数で作る（`tableSizeFor`）。卓もヘクスを列で数えるので、盤の実寸をマスの大きさで割り戻すと列が足りなくなる
- **未探索の覆いは置かない** — 盤面いっぱいのマスクは下の地形へのクリックをすべて奪ってしまうため。隠したい場合は卓のメニューから手でマップマスクを置く
