# ロビー・部屋・ネットワーク

## ロビー / 部屋 / ネットワーク

- **2D / 3Dは席ごと** — 席の視点（自動・3D・2D）は`ViewModePreferenceService`（`application/ui/view-mode-preference.service`、localStorageの`ui-view-mode`）が持ち、部屋へは配らない。1人が2Dで見たくても、ほかの人の卓は寝かせないためである。`TabletopService.mode2d`は`laysFlat()`（`domain/ui/view-mode`）で決まり、自動の席はテーブルの推奨ビュー（`GameTable.mode2d`を読む`TabletopService.recommendsFlat`）に従い、3Dか2Dを選んだ席はその選択に従う（推奨ビューは[テーブル表示](tabletop.md#テーブル表示2d--3d)）。卓の傾きロックは`game-table.component`のeffectが`mode2d()`と`orthographicProjection()`を見て張り直す
- **メニューは命令表＋並べ方の2枚** — 押せるもの1つずつに固定のkeyを与えた`MENU_COMMANDS`（`domain/ui/menu-command`）と、面ごとの並び`MenuLayout`（`domain/ui/menu-layout`、入れ子は1段）。面は`MENU_SURFACES`のFAB・GMツール・PLツール・チャットツール（`fab` / `gmToolbar` / `plToolbar` / `chatTools`）の4つで、どれもこの命令表から描く。チャットツールは発言にポインタを乗せると出るボタンの列で、置けるのはkeyが`chat:`で始まる`chatTool`の命令（`CHAT_TOOLS`）だけ。この命令はほかの面には描かない（[チャット](chat.md#チャット)）。小窓を持てる面はFABだけ（`menuSurfaceTakesGroups`）。`MenuAction`は`panel` / `toggle` / `cycle` / `act` / `custom` / `chatTool`の6種で、`custom`は行動順表示・ペルソナ・NPCバー・操作対象・射程・一人称視点のようにボタンでないものの逃げ道。**`audience`は命令表が持つ**のが要で、利用者のデータに入るのはkeyだけなのでlocalStorageを書き換えてもGM専用の命令は現れない（`MenuCommandService.run()`が`offers()`を再確認する）。発火と「いまどう見えるか」（切替の点灯・設定の現在値アイコン・保存中の無効化）は`features/menu/menu-command.service`の1か所。保存は`RoomFilesService`に、パネルの開閉は`RoomPanelService`に頼み、ページの要素であるファイル選択だけを画面から`registerFilePicker()`で受け取る。i18nの抜けは`i18n-choices.spec`が`MENU_COMMANDS`の`labelKey`と既定の小窓の`labelKey`で拾う
- **並びはこの端末だけのもの** — `application/ui/menu-layout.service`（`axe.menu.fab` / `axe.menu.gmToolbar` / `axe.menu.plToolbar` / `axe.menu.chatTools`）。**保存キーが無いときだけ既定**（状態異常カタログの「空なら配る」とは意味が違う。空にした人に配り直さないため）。リセットは既定を書き込むのでなく**キーを消す**ので、後の版で項目が増えたらその増分が入る。`parseMenuLayout`は寛容で、知らないcommandを**読み取り時には落とさず**描画時に落とす（新しい版で書いた並びを古い版で開いて戻したとき、消えていないように）。部屋のXML・`SaveDataService`・`FileArchiver`は一切触らない
- **編集パネル** — `features/menu/menu-editor-panel`（パネル名`menuEditor`、Favの「表示」から）。編集できる面は役割で絞り、GMはFAB・GMツール・チャットツール、PLはFAB・PLツール・チャットツール、見学はFABとチャットツール。小窓を作れるのはFABを編集しているときだけ。足す / 外す / 改名 / アイコン変更 / 小窓へ出し入れ / 上下。アイコンは`ui/components/icon-picker`の一覧から選ぶ。候補は`domain/ui/icon-font`の`ICON_FONT_NAMES`（同梱WOFF2の字形2,234種を、切り出し元の符号位置表で公開名に戻したもの。合字名は数字が英単語に化けるため字形名からは起こせない）で、**打つ前は命令表が使っているマークだけを出す**（2,234件を並べても選べない）。`icon-font.spec`が「既定のメニューが使うマークは全部描ける」を固定する。小窓の出る位置は`ui/anchored-popover`の`fitPopover`（立ち絵やスタンプのピッカーと共用）。並べ替えと段替えはどちらも取っ手のドラッグで、`ui/dragging/row-reorder`の`RowReorder`に載る。**落とし先は`domain/ui/menu-layout-edit`の`menuDropSpot`が決める**（小窓の見出しの下半分は「中へ」・それ以外の隙間は隣り合う項目のもの・小窓を小窓の中身の隣に落とすとその小窓の隣に出る）。タッチはドラッグが始まらないので、行の右クリック/長押しに`buildReorderContextMenu`の上下と移す先を出す。足す側は`menu-command-picker`（同じ小窓の作法・名前とキーで絞り込み・**選んでも閉じない**ので続けて足せる）で、小窓は名前を聞かずに作って行で改名させる（同じことを二度聞かない）。編集操作は`domain/ui/menu-layout-edit`の純関数で、小窓の入れ子は`moveMenuNodeInto`が拒む。持ち出しは`domain/ui/menu-layout-file`のJSON 1枚（`axe-menus.json`）で、**面を1つも名指ししていないファイルはnull**（読むと全面が空になるため）
- **部屋設定パネル** — テーブルをまたいで効く決めごとを1枚に集める（`features/room-settings/`、パネル名`roomSettings`）。中身は`ROOM_SETTINGS_TABS`（一般/戦闘/移動/UI/通知/スタンプ/自動保存/ユーティリティ）のタブ。UIタブはさらに`ROOM_SETTINGS_UI_TABS`の共通・スキン・卓上に分かれる。共通は部屋の全員に効く表示（キャラクターの向き＝部屋ルール、コマ画像をマス内に収める＝部屋ルール、コマ画像を常にカメラに向ける＝卓の属性、数値リソースにスライダーを既定で出す）で、変えられるのはGMだけ。スキンと卓上はその画面のもの（卓上ディスプレイ一式＝その画面のlocalStorage）で、誰でも触れる。書けるかは`RoomSettingsAccessService`が決め、遊びのルールを書けるのは卓を編集できる人、全員の画面に効く設定を書けるのはGMだけ（読み取り専用かは`isReadOnly` / `isSharedReadOnly`）。**読み取り専用の`inert`はタブの中身に掛ける**（hostに掛けると見学者がタブを切り替えられない）。自動保存タブは`RoomSnapshotPanelComponent`を、スキンのタブは`skin-picker`を埋め込む（`FEATURE_DEPENDENCIES`に`'room-settings': ['room-archive', 'skin']`が要る）。自動保存の入切は`RoomSnapshotService.isKeeping`＝**localStorage**（ひかえはその端末の中にしか無いので、部屋の決めごとにしない）。`RoomArchiveEventHandlerService`は`markDirty`と`flush`の両方で見る。移動範囲・ZOC・1マスの距離・コマの向きは`GameTable`の属性のままだが、`Config`が同名の答えを持ち（`CONFIG_RULE_ANSWERS`、`domain/peer/config-rule-answers`）、`domain/tabletop/room-rules`の`resolveRoomRules()`が**フィールド単位でConfig → table → 既定**の順に解決する。`Config`の属性での「未回答」は文字列/enumが`''`・数値が負の値（書くときは`-1`）・yes/noが`''`（答えは`'1'`/`'0'`）で、`readRuleText` / `readRuleNumber` / `readRuleFlag`はどれもnullに読む。属性の名前は、保存した部屋と古いピアが知っている名前のまま変えない。**移行処理は無く**、パネルでその項目を初めて書いた時点がその項目の移行で、触らない部屋は永久に今までどおり動く。移動範囲とZOCの欄の頭には、`ROOM_RULE_GROUPS`のまとまりのうち部屋が答えた項目が1つでもあれば（`isGroupAnswered()`）「部屋全体の設定です。どのテーブルを出しても同じルールになります。」を、無ければ「いまはテーブルごとの設定です。ここで変えると部屋全体の設定になります。」を出す。既定ダイスボットは一般タブで選ぶ
- **招待リンク** — 接続情報パネルで部屋ID / 部屋名 / 合言葉（任意）/ ロールを載せたリンクを生成。開くと起動時に自動入室し、進行状況と失敗時のロビー導線をバナーで表示。リンクはハッシュフラグメントに載せるためサーバーログに残らない。合言葉は部屋IDと部屋名から作るマスクを掛けて平文を出さないが、見た目で読めなくするだけで、リンクを持つ人は戻せる（`domain/peer/invite-link`、`features/lobby/invite-join`）。部屋のサーバーではロールを載せず、部屋のkeyと、GMが作るときはサーバーが署名した招待を載せる（[部屋のサーバー](#部屋のサーバーサーバー版ベータ)）。配信用の画面として開くかも載せられる（[配信オーバーレイ](replay.md#配信オーバーレイ)）
- **入室の処理** — 部屋検索と接続を`features/lobby/room-join.service`に集約し、タイムアウトで決着させる（ロビーと招待リンクで共用し、部屋のサーバーへの再接続も使う）。部屋のサーバーの部屋は部屋のkeyで探し、keyの無いリンクや席は一覧から部屋IDと部屋名で探す。開くまでは30秒（`ROOM_SERVER_OPEN_TIMEOUT_MS`）待つ。SkyWayの部屋にGMのまま入ろうとすると、PLとして入る。役割は部屋ができる前にブラウザで選んで部屋をまたいで残るので、そのままではGMのいる部屋にGMとして入り込むためである。このタブが前にその部屋のGMだったときだけ、GMのまま戻る
- **ロビーの画面** — 部屋の一覧（`features/lobby/lobby`）、部屋の作成（`features/lobby/room-setting`）、合言葉の確認（`features/lobby/password-check`）。部屋名は255文字まで
- **再接続** — 接続情報パネルの「再接続」は、ほかの参加者か部屋のサーバーにつながっているときだけ出る。「不整合データを削除する（同期破損時のみ）」を入れると、キャラクター・射程範囲・共有メモ・ダイス・マスク・地形を消してからつなぎ直す（`features/lobby/re-connect`）
- **相手ごとのつながり方（SkyWay版）** — 接続情報パネルの相手の一覧は、SkyWay版では行ごとに相手とのつながり方を出す。行に出すのは、ストリームがある相手、再接続の順番を待っている相手、SkyWayが部屋にいると言っている相手で、ストリームがない相手も行になる。状態は5つあり、アイコンと語で見分けられる。「直接」はアイコンだけで、「中継サーバー経由」（TURNを通る直接の回線）は既定の色、「他の人経由のみ」は注意の色、「再接続中」はアクセントの色、「接続できません（再試行中）」は危険の色で語を添える。「他の人経由のみ」と「接続できません（再試行中）」の行は、下に「この人とは直接つながっていません。部屋のデータは他の人から受け取ります。」を出す。状態は`peerLinkStateOf`（`core/network/peer-link`）が決め、`SkyWayConnection.peerLinks`が相手ごとに返す。ストリームが開いていれば直接とする。開いていなければ、ストリームが開くのを待っているあいだと、1・2・4・8・15秒の再試行のあいだを再接続中とする。再試行を使い切った相手（30秒ごとの再試行は続く）と、まだつなぎに行っていない相手は、ストリームが開いている誰かがユーザー一覧にその相手を載せていれば他の人経由のみ、誰も載せていなければ接続できませんとする。直接のうち`isRelayedLink`が真の回線を中継サーバー経由に分けるのは`PeerLinkService`（`application/lobby/peer-link.service`）である。一覧の幅が320px（`NARROW_PEER_LIST_PX`）より狭いときは、1行目にアイコン・名前・最後の応答の時刻、2行目に状態の語と役割を置き、語と説明は折り返して全文を出す。部屋のサーバー版はつながり方を出さず、行は部屋のサーバーが知らせるメンバーのままである
- **同期の進み（SkyWay版）** — 接続情報パネルの「部屋のデータを同期し直す」の上に、自分の席の同期の進みを出す。まだ届いていないオブジェクトがあるあいだは「部屋のデータを受け取っています（残りN件）」と細いバーを出し、残りが30秒（`SYNC_STALLED_MS`）減らなければ「受け取りが止まっています。回線が混んでいるか、相手とつながっていません。」に替える。初回の同期が済んで残りが無くなると「部屋のデータは最新です」を出したままにする。直接つながっている相手が1人もおらず、「他の人経由のみ」か「接続できません（再試行中）」の相手がいるときは、ほかの文に代えて「部屋のデータを受け取れる相手がいません」を出す。残りは`ObjectSynchronizer.pendingCount`で、要求表の件数と実行中のタスクが待っている件数を足した数である。相手のカタログが届くと増えるので割合は出さず、バーは進んだ量を表さない。初回の同期が済んだかは`isSettled`、止まっているかは`lastProgressAt`（頼んだオブジェクトが最後に届いた時刻。待ち始めた時刻も入る）で決める。`PeerLinkService`はパネルが開いているあいだだけ、`CONNECT_PEER`・`DISCONNECT_PEER`・`PEER_RECONNECT`、回線の統計（`peerStatsUpdated$`）、`syncProgressChanged$`（`core/sync/sync-progress-events`）、1秒ごと（`LINK_POLL_MS`）のどれかで読み直す。`syncProgressChanged$`は250ms（`SYNC_PROGRESS_NOTICE_MS`）に1回までしか知らせず、signalは値が変わったときだけ変わるので、数千件の同期のあいだもパネルを描き直すのは1秒に4回までである。部屋のサーバー版はこの欄を出さない
- **ネットワークのエラー** — 接続の失敗はチャットにシステムの行で出す（`features/lobby/network-event-handler.service`）。errorType`server-error`は3・8・15秒の間を空けて3回まで、ほかのエラーは別に数えて3回まで、つなぎ直す
- **部屋名の受け渡し** — SkyWayでは、ロビーのチャンネルに入るときに部屋名をメンバーのmetadataに載せ、部屋の一覧はそこから部屋名を読む（`core/network/skyway/skyway-facade`）
- **再読み込み直後の再参加待ち** — peerIdは再読み込みしても変わらず、去るページはチャンネルから抜けきれないので、前のメンバーが最長1分ほど残る。その間に参加すると、SDKは`alreadySameNameMemberExist`で断る。そこで部屋とロビーへ参加する前に、同じ名前のメンバーが抜けるのを`onMemberLeft`で待つ（`core/network/skyway/same-name-member`）。期限はSDKのkeepaliveの間隔と猶予（各30秒）に5秒を足した長さで、部屋とロビーで共有する。相手のメンバーは消さない（複製したタブかもしれないため）。開くたびに中止用のシグナルを作り、閉じたり開き直したりすると待ちを取り消す。期限切れはerrorType`same-name-member`で、専用の文言を出して待機に戻り、汎用の再試行の回数には数えない。待っている間は、ロビーと招待のバナーに「前の接続が切れるのを待っています（最長1分ほど）」を出す（`RoomJoinService.waitingForPreviousConnection`）。参加は「開く」（待ちに10秒を足した長さまで）と「つなぐ」（15秒）の2段で、openとエラーは部屋のpeerIdで照らし、待機用の接続のものと取り違えない。一覧に残った自分の古いpeerIdは接続先から外し、ほかに誰もいなければ部屋を開けた時点で参加とする（GMが一人だった部屋）。ロビーは、参加の処理中は次の参加ボタンを受け付けない

## 部屋のサーバー（サーバー版、ベータ）

- **選び方** — 部屋のサーバーを使うかは、部屋ごとではなく、置いたAxeごとに`assets/config.json`で決める。`"transport": "server"`と`backend.url`（部屋のサーバーのURL）を書くと部屋のサーバーに、それ以外の値のときと欄が無いときはSkyWayにつなぐ（`transportOf()`、`core/network/transport`、`composition/app-config.service`）。部屋のサーバーは卓を持ち、最後の1人が出たあとも保持期間のあいだ部屋を残す。画像と音声は部屋ごとにサーバーへ上げる（`core/storage/asset-http-store`）。Axeと部屋のサーバーはやりとりの版（`PROTOCOL_VERSION`、6）が同じでないとつながらない。同期とやりとりの仕組みは[同期と通信](../architecture/sync-and-network.md)にある
- **ログイン** — DiscordのアカウントでPKCEを使ってログインする（`core/network/server/server-login`、`application/lobby/server-auth.service`）。ログインの画面はポップアップで開き、開けないときはページごと移って戻ってくる。アクセストークンは15分（`ACCESS_TOKEN_SECONDS`）で、リフレッシュトークンで次の組に替える。組はlocalStorageに置き、同じページのタブはどれも1つのログインを使う。リフレッシュトークンは1回しか使えず、2回目をサーバーは盗用とみなして系列ごと無効にするので、タブはロックを取って1つずつ替える。部屋にいる間は30秒ごと（`TOKEN_CHECK_MS`）に新しいアクセストークンを確かめてサーバーに渡す（`core/network/server/token-renewal`）。サーバーはトークンの期限が切れて1分たった席を閉じる。ログイン・ログアウト・アカウントの削除（2回たずねる）は、ロビーの上端と、見学者の接続情報パネルにある（`features/lobby/server-account`）。サーバーがログインを用意していないときは「このサーバーにはログインが用意されていないため、部屋を使えません」と出し、部屋を使えない。配信用の画面は、ブラウザがログインしていてもログインを使わず、見学として入る。アカウントとして入ると、そのアカウントの席を取って本人の画面を追い出すためである
- **役割はサーバーが決める** — サーバーが役割を決め、`PeerCursor`の役割を上書きする。部屋を作った人と、GMがGMにした人はGM（`gm`）、ログインした人はPL（`pl`）、ログインしていない人は見学（`guest`）になる（`SERVER_ROLES`、`core/network/server/server-protocol`）。GMがほかの人の役割を変えるときは、接続情報パネルからサーバーへ`ROLE_REQUEST`を送り、サーバーが変えるか断る。ログインしていない人を見学から上げることと、部屋の最後のGMを外すことは断られる。画像と音声は誰でも読めるが、上げられるのはGMとPLだけ
- **サーバーの招待** — GMは接続情報パネルで、GM・PL・見学のどれで招くかを選び、サーバーに招待の署名を頼む（SkyWayの部屋で選べるのはPLと見学だけ）。招待は30日（`INVITE_SECONDS`）効き、ログインした人がその部屋に初めて入るときの役割になる。ログインしていない人がリンクを開くと、入る前にログインするか「見学で入る」かをたずねる。見学を選んだ部屋はそのタブが覚え、次からはたずねない（`features/lobby/invite-join`）
- **見学に切り替える** — 部屋のサーバーは、ログインしている席に、部屋が覚えている役割を`welcome`と`asset-token`の`keptRole`で知らせる。接続情報パネルの役割は、`keptRole`がGMかPLの席だけ、その役割と「見学」の2ボタンになる（`features/lobby/server-watch.service`）。押すと自分の`peerId`への`ROLE_REQUEST`で頼み、見学していることは部屋のサーバーが席の表とは別に覚える。入り直しても見学のまま座り、同じアカウントのほかの席も一緒に切り替わるので、Axeは何も覚えない。自分の頼みが断られたときは、ほかの人の役割の断りとは別の文で知らせ、サーバーの理由のコードは出さない
- **ダイスはサーバーが振る** — 部屋のサーバーの部屋では、ダイスの行を送った画面は自分で振らず、`ROLL_REQUEST`でサーバーに頼む。サーバーはBCDiceで振り、結果の行を全員に流す（`domain/dice/dice-bot`）。サーバーが振った行には`ChatMessage.serverRoll`が付き、チャットの行に「部屋のサーバーが振ったダイスです。振った人には出目を変えられません」という説明の印が出る。4000文字（`MAX_ROLL_COMMAND_LENGTH`）を超える行と、部屋から切り離した卓（リプレイの盤面を出している間など）で言った行は手元で振る。サーバーが振らなかったときは、その理由を振った本人にだけ知らせる（`features/dice/dice-chat-event-handler.service`）
- **上限** — 部屋に入れるのは32人まで（`MAX_MEMBERS`）。部屋名は255文字、合言葉は64文字まで。ダイスは1つの接続から10秒に20回まで（`RATE_WINDOW_SECONDS` / `MAX_ROLLS_PER_WINDOW`）
- **送る量をならす** — サーバーは10秒のあいだに2,000を超えるフレームか20,000を超えるイベントを受けると接続を切る。Axeは`SendPacer`（`core/network/server/send-pacer`）で、11秒あたり9,000イベント・900フレーム（`SEND_BUDGET_EVENTS` / `SEND_BUDGET_FRAMES`）に収まるまで送るのを待たせる。サーバーの窓より1秒長く、上限の半分より少なくするのは、前のフレームが途中で遅れて、サーバーの1つの窓に2回分が入っても収まるようにするため。大きな部屋の読み込みや、行の多いタブの削除は、数回の窓に分けて送る
- **放置の退出** — ページが3時間（`IDLE_SECONDS`）使われないと、サーバーは席を部屋から出す。ページは使われている間、5分（`ACTIVE_REPORT_SECONDS`）に1回までサーバーに使っていることを知らせ、出される5分前（`IDLE_WARNING_MS`）に「しばらく操作が無いので、まもなく部屋から抜けます。続けるときは、画面を少し操作してください」と知らせる（`core/network/server/idle-watch`）。出されたあとは自分ではつなぎ直さず、接続情報パネルの「部屋に戻る」で同じpeerIdのまま入り直す（`features/lobby/idle-seat.service`）
- **回線の見守り** — 部屋のサーバーへの接続は25秒ごと（`PING_INTERVAL_MS`）にpingを送り、10秒（`PONG_TIMEOUT_MS`）何も返らなければ切れたとみなす。入室の返事は45秒（`WELCOME_TIMEOUT_MS`）まで待つ（`core/network/server/link-heartbeat`）。接続情報パネルか通信品質のウィジェットを出している間は、pingを6秒ごとにして往復の時間を測り、10秒ごとに各席から最後に届いた時刻（`seen`）をサーバーに尋ねる（`application/lobby/link-watch.service`）。ページが隠れているときと、60秒（`LOOKED_AT_MS`）使われていないときは尋ねない。尋ねるたびにサーバーが部屋を起こすためである。サーバーへの回線は往復200ms以上で「やや不安定」、500ms以上で「不安定」になり、ほかの席は最後に届いてから75秒で「やや不安定」、135秒で「不安定」になる（`domain/peer/peer-link-quality`）
- **部屋の削除** — GMはロビーの部屋の行か接続情報パネルから、部屋のサーバーの部屋を削除できる。部屋にいる人は全員退室し、サーバーに残している卓の状態と、部屋に上げた画像と音声が消える（`features/lobby/room-deletion.service`）

## 運営者への通報

- **通報** — 部屋のサーバーの部屋にいる人は、役割を問わず、部屋・画像・音声を部屋のサーバーの運営者に通報できる。通報のボタンは、接続情報パネルの「この部屋を運営者に通報」、ファイル一覧の「この画像を運営者に通報」、ジュークボックスの「この音声を運営者に通報」の3つ。出すのは`ReportService.canReport`が真のときで、部屋のサーバーの部屋に入っていて、部屋の画像と音声の置き場（`AssetHttpStore`）が使えるときだけ（`application/moderation/report.service`）。通報できる画像と音声は、SHA-256の名前の物（人が上げた物）だけ。理由は前後の空白を除いて1〜500文字（`MAX_REPORT_REASON_LENGTH`）。ダイアログ（`features/moderation/report-dialog`）は、通報に送り手の回線とアカウントの情報が付くこと（運営者がいたずらを見分けるため）を書き、受け付けると受付番号を出す。サーバーが通報を受け付けていない・通報が多すぎる・断った・送れなかった、の4つはそれぞれ別の文で知らせる
- **止めるのは運営者** — キックやBANの操作はAxeに無い。部屋のサーバーの運営者がアカウントか回線を止めると、サーバーは`banned`で接続を閉じ、Axeはチャットに「部屋のサーバーの運営者が、このアカウントか回線を止めているため、部屋に入れません」と運営者の問い合わせ先を出す（`features/lobby/network-event-handler.service`）。問い合わせ先はhttpsのページかメールアドレスだけをリンクにし（`readOperatorContact`、`core/network/server/operator-contact`）、ロビー・部屋の作成・招待のバナー・ログインの欄でも、断られたときに出す（`features/lobby/operator-contact`）。運営者が置けないようにした画像か音声は、ほかの参加者に届かず、上げた人の画面にその旨を出す

## 同期 / 内部基盤

- **変更の購読** — `ObjectChangeService`（`application/sync/object-change.service`）。識別子1つ・別名1つを固定で聞く購読（`onObjectChangedForIdentifier` / `onObjectChangedForSingleAlias`）は索引から引くので、イベントごとに絞り込まない。`onObjectChangedFor` / `onObjectChangedForAlias`はイベントごとに絞り込む。追加と削除は`objectAdded$` / `objectRemoved$`で聞く
- **signalの配線** — `versionOf()` / `collectionOf()`のsignal API（テンプレートのリアクティブ配線）
- **movable / rotable** — どちらのディレクティブも`onObjectChangedForIdentifier`で自分の物の変更だけを聞く
- **座標の変換** — `CoordinateService`（`application/input/coordinate.service`）は、卓のカメラから出す式でページの点と卓の面の点を行き来する（[設計](../architecture.md)の「卓の描き方」）
- **i18n** — `@jsverse/transloco`（`application/i18n/transloco.config`）
