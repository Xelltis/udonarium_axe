# Axeを置く

このページは、Axe本体（リリースのzip）を静的ホスティングに置いて、ブラウザで開けるようにする手順です。
いちばん詳しく書いているのはCloudflare Pagesで、Cloudflareのアカウントを作るところから順に案内します。
レンタルサーバーなどほかの置き場所は、要点だけを書いています。
かかる時間は、Cloudflareのアカウント作りを含めて30分ほどです。

## 0. 用意するもの

- 置き終えたサーバーのURL（→ [サーバーを置く](/guide/backend)）
- メールアドレス（Cloudflareのアカウントを作るのに使います）
- パソコンと、Chromeなどのブラウザ
- テキストエディター（メモ帳やテキストエディットなど）

Cloudflare Pagesは、無料のプラン（Free）のままで使えます。
支払い方法の登録も要りません。

この手順で使う値は、次のとおりです。

| 値                 | 手に入る場所                           | 使う手順 |
| ------------------ | -------------------------------------- | -------- |
| `axe_x.y.z.zip`    | GitHubのReleases                       | 手順1    |
| サーバーのURL      | [サーバーを置く](/guide/backend)の最後 | 手順2    |
| プロジェクトの名前 | 自分で決める（AxeのURLになる）         | 手順4    |
| AxeのURL           | 手順4の最後に出る                      | 手順5    |

::: warning httpsで配ってください
Axeは、`https://`で始まるURLで配ります。
`http://`のページ（自分のパソコンの`localhost`を除く）では、部屋や画像を見分けるのに使うブラウザの機能が使えず、Axeは正しく動きません。
Cloudflare Pagesは、最初から`https://`で配ります。
:::

## 1. zipを取ってくる

1. [GitHubのReleases](https://github.com/Xelltis/udonarium_axe/releases)を開きます。
2. いちばん上にある最新の版の**Assets**を開き、`axe_x.y.z.zip`（`x.y.z`は版の番号）を押してダウンロードします。
3. ダウンロードしたzipを展開します。Windowsでは、zipを右クリックして**すべて展開**を選びます。

展開したフォルダの中に、`index.html`と`assets`のフォルダがあれば正しく展開できています。
このフォルダを、以下では「展開したフォルダ」と呼びます。

## 2. config.jsonを書く

展開したフォルダの`assets/config.json`を、テキストエディターで開きます。
最初は、次のような中身になっています。

```json
{
  "transport": "skyway",
  "backend": {
    "url": "バックエンドサーバーのURLを指定してください。http://localhost:3000"
  }
}
```

`url`の値を、置いたサーバーのURLに書き換えます。
サーバー版で配るときは、`transport`も`"server"`に書き換えます。

```json
{
  "transport": "skyway",
  "backend": {
    "url": "https://backend.example.com"
  }
}
```

`"`（ダブルクォート）や`,`（カンマ）は消さずに、文字だけを書き換えます。
書き換えたら、文字コードはUTF-8のまま保存します。
項目の意味は[config.jsonを書く](/guide/configuration)にあります。

::: tip 置く前に書き換えます
Cloudflare Pagesに上げたファイルは、その場では書き換えられません。
`config.json`は、上げる前に書き換えておきます。
あとで書き換えたくなったときは、書き換えたフォルダをもう一度上げます（→ [更新するとき](/guide/update)）。
:::

## 3. Cloudflareのアカウントを作る

すでにCloudflareのアカウントがあれば、[ダッシュボード](https://dash.cloudflare.com/)にログインして、手順4に進みます。
サーバーをCloudflareに置いたときのアカウントを、そのまま使えます。

1. [Cloudflareの登録ページ](https://dash.cloudflare.com/sign-up)を開きます。
2. **Email**にメールアドレスを、**Password**にパスワードを入れます。パスワードは8文字以上にし、数字と記号（`$`・`!`・`@`など）を1つずつ以上含めます。
3. その下の、人間であることを確かめる枠（「私はロボットではありません」）にチェックを入れて、**Sign up**を押します。
4. Cloudflareから、確認のメールが届きます。メールの中のリンクを押して、メールアドレスを確かめます。届かないときは、迷惑メールのフォルダも見てください。
5. ログインすると、ダッシュボード（Cloudflareの管理画面）が開きます。

Google・Apple・GitHubのアカウントで登録するときは、手順2の代わりに、上に並ぶ**Continue with**のボタンを押します。
登録ページの言葉は、右上の**English**から日本語に切り替えられます。

ダッシュボードには、ドメインを追加する案内なども並んでいます。
Axeを置くだけなら、ドメインは要りません。
ここでは何も追加せずに、手順4に進みます。

## 4. Pagesのプロジェクトを作って上げる

::: info 画面の言葉
Cloudflareの画面は、右上のプロフィールの**Language**で日本語にもできます。
この手順では、ボタンやメニューの名前を英語の表示で書きます。
日本語の表示にしているときは、対応する日本語の名前を探してください。
:::

プロジェクトは、Cloudflare Pagesの中の、サイト1つ分の単位です。
プロジェクトの名前が、そのまま`https://<プロジェクトの名前>.pages.dev`の形で、AxeのURLになります。

### 名前を決める

- 名前は、英小文字・数字・`-`（ハイフン）で付けます（例：`my-axe`）
- ほかの人がすでに使っている名前だと、URLは名前のあとに英数字が少し付いた形になります。実際のURLは、この手順の最後に出る画面で確かめます
- `pages.dev`のURLは、あとから変えられません。変えたくなったときは、プロジェクトを作り直します

### 作って上げる

1. ダッシュボードの左のメニューから、[Workers & Pages](https://dash.cloudflare.com/?to=/:account/workers-and-pages)を開きます。メニューが畳まれているときは、**Compute**の中にあります。
2. **Create application**を押します。
3. Workersの作りかたが並ぶ画面が出ます。下のほうにある、Pagesの**Get started**を押します。
4. **Drag and drop your files**を選びます。Gitのリポジトリから取り込むほうではありません。
5. **Project name**に、決めた名前を入れて進みます。
6. ファイルを上げる枠が出ます。エクスプローラー（MacではFinder）で展開したフォルダを表示し、そのフォルダ（`index.html`のあるフォルダ）を枠にドラッグします。
7. ファイルが上がり終えたら、**Deploy site**を押します。

枠にはzipのまま上げることもできますが、ダウンロードしたzipの`config.json`はひな形のままです。
手順2で書き換えたフォルダのほうを上げてください。
Axeのファイルは800個あまりあるので、上がり終えるまで少し待ちます。

終わると、完成を知らせる画面に、`https://<プロジェクトの名前>.pages.dev`のURLが出ます。
これがAxeのURLで、`https://<プロジェクトの名前>.pages.dev`の部分がAxeのOriginです。
[設置の準備](/guide/requirements#axeのoriginを決める)で決めたOriginと違っていたら、サーバーの`ACCESS_CONTROL_ALLOW_ORIGIN`をこのOriginに書き換えます。

ドラッグ＆ドロップで上げられるのは1,000ファイルまで、1つのファイルは25MiBまでです。
Axeのファイルはどちらにも収まるので、そのまま上がります。

## 5. 確かめる

1. AxeのURLを、パソコンのChromeで開きます。
2. ロビー（部屋の一覧）が出ることを確かめます。サーバー版では、ロビーの上に**Discordでログイン**のボタンが出ます。
3. 部屋を作って入ります。サーバー版では、先にDiscordでログインします。
4. 別のブラウザ（ほかの人のパソコンや、Chromeのシークレットウィンドウ）で同じURLを開き、作った部屋に入れることを確かめます。

| 見えるもの                                    | 原因と直しかた                                                                                                                       |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 部屋を作れて、別のブラウザからも入れる        | できあがりです                                                                                                                       |
| 上げた直後に、サイトにアクセスできないと出る  | 初めて上げた直後は、URLがまだ行き渡っていないことがあります。数分待ってから開き直すか、別の端末やネットワークで開きます              |
| ページが真っ白、または開けない                | 展開したフォルダの中身ではなく、フォルダごと1段深く上げていないか確かめます（`index.html`がURLのすぐ下にあるか）                     |
| ロビーは出るが、部屋を作れない・入れない      | `config.json`か、サーバーの`ACCESS_CONTROL_ALLOW_ORIGIN`が合っていません（→ [設置で困ったとき](/guide/troubleshooting)）             |
| サーバー版なのに**Discordでログイン**が出ない | `config.json`の`transport`が`"server"`になっていません                                                                               |
| 新しいプロジェクトを作れない                  | 作ったばかりのアカウントは、最初の48時間に作れるプロジェクトの数が限られています。前に作ったプロジェクトに上げ直すか、48時間待ちます |

前に作ったプロジェクトに上げ直す手順は、[更新するとき](/guide/update#cloudflare-pages)にあります。

## コマンドで上げる（Wrangler）

ターミナルでコマンドを打てる人は、CloudflareのコマンドラインツールWrangler（Node.jsが要ります）で上げることもできます。
更新のたびに画面を操作したくないときや、ドラッグ＆ドロップの上限を超えたときに使います。
Wranglerなら20,000ファイルまで上げられます。

```sh
npx wrangler login
npx wrangler pages deploy <展開したフォルダ> --project-name <プロジェクトの名前>
```

1行目でブラウザが開き、Cloudflareにログインします。
2行目で上げます。
ダッシュボードで作ったプロジェクトにも、その名前を指定すれば上げられます。

## ほかの置き場所

どこに置いても、展開したフォルダの中身をそのまま、`https://`で配れる場所に置けば動きます。

| 置き場所              | 要点                                                                                                                                                                                             |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| レンタルサーバー      | FTPなどで、公開フォルダ（`public_html`など）の下に、展開したフォルダの中身を上げます。サブフォルダに置いても動きます。サーバーがhttpsで配っているかを確かめてください                            |
| GitHub Pages          | 展開したフォルダの中身をリポジトリに入れ、そのブランチを配信元に選びます                                                                                                                         |
| Amazon S3＋CloudFront | 展開したフォルダの中身をバケットに上げ、CloudFrontで`https://`で配ります。フォークしたリポジトリから自動で配る方法は[config.jsonを書く](/guide/configuration#github-actionsで配るとき)にあります |

どの置き場所でも、`assets/config.json`は上げる前に書き換えておきます。
