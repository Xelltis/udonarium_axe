# config.jsonを書く

このページは、Axe本体の`assets/config.json`に何を書くかと、Axeとサーバーがつながったかの確かめかたを説明します。
Axeは起動するたびにこのファイルを読み、どの方式で、どのサーバーにつなぐかを決めます。
[Axeを置く](/guide/quickstart)の手順2で書き換えたあと、くわしい意味を知りたいときや、つながらないときに読んでください。

## ファイルの場所

Axeを置いた場所（`index.html`のあるフォルダ）の中の、`assets/config.json`です。

```text
（Axeを置いた場所）
 ├─ index.html
 └─ assets/
     └─ config.json   ← これ
```

リリースのzipには、最初から`assets/config.json`が入っています。
中身はSkyWay版のひな形で、`backend.url`には書き換えを促す文が入っています。
そのままでは、どのサーバーにもつながりません。

## 項目

| 項目          | 書かないとき | 内容                                                                                         |
| ------------- | ------------ | -------------------------------------------------------------------------------------------- |
| `transport`   | `"skyway"`   | 方式。`"server"`でサーバー版、`"skyway"`でSkyWay版。知らない値はSkyWay版として読みます       |
| `backend.url` | 空           | サーバーのURL。SkyWay版ではトークン発行サーバー、サーバー版では部屋のサーバーのURLを書きます |

### `transport`

1つの配信先で使える方式は、どちらか片方です。
部屋ごとには選べません。
両方を使いたいときは、Axe本体を2か所に置き、それぞれの`config.json`で方式を変えます。

書き換えて置き直すと、次にAxeを開いた人から新しい方式になります。
すでに開いている人は、ページを読み込み直すまで前の方式のままです。

### `backend.url`

- サーバーのURLを、`https://`から書きます
- 末尾の`/`は、あってもなくても構いません
- レンタルサーバーのサブフォルダにトークン発行サーバーを置いたときは、そのパスまで書きます（例：`https://example.com/backend`）
- サーバー版では、部屋の一覧と作成、ログイン、画像と音声のやりとりを、すべてこのURLに送ります

## SkyWay版の例

```json
{
  "transport": "skyway",
  "backend": {
    "url": "https://backend.example.com"
  }
}
```

`transport`の行は、消しても同じ意味です。

## サーバー版の例

```json
{
  "transport": "server",
  "backend": {
    "url": "https://rooms.example.com"
  }
}
```

部屋のサーバーの`ACCESS_CONTROL_ALLOW_ORIGIN`には、AxeのOriginを名前で書いておきます（`*`では、ログインのあとAxeに戻れません）。
Axeの`backend.url`とサーバーの`ACCESS_CONTROL_ALLOW_ORIGIN`は、互いを指し合う組み合わせです。
どちらか片方が違っていても、つながりません。

## 確かめる

1. 書き換えた`config.json`を置き直します（Cloudflare Pagesでは、フォルダごと上げ直します）。
2. AxeのURLをChromeで開きます。開いたままのタブは、読み込み直します。
3. ロビー（部屋の一覧）の表示と、チャットのシステムタブを見ます。

| 見えるもの                                                                                                 | 意味                                                                                                             |
| ---------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 部屋を作れて、別のブラウザからも入れる                                                                     | つながっています                                                                                                 |
| ロビーに「まだサーバーにつながっていません。しばらく待ってから「一覧を更新」を押してください。」           | つなぎに行っている途中です。数秒待って**一覧を更新**を押します                                                   |
| チャットに「SkyWayのバックエンドサーバに接続できません。…」（開いてから30秒ほどで出ます）                  | SkyWay版で、トークン発行サーバーから許可証をもらえません。`backend.url`か`ACCESS_CONTROL_ALLOW_ORIGIN`が違います |
| チャットに「ネットワークエラーが発生しました。(TypeError)」と「再接続はこれで最後です。…」がすぐ続けて出る | SkyWay版で、`backend.url`がひな形の文のままか、URLとして読めません                                               |
| ロビーに「ルーム一覧の取得に失敗しました。「一覧を更新」で再検索できます。」                               | サーバー版で、`backend.url`の部屋のサーバーに届きません。URLが違うか、サーバーが動いていません                   |
| ロビーに「接続先（config.json の backend.url）が設定されていません」                                       | サーバー版で、`backend.url`が空か、URLとして読めません                                                           |
| ロビーに「このサーバーにはログインが用意されていないため、部屋を使えません」                               | 部屋のサーバーに、ログインの設定が入っていません                                                                 |
| サーバー版なのに、ロビーの上に**Discordでログイン**が出ない                                                | `transport`が`"server"`になっていません                                                                          |

ほかの表示と直しかたは、[設置で困ったとき](/guide/troubleshooting)にあります。

## GitHub Actionsで配るとき

Axeのリポジトリをフォークし、付属のワークフロー（`.github/workflows/deploy.yml`）でAmazon S3とCloudFrontに配るときは、`config.json`を手で書く代わりに、GitHubのEnvironmentに値を入れます。
ワークフローが、ビルドのあとに`config.json`を作ります。

| 入れる場所                   | 名前                         | 内容                                                         | 必須 |
| ---------------------------- | ---------------------------- | ------------------------------------------------------------ | :--: |
| Secret                       | `BACKEND_URL`                | `backend.url`に入る値                                        |  ○   |
| Variable（Secretではない方） | `TRANSPORT`                  | `transport`に入る値。書かなければ`skyway`                    |      |
| Secret                       | `AWS_REGION`                 | S3のバケットのリージョン                                     |  ○   |
| Secret                       | `AWS_S3_BUCKET`              | Axeを置くS3のバケット                                        |  ○   |
| Secret                       | `AWS_DEPLOY_ROLE_ARN`        | GitHub ActionsがAWSに入るためのIAMロール（OIDCで引き受ける） |  ○   |
| Secret                       | `CLOUDFRONT_DISTRIBUTION_ID` | 配り終えたあとに古いキャッシュを消すCloudFrontの配信         |  ○   |

`TRANSPORT`に`skyway`と`server`のほかの値を書くと、ワークフローが止まります。

## オフライン

<Shot src="guide-connection-mode" alt="接続パネルの上部。ニックネームと役割の下に「オンライン」と「オフライン」の切り替えがあり、オンラインが選ばれている" width="400" caption="接続パネル。オフラインに切り替えると、ページを読み込み直してこのブラウザだけで動きます" />

接続パネルの**接続**を**オフライン**にすると、Axeはネットワークを使わずに、そのブラウザだけで動きます。
このとき`config.json`は読まず、どのサーバーにもつなぎません。
部屋の保存と読み込みはできるので、設置の前にAxeの動きを試すのにも使えます。
**オンライン**に戻すと、ページを読み込み直して`config.json`を読みます。
